[S-Brain] 검증 업무 담당 제안

## 결론

- 검증 1: 박상희 담당
- 검증 2: 정재희님 담당

검증 결과를 서로 대신 판단하지 않고, 각자 맡은 검증을 끝낸 뒤 결과만 전달하는 방식입니다.
박상희는 이미 사업계획서와 평가 기준을 정리하고 있으므로 검증 1을 맡는 것이 자연스럽고, 정재희님은 결과물을 가장 잘 알고 있으므로 검증 2를 맡는 것이 효율적이라고 판단했습니다.

## 검증 1. 사업계획서 문서 검증

담당: 박상희

사업계획서가 공고 양식과 평가 기준에 맞는지 확인합니다.

박상희가 하는 일:

- 필수 항목과 필수 섹션 확인
- 평가 기준에 따른 문서 내용 확인
- 근거 위치 확인
- 문서 점수 계산
- 부족한 항목과 이유 정리
- 다시 작성할 섹션 결정
- 재작성 후 문서 점수 재확인

검증 1이 끝나면 아래 결과를 정재희님께 전달하겠습니다.

- 확정된 기능 목록
- 기능별 설명
- 문서 평가 결과
- 문서에서 부족한 항목
- 검증 2에서 확인해야 할 기능 기준







## 검증 2. 계획서와 결과물 대조 검증

담당: 정재희님

검증 1에서 전달한 기능 목록을 기준으로 결과물을 확인합니다.

정재희님이 하는 일:

- 기능 목록의 각 기능이 결과물에 있는지 확인
- 기능이 정상적으로 동작하는지 확인
- 일부만 구현된 기능 표시
- 확인되지 않는 기능 표시
- 확인할 수 없는 기능과 이유 기록
- 결과물에 추가된 기능 기록
- 결과물 검증 점수 계산
- 추가 수정이 필요한 기능 결정
- 수정 후 해당 기능 재확인

검증 2의 결과는 아래처럼 정리하면 됩니다.

- 기능 이름
- 확인 결과: 구현됨 / 부분 구현 / 추가 수정 필요 / 확인 필요
- 확인한 내용
- 부족한 내용
- 확인 근거
- 수정이 필요한 기능
- 수정 후 재확인 결과
- 결과물 검증 점수






## 서로 겹치지 않게 하는 기준

박상희는 결과물의 기능이 실제로 동작하는지 판단하지 않습니다.
정재희님은 사업계획서의 문서 점수나 문서 내용을 평가하지 않습니다.

박상희가 전달하는 것은 검증 2의 기준이 되는 기능 목록까지입니다.
정재희님은 그 기능 목록을 받아 결과물에 실제로 있는지만 확인합니다.

따라서 겹치는 업무는 아래 한 단계뿐입니다.

```text
박상희: 검증 1 완료 → 기능 목록 전달
정재희: 기능 목록 수신 → 검증 2 완료
```








## 진행 순서

1. 박상희가 검증 1을 진행합니다.
2. 박상희가 검증 1 결과와 기능 목록을 전달합니다.
3. 정재희님이 검증 2를 진행합니다.
4. 정재희님이 기능별 확인 결과와 결과물 점수를 전달합니다.
5. 박상희는 전달받은 검증 2 결과를 최종 산출물 기록에 반영합니다.

이렇게 진행하면 검증 1과 검증 2의 책임자가 명확하고, 같은 내용을 두 사람이 반복해서 확인하는 일이 줄어들 것 같습니다.
