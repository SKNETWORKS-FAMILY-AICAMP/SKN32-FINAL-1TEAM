# PartⅡ 작성 문체·구성 가이드

이 문서는 `사업계획서 작성 예시 PartⅡ` PDF를 참고하여 Agent가 따를 작성 방식만 정리한 것이다. 원문을 복제하지 않고, 문체와 구조를 재구성하였다.

## 전체 톤

- 설명형보다 계획형 문장을 사용한다.
- “무엇을 개발하는가”, “왜 필요한가”, “어떻게 검증할 것인가”, “어떻게 판매할 것인가”가 한눈에 보여야 한다.
- 각 문단은 평가 항목에 직접 대응해야 한다.
- 기술 설명은 길게 풀어쓰기보다 핵심 요소별 불릿으로 나눈다.

## 자주 사용하는 문장 패턴

- `본 개발 제품은 [대상 고객/현장]에서 발생하는 [문제]를 해결하기 위한 [제품/서비스]임.`
- `기존 방식은 [한계]가 있어 [고객/사용자]에게 [부담/비용/시간 지연]이 발생함.`
- `이에 따라 [핵심 기능]을 적용하여 [개선 효과]를 확보하고자 함.`
- `최종 개발 목표는 [기술/서비스]를 구현하여 [정량 목표 또는 사용 효과]를 달성하는 것임.`
- `주요 성능지표는 [정확도/응답속도/처리량/연동 수/비용 절감률]을 중심으로 설정함.`
- `측정 결과는 [공인시험/외부기관/자체평가/고객 PoC]를 통해 검증할 계획임.`
- `사업화 초기에는 [특정 고객군]을 대상으로 시범 적용 후, [확장 시장]으로 확대할 예정임.`

## 항목별 작성 방식

### 1. 기술개발의 개요 및 필요성

작성 순서:

1. 개발 대상 제품·서비스의 정의
2. 적용 분야와 주요 고객
3. 기존 제품·기술·업무 방식의 문제점
4. 고객 또는 시장의 개선 요구
5. 개발 필요성
6. 제안 기술의 핵심 개선점

권장 구조:

```md
◦ 개발 대상 서비스 개요
- [서비스명]은 [고객]이 [상황]에서 겪는 [문제]를 해결하기 위한 [제품/서비스]임.
- 주요 기능은 [기능1], [기능2], [기능3]으로 구성됨.

◦ 기존 방식의 문제점
- 기존 [방식/제품]은 [한계]로 인해 [비효율/비용/품질 문제]가 발생함.
- 특히 [세부 상황]에서는 [구체 문제]가 반복적으로 발생함.

◦ 기술개발 필요성
- [시장/고객/정책 변화]에 따라 [해결 필요성]이 증가하고 있음.
- 따라서 [제안 기능]을 개발하여 [기대 효과]를 확보하고자 함.
```

### 2. 기술개발의 목표

작성 순서:

1. 최종 목표 한 문장
2. 핵심 개발 내용
3. 정량 성능지표
4. 측정 방법과 증빙 방법

권장 성능지표 예시:

| 지표 | 단위 | 최종 개발 목표 | 측정 방법 | 증빙 방법 |
| --- | --- | --- | --- | --- |
| 검색 응답속도 | 초 | O초 이하 | 지정 문서셋 질의 응답 시간 측정 | 자체평가 또는 외부 PoC |
| 답변 근거 표시율 | % | OO% 이상 | 답변별 출처 링크 표시 여부 확인 | 자체평가 |
| 권한 반영 정확도 | % | OO% 이상 | 사용자 권한별 접근 결과 비교 | 보안 테스트 |
| 문서 연동 수 | 건 | O개 이상 | 연동 가능한 저장소·문서 포맷 확인 | 기능 테스트 |
| 사용자 만족도 | 점 | O점 이상 | 시범 고객 설문 | 고객 검증 |

### 3. 기술개발의 방법

작성 순서:

1. 핵심 기술별 개발 방법
2. 자체개발·외부기술·솔루션 도입 여부
3. 연차 또는 단계별 개발 계획
4. 수행기관별 역할이 있으면 구분
5. 테스트베드와 검증 계획

권장 구조:

```md
◦ [핵심기술 1] 개발
- [구현 방법]을 적용하여 [기능]을 개발함.
- [기술 요소]를 활용하여 [성능 목표]를 달성하고자 함.

◦ [핵심기술 2] 개발
- [데이터/시스템/사용자 흐름]을 기준으로 [처리 방식]을 설계함.
- [테스트 환경]에서 [검증 항목]을 확인할 예정임.
```

### 4. 사업화 계획

작성 순서:

1. 제품화 또는 서비스화 계획
2. 양산 또는 운영 계획
3. 판로 확보 계획
4. 마케팅 및 판매 전략
5. 해외 진출 가능성
6. 고용 창출과 조직 운영 계획

권장 구조:

```md
◦ 제품화 계획
- MVP 기능을 우선 개발하여 [초기 고객]을 대상으로 시범 적용할 계획임.
- 시범 적용 결과를 바탕으로 [기능/UX/성능]을 개선하고 정식 서비스로 전환함.

◦ 판로 확보 계획
- 초기에는 [고객군]을 대상으로 직접 영업과 PoC를 추진함.
- 이후 [파트너/채널]을 통해 판매 대상을 확대할 예정임.

◦ 가격 및 수익모델
- 기본 과금은 [월 구독/사용량/좌석당 과금] 방식으로 설계함.
- 고객 규모와 보안 요구 수준에 따라 [요금제]를 구분할 계획임.

◦ 고용창출 계획
- 개발 안정화 단계에서 [개발/영업/고객지원] 인력을 단계적으로 채용할 계획임.
```

## SaaS·AI 서비스 작성 시 적용 방식

- 제조업처럼 양산 계획을 억지로 쓰지 말고, `서비스 운영`, `클라우드 배포`, `고객 PoC`, `구독 과금`, `보안 운영`으로 바꾸어 작성한다.
- 시험기관 인증이 어려운 지표는 PoC, 로그 분석, 사용자 테스트, 보안 점검, 자체 테스트 기준으로 제시한다.
- 기술 차별성은 모델명보다 고객 문제 해결 방식, 데이터 보안, 권한 관리, 출처 제시, 운영 편의성으로 설명한다.
