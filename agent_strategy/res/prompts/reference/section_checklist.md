# 사업계획서 작성 결과 체크리스트

작성 Agent가 생성한 결과물을 검토할 때 사용한다.

## 1. 기술개발의 개요 및 필요성

- [ ] 개발 대상 제품·서비스가 한 문장으로 정의되어 있는가
- [ ] 목표 고객과 사용 상황이 명확한가
- [ ] 기존 방식의 문제점이 구체적으로 작성되어 있는가
- [ ] 시장 문제와 기술 필요성이 연결되어 있는가
- [ ] 출처 있는 근거와 작성자의 해석이 구분되어 있는가

## 2. 기술개발의 목표

- [ ] 최종 목표가 제품·서비스 결과물 중심으로 작성되어 있는가
- [ ] 핵심 개발 내용이 기능별로 구분되어 있는가
- [ ] 정량 성능지표가 5개 이상 제시되어 있는가
- [ ] 각 지표에 단위, 목표값, 측정방법, 증빙방법이 있는가
- [ ] SaaS/AI 서비스에 맞는 검증 방식이 제시되어 있는가

## 3. 기술개발의 방법

- [ ] 핵심 기능별 구현 방법이 작성되어 있는가
- [ ] 자체개발, 외부기술 활용, 솔루션 도입 여부가 구분되어 있는가
- [ ] 단계별 개발 일정 또는 개발 흐름이 있는가
- [ ] 테스트베드, PoC, 자체평가 등 검증 계획이 있는가
- [ ] 보안, 권한, 데이터 처리 방식이 필요한 경우 포함되어 있는가

## 4. 사업화 계획

- [ ] 제품화 또는 서비스화 계획이 있는가
- [ ] 초기 고객 확보 방법이 구체적인가
- [ ] 가격 및 수익모델이 제시되어 있는가
- [ ] 판로와 마케팅 전략이 구분되어 있는가
- [ ] 해외 진출 계획 또는 향후 검토 계획이 있는가
- [ ] 고용창출 및 인력 운영 계획이 포함되어 있는가

## 표현 점검

- [ ] 과장 표현이 없는가
- [ ] 출처 없는 시장 규모를 단정하지 않았는가
- [ ] 산업 전체 통계를 아이템 시장으로 오인하게 쓰지 않았는가
- [ ] 경쟁사 대비 차별성이 기능·고객·비용·운영 관점에서 작성되었는가
- [ ] 문장 끝이 사업계획서형 어미로 통일되어 있는가

## 전략·근거 연결 점검

- [ ] 전략 단계에서 확정된 `featureList` 기능이 본문에 의미상 동일하게 포함되어 있는가
- [ ] `provided`·`confirmed`·`proposed`·`needs_confirmation` 상태가 사실과 계획에 맞게 구분되어 있는가
- [ ] 원본 사실과 사업계획 제안값이 문장에서 구분되어 있는가
- [ ] 사용한 근거의 `sourceRefs`와 본문 주장이 연결되어 있는가
- [ ] 목표 고객·기술언어·시험조건을 입력값처럼 단정하지 않고 확인 필요 또는 제안으로 표시했는가

## 일정·예산·출력 계약 점검

- [ ] 개발 종료월이 공고 접수 마감일을 넘지 않는가
- [ ] 정부지원사업비 합계가 공고 지원규모 상한을 넘지 않는가
- [ ] F16 본문에 사업계획서 항목 번호·제목을 중복 작성하지 않았는가
- [ ] 표 항목은 요구된 컬럼과 원본 행을 유지하는가
- [ ] 이미지 항목은 USER_FLOW와 SERVICE_ARCHITECTURE 목적을 구분하는가
- [ ] 확인이 필요한 값은 `needsUserConfirmation` 또는 본문에 명시했는가
