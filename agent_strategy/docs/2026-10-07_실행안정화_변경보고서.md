# 2026-10-07 실행 안정화 변경 보고서

## 변경 목적

전체 실행과 회귀 재작성 과정에서 발생한 중복 실행, 오래된 검증 결과 재사용, 선택 검증 후 전체 상태 불일치를 줄이고 실행 비용을 관리한다.

## 전략·작성 Agent 변경

- 회귀 재작성 전체 실행 버튼의 중복 클릭을 차단한다.
- 자동 회귀는 새 전체 실행 완료 후에만 실행한다.
- 새로고침으로 마지막 결과를 복원할 때 자동 회귀를 재시작하지 않는다.
- Pass 건너뛰기 검증 버튼은 Warning·Fail만 다시 검증하며 작성 결과를 변경하지 않는다.
- 선택 검증 뒤 전체 실패 상태와 평가 요약을 보존한다.
- 실행 결과의 총 토큰 사용량을 평가 요약에 표시한다.

## 검증 1 변경

- 협력기관·장비·채용 facts의 평탄화 경로와 `resources` 중첩 경로를 동일하게 비교한다.
- 배열 인덱스 경로를 구조적으로 해석한다.
- 정책 버전 변경으로 이전 검증 캐시를 무효화한다.

## 검증

- `python -B -m py_compile` 통과
- `node --check` 통과
- 회귀 테스트 19개 통과

## 운영 방법

정책 또는 검증 비교 로직이 바뀌면 정책 버전을 올린 뒤 서버를 재시작한다. 기존 결과를 전체 재실행하지 않고 영향을 받은 항목만 선택 검증할 수 있다. 자동 회귀를 사용할 때는 최대 횟수를 1회로 두고, 실패 항목이 확인된 경우에만 활성화한다.

## 2026-10-07 추가 변경

1. F17 필수 표 열·행 위반은 최대 1회 재시도하고, 재시도 후에도 실패하면 표를 성공 처리하지 않는다. 원본 행이 있으면 문자열 설명으로 대체하고 `tableFallbackUsed`, `fallbackReason`을 저장한다.
2. 초기창업 일정은 협약 수행일정과 성장 로드맵을 분리한다. 협약용 일정표만 종료월을 비교하며 초과 시 F19 실패로 처리한다.
3. 점수 결과에 내부 품질 점수, 문서층 70점 환산값, 공식 배점(`null`), 내부 예상 배점을 분리 저장하고 평가 요약·항목 상세에 표시한다.
4. 실제 표 구조가 저장된 결과에 대한 `tables.columns`·`tables.rows` 누락 오탐을 보정한다. 실제 표가 없거나 필수 열이 빠진 경우는 계속 실패 처리한다.
5. `py_compile`, `node --check`, 회귀 테스트 19개를 통과했다.
6. **검증 캐시 재사용 보정**
   - 기존 F19 결과가 `contentHash`와 정책 버전이 같아 재사용되는 경우에도 현재 결과의 표 구조를 다시 확인한다.
   - 과거 검증에서 저장된 `tables.columns`·`tables.rows` 누락 오탐은 실제 표가 있으면 제거한다.
   - 실제 표가 없거나 필수 열이 없으면 캐시를 사용하더라도 `fail`을 유지한다.
   - 이 보정은 F16·F17·F18 재호출 없이 기존 결과 검증·조립만으로 적용된다.
