이 폴더가 **최종 결과**다. 같은 날 앞선 세 실행은 보존하되 아래 "이전 실행과의 관계"에 무엇이 달랐는지 적었다.

10개 입력에서 실제로 무엇이 달라졌는지만 적는다. 전체 우열이나 통계적 유의성은 말하지 않는다.
사람 판정 칸은 비어 있다 — `human_review.csv`.

질의 파일은 바꾸지 않았다. 나머지 7건은 소재지가 비어 지역·시·군·구 규칙이 걸리지 않는다.

각 쌍은 `search` 값만 다르다(자동 확인). 모든 응답이 5건을 채웠다.

**검색 후보 깊이는 방식마다 다르다.** 서비스 구현을 그대로 쓴 결과이며 맞추지 않았다.

| 단계 | dense 깊이 | hybrid 깊이 | 라운드 |
|---|---:|---:|---:|
| A (후처리 제외) | 6 | 50 | 모두 1 |
| B (서비스 조건) | 40 | 50 | 모두 1 |

후보량이 다르므로 이 비교를 "같은 후보에서 알고리즘만 바꾼 비교"로 읽으면 안 된다.

## 2. 무엇이 달라졌나 (사실)

```
A 단계  상위 5칸 중 공통 18/50 · hybrid 에만 나온 공고 32건 · 공통 공고의 순위 이동 14건
B 단계  상위 5칸 중 공통 20/50 · hybrid 에만 나온 공고 30건 · 순위 이동 17건
        10개 사례 모두 두 방식의 상위 5가 달랐다
```

위 수치는 **노출 칸 수의 합**이며 고유 공고 수나 정확도가 아니다.

### 규칙 관련 수치 — 두 가지를 구분한다

| | dense | hybrid | 뜻 |
|---|---:|---:|---|
| 규칙에 걸린 후보 **예시** 누적 (응답·규칙별 최대 5개) | 지역 15 · 시군구 1 · 집단 9 | 지역 15 · 시군구 2 · 집단 16 | 화면에 이유를 보여주려고 담는 목록. 전체 건수도, 실제 순위 하락 건수도 아니다 |
| **최종 상위 5에 남은** 규칙 플래그 | 0 · 0 · 0 | 0 · 0 · 0 | 상위 5에는 규칙에 걸린 공고가 하나도 없다 |

**플래그 0은 "자격을 모두 충족했다"는 뜻이 아니다.** 지역·집단 규칙에 걸리지 않았다는 뜻일 뿐이고,
업력·접수기간 등은 별도 자격 API 가 판정한다.

전체 후보 중 규칙이 실제로 몇 건을 내렸는지 알려면 재정렬 전후 순위가 필요하다. 이번 응답만으로는 추정하지 않는다.

## 3. 사용자가 판단할 사례

아래는 **Claude 의 잠정 의견**이다. 사람 판정이 아니며 `human_review.csv` 에 반영하지 않았다.

**하이브리드가 나아 보이는 사례 — case05 수출 (q021) "산업용 밸브, 중동 수출"**
```
dense   국가전략기술 기술이전 · 실리콘밸리 GTM · [울산] 이전·창업기업
hybrid  실리콘밸리 GTM · [인천] 중동 상황 위기 대응 긴급 · 중동피해 긴급지원 지사화
```
"중동"이 그대로 든 공고를 단어 검색이 찾았다. 다만 "중동 **피해** 지원"이라 이 신청자에게 맞는지는 사람이 봐야 한다.
(이 설명은 순위 정보에서 읽은 추정이며 단어 기여도를 계산한 것이 아니다.)

**하이브리드가 나빠 보이는 사례 — case08 사회적경제 (q031) "발달장애인 고용, 친환경 세제"**
dense 1위였던 "장애인 창업 컨설팅"이 hybrid 상위 5에서 빠지고 "선도기업 전략직종 직무개발"이 들어왔다.

**판단하기 어려운 사례 — case01·02·04**
양쪽 모두 "AI 창업 교육·경진대회" 계열이 섞인다. 공고 데이터에 그런 공고가 많은 것으로 보인다.

**무관 질의 2건 (case09·10)** — 어느 쪽도 "관련 없음"이라고 말하지 못하고 5건을 돌려준다.
유사도 0.48~0.51 로 정상 질의와 겹친다. **무관 입력을 거르는 장치가 없다.**

## 4. 이 비교로 알 수 없는 것

- 어느 쪽이 전체적으로 낫다고 말할 수 없다. 사례 10개이고 사람 판정이 없다.
- **Chroma 색인 내용이 지금 DB 내용과 같은지는 확인하지 못했다.** 벡터 파일(입력 해시)까지는 일치한다.
- 기존 평가(`eval/evaluate.py`)의 P@3 는 마감·지역·집단 규칙 없이 잰 값이라 B 단계를 검증하지 않는다.
- 주제 판정(qrels)은 자격 판정이 아니다.
- 소재지가 없는 7개 입력에서는 지역 규칙이 실질적으로 작동하지 않았다.

## 5. 다음 개선 후보

1. **무관 입력 차단** — 두 방식 모두 무관 질의에 5건을 돌려준다.
2. **업력·나이 조건 칸으로 뽑기** — 상위 3칸의 65%가 업력 '모름'(`eval/gate_eval.py`).
3. **사람 판정 확보** — `human_review.csv` 를 채우면 이 10개 사례에 한해 사람 기준 비교가 된다.
4. Chroma 색인에 입력 해시를 메타데이터로 넣으면 내용 정합성을 직접 확인할 수 있다.

## 6. 이전 실행과의 관계

| 폴더 | 상태 |
|---|---|
| `…T051606Z` | 첫 실행. **내용 정합성 미검증**(ID 집합만 확인) · 기준일 표시 오류 · manifest 경로 표기 오류 |
| `…T053021Z` | 도구 1차 수정 확인용. manifest 의 `dirty_files` 첫 항목이 잘려 기록됨 |
| `…T053148Z` | 리뷰 4건 반영. 날짜가 바뀌어도 성공으로 저장되는 문제가 남아 있었다 |
| **`…T054314Z`** | **최종.** 날짜 경계 무효 처리까지 반영 |

상위 5 비교: 첫 실행 ↔ `…T053148Z` 는 40개 중 39개 동일(1개는 근사 검색 흔들림으로 보인다),
`…T053148Z` ↔ 최종은 **40개 모두 동일**하다. 이번 수정은 결과 순위를 바꾸지 않았다.

## 7. 파일과 재실행

```
manifest.json      코드·데이터·모델 리비전·설정·정합성 검사 결과
inputs.jsonl       입력 10개와 선정 이유·가상 보완 표시
responses.jsonl    원본 응답 40개 (applied_date · query_as_of_date 포함)
notices.jsonl      등장한 공고의 당시 본문·조건·링크와 내용 해시
comparison.jsonl   공통/신규/순위 이동 집계
comparison.html    입력별 A/B × dense/hybrid 비교표
human_review.csv   사용자 판정 양식 (비어 있음)
```

재실행: `.venv\Scripts\python.exe -X utf8 eval/search_comparison.py` (입력만 보려면 `--plan`)
실행할 때마다 새 폴더가 생기고 기존 결과는 덮어쓰지 않는다.
정합성 검사에 걸리면 **검색을 시작하지 않고 종료코드 2로 멈춘다**(색인을 자동으로 다시 만들지 않는다).
실행 중 날짜가 바뀌면 **무효 실행으로 처리해 종료코드 3** 으로 끝나고, 비교표·판정 양식을 만들지 않는다.
원본 응답만 `…_INVALID_date_changed/` 에 진단용으로 남는다.

`reports/` 는 Git 제외 대상이 **아니다**(`git check-ignore` 확인). 비교 결과 네 폴더 합계 약 2.1MB이며
커밋 여부는 사용자가 정한다.
