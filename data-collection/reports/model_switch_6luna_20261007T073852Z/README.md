## 바꿨을 때의 문제점 (코드 확인)

1. **자격요건**: 추출기 버전이 바뀌면 다음 배치 한 번에 하루 상한 없이 2,096건을 전부 다시 부른다. 그리고 지금 코드는 `temperature=0`을 보내 새 모델이 거부한다 → 이번에 요청 옵션을 모델에 맞게 고쳤다(지금 모델 요청은 그대로, 시험 확인).
2. **자격요건 값이 달라진다**: 사업자 유형·예비창업자 가능 칸이 비는 경우가 많아지고, 근거 검사에서 버려지는 값이 늘었다. 이 두 칸은 공고 서버 검증 화면(`/api/conditions`)과 신청자 유형 추출기의 참고 칸에만 쓰이고 추천·자격 판정에는 쓰이지 않는다. **지원 금액 상한은 조율 창구 공고 상세(`support_amount_max_won`)에 그대로 나간다** — 표본에서 5건이 "있음 → 없음"이 됐다.
3. **신청자 유형·업종**: 지금은 공고문이 바뀐 것만 다시 뽑아서, 모델만 바꾸면 옛·새 결과가 섞인다 → 전환할 때 엔진이 다르면 다시 뽑게 고쳐야 한다(계획에 있음).
4. **업종**: 공고 서버 순위는 9/28 결과 파일을 쓰므로 새 결과는 순위에 들어가지 않는다(사용자 결정대로 유지).
5. **가점**: 서버가 추출기 버전이 다른 결과를 버려서, 다시 뽑고 시험 서버에 새 코드를 올려 재시작하기 전까지 가산점이 전부 "모름"이 된다.
6. 다시 뽑으면 공용 DB 결과가 덮어써진다(되돌리는 길은 백업).
7. 업력 근거 화면은 9/28 업력 재추출 결과로 일부 공고를 덮어 보여 줘서, 자격요건을 바꿔도 그 공고들은 옛 값이 보인다.
