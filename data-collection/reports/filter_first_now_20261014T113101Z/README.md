## 기준일 모집 상태 — 규칙과 근거

- 근거: notices.recruitment_status·apply_end·snapshot_at·raw.rcrt_prgs_yn (SELECT 만). 9/30 부터 매일 배치가 K-Startup "모집 중 목록에서 빠진 공고"를 마감으로 바꾼다(`shared/store_mysql.close_missing`, 닫을 때 `snapshot_at` 을 그 목록 시각으로 덮는다). 첫 일괄 닫기 2026-10-01. 9/28 실행 때는 이 기능이 없어 이 공고들이 모두 "모집 중"이었다.
- 지금 마감인 말뭉치 공고 258건 — close_missing 이 닫음(원본 표시 모집 중) 258건 · 출처가 마감으로 준 것 0건.
- 규칙: 지금 '마감'(closed)인 말뭉치 공고만 본다. ① 닫힌 기록(snapshot_at)이 기준일 당일 이전 → 그대로 마감. ② 마감일(apply_end)이 기준일 전 → 그대로 마감(접수 기간이 이미 끝남). ③ 마감일이 기준일 당일·이후 → 기준일에는 모집 중이었다고 보고 '열림'. ④ 마감일 없음 → 원본 표시가 모집 중(raw.rcrt_prgs_yn='Y')이고 첫 일괄 닫기(close_missing 첫 실행, 기준일 뒤)보다 뒤의 날에 닫혔으면 '열림', 아니면 닫힌 날을 알 수 없어 지금 상태 그대로. DB 는 바꾸지 않고 메모리에서만 바꾼다.
- 판정 결과: 마감일이 기준일 이후라 되돌림 142 · 첫 일괄 닫기 뒤에 닫혀 되돌림(마감일 없음) 0 · 기준일 전에 닫힌 기록이 있어 그대로 0 · 마감일이 기준일 전이라 그대로 116 · 마감일이 없고 닫힌 날을 알 수 없어 그대로 0.
- 한계: 마감일 전에 일찍 모집을 끝낸 공고는 구분하지 못한다(기록이 없다). 지금 열림·모름인 공고는 그대로 둔다.
