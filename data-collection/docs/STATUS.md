## 현재 코드에서 확인한 상태

2026-09-18 로컬 파일을 읽고 확인한 내용이며 서비스 실행 검증 결과는 아니다.

- `collect/`, `search/`, `shared/`, `db/`, `ec2/`, `tests/` 등으로 파일이 분리돼 있다.
  폴더 정리는 사용자가 Claude에게 요청했다고 설명했다. 이번 Codex 작업 이전부터 다수의 이동·수정·미추적 파일이 존재한다.
- 배치 진입점은 `collect/daily_pipeline.py`이며 수집 → 정규화 → MySQL 저장 → 첨부 추출 → 임베딩·색인 → 업로드 → 자격요건 추출 경로가 있다.
- `shared/embed.py`는 BGE-M3 공고 임베딩을, `search/vecstore.py`는 로컬 벡터 색인·검색을 담당한다.
- `search/app.py`의 매칭 API는 `dense`와 `hybrid`를 지원하며 기본값은 `hybrid`다.
  `search/hybrid.py`는 BM25와 가중치 지정이 가능한 RRF를 제공한다.
- 이전 구조 파악 이후 `search/applicant.py`, 가중치 비교 API·화면, `eval/weight_eval.py`,
  `tests/test_applicant.py` 등이 존재함을 추가 확인했다. 이번 작업에서 추가하거나 검증한 기능이 아니다.
- `eval/`에는 질의, 사람/LLM 판정, qrels, 기존 평가 결과가 있다. 과거 평가 결과를 현재 코드의 성능으로 단정하지 않는다.

## 검증 상태와 남은 확인

- Codex의 2026-09-18 최초 매칭 검토: [상세 결과](MATCHING_REVIEW_20260918.md).
  현재 API는 하이브리드 검색 후 마감 제외·규칙 재정렬을 수행한다. 업력은 별도 자격 확인 API에서 판정한다.
  당시 재현한 사항: 시도/시군구 우선순위 역전, score 모드의 RRF·코사인 점수 혼용,
  마감 후보 제거 후 결과 미보충, 설립일 없는 사업자의 예비창업자 오판정.
  관련 기존 단위 테스트는 33개 통과했으며 실제 DB·모델·HTTP 서버로는 검증하지 않았다.
  프로젝트 Python 실행 접근 제한으로 번들 Python 3.12.14와 기존 가상환경 패키지를 사용했다.

- 이전 재검토: [수정 재검토](MATCHING_REVIEW_20260918_FOLLOWUP.md).
  1번 지역 순서와 4번 설립일 누락/일반 문자열 처리는 해결 확인했다. 관련 테스트 42개 통과.
  당시 미수정 사항은 2번 점수 혼용, 3번 후보 미보충, 추가 발견한 유효하지 않은 날짜 처리였다.
  `2026-02-30` 등 4종은 내부 TestClient에서 `/api/match`·`/api/eligibility` 모두 HTTP 500을 재현했다.
  실제 서비스·DB·모델을 호출한 결과는 아니다.

- 최신 확인: Claude가 `parse_ymd()`에서 `ValueError`를 처리해 **유효하지 않은 날짜의 HTTP 500은 해결됐다.**
  Codex가 관련 테스트 45개, 잘못된 날짜·빈 값 8종 및 정상 날짜 3종 × API 2개(22건)를 확인했다.
  정상 윤년 날짜와 공고의 잘못된 시작일·마감일 파싱도 확인했다. 이번 수정 범위에서 추가 문제는 발견하지 않았다.
  현재 남은 원 검토 사항은 **2번 점수 혼용과 3번 후보 미보충**이다. 이번 수정에서 다루지 않았다.
  상세 검증 조건은 [수정 재검토 문서의 후속 확인](MATCHING_REVIEW_20260918_FOLLOWUP.md#후속-확인--무효-날짜-오류-해결)에 추가했다.

- 이번 작업: 공용 Markdown 문서 작성 완료. 6개 문서의 로컬 링크 32개 및 기존 문서 수정분의 공백 오류 검사를 통과했다.
  검색·수집·모델·DB 실행 검증은 하지 않았다.
- 폴더 이동 이후 전체 실행·테스트는 위 "Claude 가 실행으로 확인한 상태" 에서 통과했다.
- 평가 수치는 같은 코드로 두 번 돌려도 P@3(2) 기준 ±0.007 흔들린다(Chroma 근사 검색).
  작은 차이를 코드 변경의 효과로 해석하지 않는다.
- 모든 평가 수치는 **LLM 잠정 판정 기준**이다. LLM 과 사람 판정의 정확 일치는 0.64 로 기준(0.70) 미달이다.
- EC2 배포본은 패키지 분리 이전의 평면 구조 그대로다(크론 영향 없음). 새로 올릴 때 경로를 맞춘다.
- BM25 색인은 서버 시작 시 만든다. 매일 배치 후 서버를 재시작하기 전까지 새 공고가 단어 검색에 반영되지 않는다.
- `README.md`, `FLOW.md`, `HANDOFF.md`, `eval/README.md`에는 과거 시점의 설명과 수치가 있다.
  예: README의 9단계 요약 외에 실제 배치에는 자격요건 추출 단계가 있고, ML 기능은 시험용 API와 연결된 부분이 있다.
  이번에는 전체 문서를 재작성하지 않았으므로 해당 기능을 작업할 때 실제 코드와 대조한다.
- 기존 수정의 작성자·완료 여부를 Git 상태만으로 확정할 수 없다. 기존 변경과 자신의 변경을 구분한다.

## 사용자가 대기시킨 작업 (요청 전에는 시작하지 않는다)

- 업력을 공고에서 뽑아 칸으로 만들기. 멘토 조언에 따라 룰 → ML/DL → LLM 순서로 설계한다.
  현재 상태: 상위 3칸 중 업력 모름 0.647 · 업력 불가 0.051(`eval/gate_eval.py`, 정상 52질의).

- 팀원 웹과의 API 연결. 변경이 잦아 사용자가 시점을 정한다.
- 국세청 사업자등록 API(진위확인·상태조회) 연결. 주소는 제공되지 않으므로 설립일 검증·폐업 확인 용도다.
- 평가에서 마감 지난 공고 제외(서비스는 `hide_expired` 로 숨기지만 평가는 포함해 재고 있다.
  현재 자격 불가칸 0.218 중 접수기간 사유가 26칸).
