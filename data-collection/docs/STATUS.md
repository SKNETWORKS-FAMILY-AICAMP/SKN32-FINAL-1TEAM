### B의 최소 완료 범위

  신청 자격은 관련성과 분리하고 근거가 부족하면 `모름`으로 남긴다. 자격 전수 조사 때문에 관련성 평가를 미루지 않는다.

  테스트 53개 및 추가 가상 시나리오 12개 통과. 실제 DB·모델·성능·전체 테스트는 이번에 실행하지 않았다.
  추가로 낮은 우선순위 P3 한 건: `search_ms = dense_ms + bm25_ms`라 벡터 추가 조회·RRF 결합 시간이 빠진다.
  모의 시간으로 검색 10ms + 단어 검색 20ms + 벡터 조회 250ms를 설정했을 때 총 280ms 중 30ms만 보고함을 확인했다.
  이는 검색 결과 오류가 아니라 성능 표시 오류다. 상세는 [재검토 기록](MATCHING_REVIEW_20260918_FOLLOWUP.md) 마지막 항목.

- 이번 작업: 공용 Markdown 문서 작성 완료. 6개 문서의 로컬 링크 32개 및 기존 문서 수정분의 공백 오류 검사를 통과했다.
  검색·수집·모델·DB 실행 검증은 하지 않았다.
- 폴더 이동 이후 전체 실행·테스트는 위 "Claude 가 실행으로 확인한 상태" 에서 통과했다.
- 평가 수치는 같은 코드로 두 번 돌려도 P@3(2) 기준 ±0.007 흔들린다(Chroma 근사 검색).
  작은 차이를 코드 변경의 효과로 해석하지 않는다.
- 모든 평가 수치는 **LLM 잠정 판정 기준**이다. LLM 과 사람 판정의 정확 일치는 0.64 로 기준(0.70) 미달이다.
- EC2 배포본은 패키지 분리 이전의 평면 구조 그대로다(크론 영향 없음). 새로 올릴 때 경로를 맞춘다.
- BM25 색인은 서버 시작 시 만든다. 매일 배치 후 서버를 재시작하기 전까지 새 공고가 단어 검색에 반영되지 않는다.
- `README.md`, `FLOW.md`, `HANDOFF.md`, `eval/README.md`에는 과거 시점의 설명과 수치가 있다.
  예: README의 9단계 요약 외에 실제 배치에는 자격요건 추출 단계가 있고, ML 기능은 시험용 API와 연결된 부분이 있다.
  이번에는 전체 문서를 재작성하지 않았으므로 해당 기능을 작업할 때 실제 코드와 대조한다.
