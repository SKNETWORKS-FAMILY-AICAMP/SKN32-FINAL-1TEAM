# 보안 정책

## 보호 대상

| 대상 | 어디에 있나 | 새면 생기는 일 |
|---|---|---|
| 팀 공용 DB 접속 정보 (`MYSQL_USER`·`MYSQL_PASSWORD`·호스트) | `data-collection/.env`, 배치 서버 `~/sbrain/data-collection/.env` | 팀 전체가 쓰는 공고·판정 데이터가 바뀌거나 지워진다 |
| DB 서버 인증서(CA) | PC `data/ec2-ca.pem`, 배치 서버 `~/sbrain/secrets/ec2-ca.pem` | 서버 신원 확인이 무력해진다 |

공용 DB에 대한 쓰기 승인은 한 번에 한 작업이다. 이전에 승인받은 쓰기를 근거로 다른 쓰기를 하지 않는다.

## 공고 서버 접근 정책 — 미정

- 지금 공고 서버(8000)에는 **로그인·키 같은 인증이 없다.** 인증 방식과 요청 본문 기록 여부는 공고 서버를 어디에 배포할지 정할 때 함께 정한다(조율 요청서의 운영 질문도 미답).
- 정해지기 전까지 지켜야 하는 것:
  - **바깥에 공개하지 않는다.** PC에서는 `127.0.0.1`에만 연다. 리눅스에서는 코드가 `0.0.0.0`에 열기 때문에, 서버에 올릴 때는 보안그룹·내부망으로 외부 접근을 막아야 한다(요청서 기준 AWS 내부망).
  - **신청자 입력을 저장하지 않는다.** 공고 서버는 요청 본문을 파일·DB·로그에 쓰지 않는다. 이를 바꾸는 변경은 정책 결정 전에는 하지 않는다.
  - 응답의 `stored_only`는 이름과 만 나이를 그대로 돌려주고, 사업자번호는 "입력함"으로만 돌려준다. 사업자번호 값을 응답·로그에 내보내는 변경을 하지 않는다.
- 검증 화면(8010)·판정 화면(8001, `eval/label_app.py`)·리랭커 시연(`/demo`)·분류 시연(`/classify`)은 내부 검토 전용이다. 배포 대상이 아니다.

## DB 접속

1. `MYSQL_USER`·`MYSQL_PASSWORD`가 비면 접속하지 않고 무엇이 빠졌는지 알린다(비워 두면 OS 계정으로 붙으려 해 엉뚱한 오류가 난다).
2. `MYSQL_SSL_CA`가 있으면 그 CA로 **서버 신원까지 검증**하는 TLS로 붙는다. 팀 DB는 이것을 쓴다.
3. `MYSQL_SSL=1`만 있으면 암호화만 하고 신원은 확인하지 않는다.
4. 둘 다 비면 평문이다 — 로컬 개발 DB에서만 쓴다. 팀 DB는 평문 연결을 거부한다(`require_secure_transport`).
5. 실패 경로: 인증 실패·CA 경로 오류·포트 차단은 모두 예외로 끝난다. 배치는 4단계에서 멈추고 트랜잭션을 되돌린다(DB는 전날 상태). 공고 서버는 켤 때 공고 정보를 못 읽으면 열리지 않는다.

팀 DB 3306 포트는 아직 IP 제한이 없다(배포 다음 단계로 계획).

## 비밀값 관리

- 비밀값은 `.env`에만 둔다. `.env`·`*.key`·`secrets.*`는 git에서 제외되어 있다. `.env.example`에는 이름과 설명만 둔다.
- 이미 설정된 환경 변수가 `.env`보다 우선한다. 배치 컨테이너는 이 규칙으로 `.env`의 Windows 경로(`MYSQL_SSL_CA`)를 덮는다.
- **공용 문서·결과 파일·로그·커밋에 키·비밀번호·접속 문자열·실제 신청자 개인정보를 쓰지 않는다.** 실험 DB 설정을 화면에 보일 때는 비밀번호를 뺀다.
- 배치 서버의 `.env`는 배치에 필요한 키 8개만 담고 권한 600이다.
- 교체: 자동 교체는 없다. 키·비밀번호는 사용자가 직접 바꾼다. **PC `.env`와 배치 서버 `.env`가 따로 있어 둘 다 바꿔야 한다**(한쪽만 바꾸면 그쪽 배치·서버만 실패한다).
- 인증키는 공공데이터포털의 **디코딩된 원본 키**를 넣는다. 인코딩된 키(`%2B`·`%2F`·`%3D` 포함)는 이중 인코딩으로 인증에 실패한다.

## 외부 사이트 수집 예절

- K-Startup 첨부 경로(`/afile/`)는 robots.txt `Disallow`라 **자동으로 내려받지 않는다.** 필요하면 창업진흥원에 정식으로 요청한다(발표 뒤 과제).
- 기업마당 첨부는 요청 간격 기본 1초(다운로드 실패 뒤에는 4배), 파일 30MB 상한, 연속 실패 20건이면 멈춘다. 실패한 첨부는 24시간 뒤에 다시 시도한다.

## 비용 통제 (OpenAI)

- 배치 LLM 단계는 바뀐 공고만 부른다(문서 해시가 같으면 건너뜀). 신청자 유형·업종·가점은 하루 300건 상한이고, 가점 상한은 한국 날짜 기준으로 같은 날 다시 돌려도 합산한다(`data/bonus_daily_calls.json`).
- 키가 없으면 LLM 단계는 실패하지 않고 건너뛴다(로그에 남음).
- AI 작업자가 돌리는 실험·재추출은 약 $5 이상이면 먼저 사용자에게 확인한다. 실행 전에 `--plan`이 있는 명령은 예상 대상·비용을 먼저 본다.
