## 1. 한 일

비유하면 공고 서버 가게에 **"오늘 재료가 신선한가요?" 창구**를 새로 열고, 기존 추천 접시에 **"이 요리 레시피가 바뀌었는지 알려 주는 꼬리표"**를 붙였습니다.

| 무엇 | 내용 |
|---|---|
| `GET /api/collection_status` | 응답 `{"status": "정상"|"지연"|"실패", ...}`. 기존 판정 함수(`search/collection_status.py check()`)를 그대로 쓰고, 그 위에 **서버가 메모리에 올린 공고가 24시간 넘게 오래되면 `정상` → `지연`** 규칙을 얹었다 |
| `/api/match` 결과 한 건 | `content_version`(공고 내용 지문), `bonus_score: null`, `bonus_items: []` 추가. 가산점은 03에서 채운다. 약속상 null·[]는 "계산하지 못함" |
| 서버 시작(boot) | 올린 공고의 저장 시각(`STATE['loaded_store_at']`)과 공고별 지문(`STATE['content_versions']`)을 읽는다. 둘 다 실패해도 서버는 열린다(`boot_errors`에 기록) |

### 왜 "서버가 올린 공고"까지 보나

공고 서버는 켤 때 공고를 메모리에 올린다. 매일 배치 뒤에는 **서버를 다시 켜야** 새 공고가 반영된다. DB 기준으로만 보면, 서버를 사흘째 안 켠 날에도 "정상"이 나와 사흘 전 공고로 추천하게 된다. 기준 문서는 "최종 수집 24시간 초과면 매칭 안 함"이라서, 실제로 추천에 쓰는 데이터 기준으로 판단하도록 했다. `실패`는 더 강한 상태라 그대로 둔다.

### DB를 못 읽으면 503

수집 상태를 읽지 못하면 상태를 지어내지 않고 HTTP 503 + `{"code": "COLLECTION_STATUS_UNAVAILABLE"}`을 준다. 조율 쪽은 다시 부르다가 "잠시 문제" 안내를 낸다. `실패`를 주면 "공고 정보를 갱신하는 중" 안내가 나가는데, 이는 사실이 아니다. 응답에는 DB 주소나 오류 원문을 싣지 않는다.

### 공고 내용 지문(`content_version`)에 넣은 것

- **넣음(원문만):** `notices`의 제목·본문·지원대상(글·분류)·제외 조건·업력 칸·지역·분류(대·중)·기관 3개·접수 시작·마감·접수기간 원본(JSON)·기간 유형·모집 상태·링크 2개, 그리고 **첨부 파일 바이트의 SHA-256**(`attachment_texts.content_sha256`). 추출한 글자가 아니라 파일 자체 지문이라 추출기를 바꿔도 그대로다.
- **뺌:** 수집·수정 시각(`snapshot_at`·`updated_at`·`last_import_id`·`created_at`), API 수정 시각, 정규화 경고, 원본 행 전체(`raw`), LLM이 뽑은 값(조건·판정표·가점). LLM 값은 다시 뽑으면 내용이 그대로여도 달라질 수 있어서 뺐다. 원문이 지문에 들어 있으니 원문이 바뀌면 지문도 바뀐다.
- 모양은 `cv1-` + SHA-256 앞 32자. 만드는 방식을 바꾸면 접두어를 `cv2`로 올린다.
- **(10/6 Codex 검수 P2-5 반영) 지금은 `cv2-`:** 첨부 지문을 **지금 달린 첨부(`notice_attachments.active`)** 로만 계산한다. cv1은 빠진·바뀐 첨부도 넣어 첨부 삭제를 감지하지 못했다. 10/6 같은 DB에서 첨부 지문이 달라진 공고 8건(비활성 첨부 9행).

## 4. 남은 일·알아 둘 점

- **하루 뒤 지문 비교 (미검증):** 지문이 수집 잡음 없이 내용이 바뀔 때만 바뀌는지는 하루가 지나야 알 수 있다. 10/6 스냅샷을 `data/notice_api/content_version_20261006.json`(cv1)에 남겼고, cv2로 바꾼 뒤 `data/notice_api/content_version_20261006_cv2.json`을 새로 남겼다 — **10/7 비교는 cv2 파일로** 한다. 10/7 09:00 배치 뒤 아래를 돌려 `by_field`에 날마다 바뀌는 칸(예: 링크에 붙는 값)이 몰려 있는지 본다. 몰려 있으면 그 칸을 빼고 접두어를 `cv3`로 올린다.
  ```powershell
  .\.venv\Scripts\python.exe -X utf8 -m search.content_version --compare data/notice_api/content_version_20261006_cv2.json
  ```
- 이 PC의 8000 서버는 아직 **옛 코드**로 떠 있을 수 있다. 새 창구를 쓰려면 다시 켜야 한다(사용자 확인 후).
- 이 PC의 벡터 색인은 10/2 이후 갱신되지 않는다(매일 배치가 서버로 옮겨 감). 01과는 관계없지만, 실제 연결(배포) 때는 공고 서버를 배치와 같은 곳에 두거나 색인을 받아 와야 한다.
- 조율 쪽에 알릴 것(05 답변서): 수집 상태 "지연" 기준에 **서버가 올린 공고의 나이**가 들어간다는 점, DB를 못 읽으면 503이라는 점.
