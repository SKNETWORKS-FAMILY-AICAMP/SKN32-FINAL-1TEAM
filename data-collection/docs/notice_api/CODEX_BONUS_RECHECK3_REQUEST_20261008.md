### 2.6 순위 비교 측정(재재검수 8절 요청) — `reports/bonus_rank_cases_20261008T035007Z/`
`-m eval.bonus_rank_cases`. 내 PC에서 서비스 `match()`(하이브리드, 상위 20)를 요청 `weights={'bonus': 0 | 0.2}`로 부름(서비스 기본값은 바꾸지 않음). 남은 10건마다 그 공고에 점수가 나오는 입력 + 정형 필터를 통과하는 유형·설립일 + 공고 지역으로 가상 신청자를 만들고 아이디어 세 가지:
- 공고 제목 그대로: 10건 모두 세기 0에서 이미 1위 → 변화 없음.
- 분야만 같은 평범한 문장: 10건 모두 20위 밖 → 변화 없음.
- 제목 핵심어(지역·연도·"공고·모집" 뺌): 4건이 세기 0에서 2위. 120238은 1위 "2026년 해외지사화사업 참여기업 모집 재수정"(가산점 모름, 검색 점수 4.0% 높음)을 앞질러 1위. 125997은 1위 "2026년 여성기업 육성사업 공고"(가산점 모름, 검색 점수 같음)를 앞질러 1위. 122057·126642는 1위도 같은 가산점이라 그대로.
- 읽을 점: 0.2는 검색 점수 차가 몇 % 안 되는 경쟁 공고끼리만 순서를 바꾼다. 앞질린 공고는 가산점이 "모름"인 공고다(가점이 없다는 확인이 아님).

## 3. 봐 주셨으면 하는 것

1. R2-P1-1~5·R2-P2-1 처리가 지적한 경로를 막는가. 특히 ④ 점수 주인·⑤ 택1은 원문 관계를 해석하지 않고 의심되면 null로 막는 보수적 근사다 — 알고 있는 틈: ④는 쉼표로만 이어진 "여성기업 우대 안내, 벤처기업 가점 10점"을 나누지 못한다(쉼표 나열과 구분할 수 없어서), ⑤는 단어 목록에 없는 표현을 놓친다. 이것으로 충분한가.
2. ①에서 짝이 False(안 가짐이 확실)면 "둘 중 하나"로 보는 사용자 결정이 부분합 정의(결정 0012)와 어긋나지 않는가.
3. ②를 "가점·인정 줄"로 한정한 것이 R2-P1-2 취지에 맞는가(한정하지 않으면 117928·125997의 "필수 제출서류: 최근 3개년 재무제표" 줄에 걸린다).
4. 공통 규칙(이전 계산이 null이면 null, 커지면 null)이 "더 엄격하게만"을 보장하는가.
5. 순위 세기 0.2(결정 0015): 2.6의 측정이 판단 근거로 충분한가, 남은 조건이 있는가. 가산점 "모름" 공고가 앞질리는 쏠림을 어떻게 볼지.
6. 남은 10건의 원문 대조가 맞는가.
