## 1. 지적별 응답

### P1-1 · 선택 조건 중복 합산

- 확인: 지시문 규칙 5가 "또는"을 두 항목으로 나누라고 했고, `score()`는 이름·근거가 **모두** 같을 때만 합쳤다. 실제 v3 결과에서 같은 근거 문장이 점수 있는 항목 여러 개로 나뉜 공고는 103건이었다. 그중 계산되는 종류(인증·여성·장애인·지역)가 2개 이상인 공고는 58건이다.
- 수정
  - 추출기 v4가 항목마다 `group`을 낸다. 지시문은 같은 group을 두 경우로만 정했다. ① 한 행이 조건 여러 개를 나열하고 점수가 하나인 경우, ② 문서가 "하나만 인정"이라고 적은 경우. 같은 배점 칸을 쓰는 것(병합 칸, "각 1점")과 "최대 N점/N개"는 다른 group으로 두게 했다.
  - 표본 v4 첫 판에서 LLM이 F03·F16·F20의 따로 더하는 항목을 한 group으로 묶었다. 그래서 위 문구를 넣고 다시 확인했다(§2).
  - 계산은 `_groups()`가 맡는다. 같은 `group`이거나 같은 근거 문장이면 한 묶음이고, 세부사업이 같을 때만 묶는다. 묶음은 해당 항목 중 가장 큰 점수 하나만 센다.
  - 세부사업(`program`)이 여럿이면 세부사업마다(공통 항목 포함) 따로 계산해 가장 큰 값을 쓴다. 항목 이름에는 `[세부사업]`을 붙인다. 신청자가 어느 세부사업에 낼지 모르기 때문이다.
- 검증
  - `test_bonus.test_choice_row_counts_once`: F19 행에서 인증 1·2·3개 모두 **10점**이다.
  - `test_programs_are_scored_separately`
  - 표본 F19 v4는 한 항목(`certs` 3개, 10점)으로 나왔다.

### P1-2 · 근거 위치·연번·부정 조건

- 확인: `find_quote()`가 `doc.find(words[0])`로 자르는 것과, 근거와 구간 숫자의 합집합으로 검사하는 것을 확인했다.
- 수정
  - `locate_all()`은 공백을 뺀 문자열에서 **실제로 일치한 자리**를 원문 좌표로 돌려준다. 단어 순서로 느슨하게 맞출 때는 근거에 없는 부정어(`제외·미해당·해당 없·불가·아닌·않는·않은·미포함`)가 끼어 있으면 인정하지 않는다.
  - 점수는 **원문 구간에서만** 찾는다. LLM이 재구성한 quote의 숫자는 쓰지 않는다.
  - `_points_in()`은 'N점'과 괄호 속 숫자를 늘 본다. 단위 없는 숫자는 'N점'이 없을 때만 보고, 맨 앞 숫자는 연번으로 보고 뺀다.
  - 합계 한도는 같은 숫자 'N점'이 '최대·한도·이내·까지·상한·합계·합산·총·초과' 가까이에 있고 '가점'과도 가까울 때만 남긴다.
- 검증: `test_extract_bonus.CodexReproTests`에 재현 세 가지를 그대로 넣었다(다른 줄 9점, 연번 1, '제외하고' 재구성). 세 경우 모두 점수를 승인하지 않는다. 한도 근거·잘린 발췌 시험도 있다.
- 한계: 표가 글자로 풀린 문서에서 항목·배점 칸의 연결은 여전히 LLM이 짚은 조각(`points_source`)과 거리(600자)로만 확인한다. 항목 주체와 배점 셀을 구조적으로 연결하지는 못한다(P2-7).

### P2-1 · 추가 조건

- 수정
  - 추출기가 `extra_conditions`를 낸다(기간·유효기간·역할·제외 대상·"그리고" 조건).
  - `item_hit()`은 추가 조건이 있으면 '해당'을 **모름**으로 낮추고, '해당 아님'은 그대로 둔다.
  - 전남광주로 묶인 신청자가 '전남'만 또는 '광주'만 요구하는 가점에 맞는지는 시·군·구로 가린다. 광주 5개 구면 광주로 본다. 시·군·구가 없으면 모름이다.
- 검증: `test_extra_conditions_turn_hit_into_unknown`(F12 가족친화·F20 "개인사업자 제외"), `test_region_and_district`.
- 영향: 추가 조건이 붙은 항목이 많다. 표본 F12·F13·N07은 대부분 모름이 된다. 그만큼 가산점 null이 늘어난다(§3 분포). 지어내지 않는 쪽을 택했다.

### P2-2 · 발췌 잘림

- 수정: `build_parts()`는 모든 출처의 '가점·가산점' 주변을 먼저 담고, 남은 자리에 '우대·우선 선정' 주변을 담는다. 최대 길이는 6,000자에서 12,000자로 늘렸다. 가점 구간을 다 담지 못하면 `complete=False`가 되고, LLM이 '없음'이라고 해도 `unverified`(모름)로 둔다.
- 검증
  - `test_bonus_windows_come_before_preference_windows`
  - `test_cut_document_cannot_say_none`
  - 표본 **N07은 v4에서 `found`**: 신규 10, 직전 탈락 2, 여성·장애·가족친화 각 3 등이 '중소기업 운전·육성(일반)자금' 세부사업으로 잡혔다.

### P2-3 · 우대만 있는 공고

- 수정: 대상 고르기를 자르기와 같은 말(`가점·가산점·우대·우선 선정/지원/선발`)로 넓혔다. 금리·금액 우대와 선정 뒤 혜택은 지시문에서 계속 뺀다.
- 결과: 대상(LLM 부를 공고)이 667건에서 969건으로 늘었다. 표본 **N05는 v4에서 `found`**이고 "R&D PULL-UP 사전매칭형" 항목이 있다(점수 없음 → 계산은 모름).

### P2-4 · 오래된 가점

- 수정

  - 서버 `boot()`는 `bonus.load(versions=지금 지문, extractor_version=지금 버전)`으로 둘 중 하나라도 다른 행을 버린다(→ null). 지문 계산이 실패하면 가점을 아예 쓰지 않는다.
  - `plan_work()`는 발췌 지문·추출기 버전·내용 지문 셋이 모두 같아야 건너뛴다. 그래서 발췌 밖이 바뀐 경우와 가점 말이 없는 공고의 원문이 바뀐 경우도 다시 뽑는다.

### P2-7 · 표 점수 null
