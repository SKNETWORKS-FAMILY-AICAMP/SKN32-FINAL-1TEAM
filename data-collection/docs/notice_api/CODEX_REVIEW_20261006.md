### P1-1. 선택 조건을 독립 항목으로 합산하여 실제 가점을 부풀린다

위치: [search/bonus.py](C:/mok_workspace/SKN32-FINAL-1TEAM/data-collection/search/bonus.py:155) · [collect/extract_bonus.py](C:/mok_workspace/SKN32-FINAL-1TEAM/data-collection/collect/extract_bonus.py:110)

표본 F19 `bizinfo:PBLN_000000000122057`의 원문은 “벤처, 이노비즈, 메인비즈 기업 : 10점”이라는 **한 행**이다. 추출기는 세 인증을 각각 10점 항목으로 나누며, 계산기는 이름·quote가 모두 같은 경우만 중복으로 제거한다. 인증이 두 개면 두 항목이 남는다.

실제 저장된 표본 항목에 `certifications=['벤처기업','이노비즈']`를 넣어 `bonus.score`를 실행한 결과:

```text
bonus_score = 15
bonus_items = [
  {'name': '벤처기업', 'points': 10},
  {'name': '이노비즈 기업 (합계 한도 15점 적용)', 'points': 5}
]
```

이 두 인증만으로 확인 가능한 점수는 같은 행의 **10점**이다. 공고 전체 한도 15점은 다른 가점까지 포함한 한도이므로 이 중복을 해소하지 못한다. 부풀린 점수는 카드 표시와 `bonus_boost` 모두에 전달된다. F06의 “제조업 또는 사회적경제기업”, F13의 인증 묶음도 같은 구조다.

수정 방향: 같은 평가 행·선택 조건·세부사업을 식별하는 그룹과 적용 범위를 보존하고 그룹 내 점수는 한 번만 인정한다. 중복 인정이 확인되지 않으면 합산을 보류한다. `uncertain`을 저장만 하고 계산에서 버리는 현재 경로도 함께 검토해야 한다.

재검증 조건: F19에서 인증 1개/2개/3개 모두 해당 인증 행의 기여는 10점. 다른 확정 가점이 있을 때만 공고 전체 한도를 적용. 국내/국외·사업별 행을 무조건 중복 제거하여 유효한 선택지를 잃지 않는지도 확인.

### P1-2. 근거 검사에서 다른 구간의 점수·연번·부정 조건을 승인한다

위치: [collect/extract_bonus.py](C:/mok_workspace/SKN32-FINAL-1TEAM/data-collection/collect/extract_bonus.py:240) · [collect/extract_bonus.py](C:/mok_workspace/SKN32-FINAL-1TEAM/data-collection/collect/extract_bonus.py:218) · [collect/extract_bonus.py](C:/mok_workspace/SKN32-FINAL-1TEAM/data-collection/collect/extract_bonus.py:287)

공백을 제거한 quote가 문서에 있으면, 실제 일치 위치 대신 **첫 단어가 처음 나온 위치**에서 span을 자른다. 이후 quote와 잘못된 span의 숫자를 합집합으로 비교한다.

재현:

```text
원문 = '여성기업 가점 9점. ' + '배경 설명 ' * 30 + '여성기업 가점 1점.'
quote = '여성기업 가점 1점'
LLM points = 9
find_quote → 앞쪽 '여성기업 가점 9점...' 구간
verify → points=9, status=found, problems=[]
```

quote는 뒤쪽 1점 문장인데 앞쪽 9점 숫자로 검증된다. 별도로 `원문='1 여성기업 가점 2점'`, `quote='1 여성기업 가점'`, `points=1`도 problems 없이 found로 승인했다. 표의 연번 1을 점수로 인정한 것이다.

완화된 단어 순서 검사도 `quote='여성기업 가점 1점'`를 `원문='여성기업은 제외하고 벤처기업 가점 1점'`에서 인정했다. 글자 존재·순서만으로 조건 주체와 부정을 보장하지 못한다. `max_total_points`는 범위만 검사하고 원문 근거는 확인하지 않는다.

수정 방향: 실제 일치 구간 좌표를 사용하고 항목 주체·조건·배점 셀을 연결한다. 연번·평가 기본 배점·다른 항목 점수를 분리한다. 부정·선택 조건이 제거된 재구성 quote는 확정 근거로 사용하지 않는다. 한도 역시 원문 근거를 검증한다.

재검증 조건: 위 세 사례는 모두 확정 점수 승인 금지. 정상적인 표 셀 교차 사례는 별도 근거와 배점 연결을 입증해야 한다.

### P2-1. 추가 조건을 확인하지 않고 인증·지역·성별만으로 해당을 확정한다

위치: [search/bonus.py](C:/mok_workspace/SKN32-FINAL-1TEAM/data-collection/search/bonus.py:81) · [search/bonus.py](C:/mok_workspace/SKN32-FINAL-1TEAM/data-collection/search/bonus.py:112)

인증 항목은 알려진 certs와 신청자 인증의 교집합이 하나라도 있으면 True다. 인증 시기·마감일 유효성·주관기관 역할·AND 조건을 읽지 않는다. 지역은 일부 인증·연구소 조건만 보완하며 사업자 유형이나 본사/공장 구분을 보지 않는다.

실제 F12 가족친화인증 항목은 **최근 3년 이내·마감일 유효·주관연구개발기관** 조건을 가진다. 그 인증만 입력하면 True가 나왔다. 또한 F20 원문과 같은 “도내 본사 및 사업장(개인사업자 제외)”를 5점 지역 항목으로 구성하고 개인사업자·충남 신청자를 넣으면 True가 나왔다. 개인사업자는 명시적 제외 조건을 충족하지 못한다. 이 후자는 실제 표본의 points가 null이므로 현재 그 행에서 5점을 지급했다는 뜻은 아니다. 점수 누락이 해소되면 바로 드러나는 계산 경로 문제다.

여성 항목도 “대표”라는 단어가 있으면 여성기업 인증 또는 여성 성별만으로 True다. 공동대표·기관 역할 등 조건은 별도로 확인하지 못한다. 전남과 광주를 같은 지역으로 묶는 입력 계약은 일반 지역 순위에는 사용할 수 있어도, 전남 단독 가점의 정확한 주소 증명에는 부족하다.

수정 방향: 추가 조건을 구조화하여 입력으로 확인 가능한 조건만 판정한다. 명시적 제외는 False, 충족 여부를 모르는 추가 조건은 None으로 둔다. 복합 인증의 AND/OR, 지역의 적용 주체와 본사·공장·종사자·공급기업 구분을 보존한다.

## 9. 변경·보존 확인

검수 중 읽기 전용 Git 조회, DB SELECT, 모킹 시험을 수행했다. 코드와 DB 수정, 스테이징·커밋·push, 유료 API 호출은 수행하지 않았다. 시험 임시 파일은 시험 프레임워크의 임시 폴더만 사용했다.

검수 시작 시 주요 코드·시험·마이그레이션·STATUS/WORKLOG/문서 지도 16개 파일의 SHA-256을 기록했고, 종료 시 동일 여부를 대조했다. 이 결과 파일만 새로 작성했다. 기존 Claude 변경과 미추적 파일은 검수 대상 상태 그대로 보존했다.
