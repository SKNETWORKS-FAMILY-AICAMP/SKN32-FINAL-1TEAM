## Codex 검수 반영 — 추출기 v4 (2026-10-06)

비유: 메뉴판(가점 목록)을 만들 때 **"이 중 하나만"이라고 묶인 줄**을 따로따로 적어 두면 손님이 두 번 받는다. v4는 메뉴판에 묶음 표시(group)·세부 코너(program)·추가 조건을 함께 적고, 계산할 때 묶음은 한 번만 센다.
메뉴판이 옛것이면(공고문이 바뀜) 그 메뉴판은 쓰지 않는다.

| 바뀐 것 | 전(v3) | 후(v4) |
|---|---|---|
| 선택 조건 | "벤처·이노비즈·메인비즈 10점"이 항목 3개로 나뉘어 인증 2개면 15점 | `group`(한 행의 선택지·"하나만 인정")은 한 번만 센다 → 10점 |
| 세부사업 | 사업별 가점을 모두 더함 | `program`별로 따로 계산해 가장 큰 값, 이름에 `[세부사업]` |
| 추가 조건 | "최근 3년 이내", "개인사업자 제외"를 보지 않고 해당 | `extra_conditions`가 있으면 해당 → **모름** |
| 근거 위치 | 첫 단어가 처음 나온 자리로 검사(다른 줄 점수 승인) | 실제로 일치한 자리, 부정어가 끼면 불인정 |
| 점수 검사 | 근거와 구간 숫자의 합집합(연번 승인) | 원문 구간의 'N점'·괄호 숫자, 연번 제외. 떨어진 배점 칸은 `points_source`가 600자 안에 있을 때 |
| 합계 한도 | 범위만 검사 | 문서에 '최대·한도…' + '가점' 가까이 있을 때만 |
| 발췌 | 6,000자, 앞에서부터 | 12,000자, **가점 구간 먼저** 담고 남은 자리에 우대. 가점 구간을 다 못 담으면 '없음' 대신 `unverified` |
| 대상 | '가점·가산점'이 나오는 공고 | '우대·우선 선정'까지 |
| 최신성 | 옛 가점을 그대로 씀 | `notice_bonus.content_version`(마이그레이션 008). 서버는 지문·추출기 버전이 지금과 다른 행을 쓰지 않음 |
| 하루 상한 | 실행마다 300건 | 한국 날짜 하루 300건(`data/bonus_daily_calls.json`) |
| 순위 세기 | 0.2 | **0**(가산점은 결과에 나가지만 순위에는 안 씀) |

표본: 검수와 같은 30건을 v4로 세 번 다시 뽑아 고쳤다(첫 판에서 LLM이 같은 배점 칸을 쓰는 따로 항목을 한 group으로 묶음 → 지시문 보강, 괄호 숫자 "(1)"이 빠짐 → 검사 보강, 같은 문구가 두 번 나오는 근거 → 배점 칸에 가장 가까운 짝). 표본별 결과는 [응답서 2절](../CODEX_REVIEW_RESPONSE_20261006.md).

## 3-1 · 가점 추출기와 표본 시험

### 추출기가 하는 일

| 순서 | 내용 |
|---|---|
| 대상 | 열린 공고 중 공고문(API 개요·지원대상·첨부 본문)에 "가점·가산점"이 나오는 공고. 10/6 기준 **667건** |
| 자르기 | 공고문 전체 대신 "가점·가산점·우대·우선 선정" 주변(앞 200자·뒤 700자)만, 최대 6,000자 |
| LLM | `gpt-5.6-luna`(추론 medium), 구조화 출력. 항목마다 이름·점수·종류·인증·지역·조건·근거 원문 |
| 코드 검사 | ① 근거 원문 대조 — 단어가 같은 순서로 가까이 모두 있어야 인정(표가 글자로 바뀌며 칸이 끼어드는 것은 허용) ② 점수는 근거 구간에 숫자로 있을 때만(단위 붙은 "3년"·"30%" 등은 점수 아님) ③ 지역이 4곳 이상이면 비움 ④ 상태 셋: `none`(가점 없음) · `found`(항목 있음) · `unverified`(찾았지만 근거가 안 맞아 모두 버림 = 모름) |

**종류(kind)** 는 웹 입력으로 판단할 수 있는지에 맞춰 나눴다: 여성 · 장애인 · 청년(대표자 나이) · 지역 · 인증 · 고용 · 수출 · 특허 · 이전실적 · 재창업 · 업종 · 기타.

**가점이 아닌 것**(지시문): 감점, 기본 평가 배점, 지원 금액·금리 우대, 자격 조건 자체, **이 공고에 선정된 뒤 받는 혜택**("선정 기업은 다른 사업에서 가점").

## 3-3 · 신청자별 가산점 계산 (`search/bonus.py`)

비유: 공고마다 만든 가점 메뉴판을 손님 정보(성별·인증·지역)와 한 줄씩 맞춰 본다. 줄마다 **해당 · 해당 아님 · 모름** 셋 중 하나.

| 가점 종류 | 판정 |
|---|---|
| 여성 | 근거에 '대표'가 있으면 대표 성별로(여성기업 인증도 인정). 그 밖에 '여성기업'을 요구하면 인증과 대조. 그 밖(여성연구자 비율 등)은 모름 |
| 장애인 | '장애인기업'을 요구할 때만 인증과 대조. 장애인표준사업장·장애인 고용 등은 모름 |
| 인증 | 우리 인증 목록 14종에 있는 인증만 신청자 목록과 대조. 목록 밖(명문장수기업 등)은 모름 |
| 지역 | 근거 글에 그 시·도(또는 시·군·구, '도내·관내')가 적힌 항목만 시·도 대조. 시·군·구가 적혀 있으면 시·군·구까지. 인증·연구소 조건이 함께 있으면 그 조건이 없을 때 모름 |
| 청년 | 생년월일과 "만 N세 이하·미만" 대조(지금 조율 쪽이 생년월일을 보내지 않아 모름) |
| 재창업 | 첫 창업 여부 |
| 고용·수출·특허·이전실적·업종·기타 | 입력이 없어 모름 |

신청자 인증 목록은 화면에서 고른 것이라 **고르지 않은 인증은 없다**고 본다.

**공고 합계:** 행 없음(첨부를 못 읽음, K-Startup 등) → `null` · `none`/`no_mention` → `0` · `unverified` → `null` · `found`면 점수 있는 해당 항목의 합(공고 합계 한도로 자르고, 자른 만큼 마지막 항목을 줄여 **항목 합 = 합계**를 지킨다). 해당 없이 모두 '해당 아님'이면 0, 모름이 섞이면 `null`. 같은 항목(이름·근거 같음)이 두 번 뽑혔으면 한 번만 센다.

**연결:** 서버 시작 때 `STATE['bonus']`로 읽어 추천 결과 `bonus_score`·`bonus_items`, 공고 상세 `bonus_info`(`found`일 때만)에 넣는다.

**점검에서 고친 것(무작위 15·20건을 근거 문장과 함께 읽음, AI 참고):** 처음 규칙은 너무 후했다 — "장애인표준사업장"을 장애인기업 인증으로, "서울 소재 기업부설연구소"를 서울 소재만으로, "여성연구자 10% 이상"·"가족친화인증"(LLM이 여성으로 분류)을 여성 신청자에게, "도시철도2호선 공사현장 반경 300m 상가"를 시·도만으로 줬고, 같은 "여성기업 1점"을 두 번 셌다. 위 표의 규칙으로 고친 뒤 무작위 20건에서 틀린 판정을 찾지 못했다. 반대로 너무 엄격해진 "대표이사가 여성인 기업"(LLM이 이름을 '여성기업'으로 붙임)은 성별을 먼저 보도록 고쳤다.

## 3-4 · 순위 반영

| 항목 | 내용 |
|---|---|
| 방식 | 검색 점수(하이브리드면 RRF, 의미 검색만이면 유사도) × (1 + 세기 × min(가산점, 10)/10). 기존 규칙 묶음(다른 시·도 → 다른 시·군·구 → 예비창업 추정 → 업종 → 집단 근거) **안에서만** 순서를 바꾼다 — 다른 지역 전용 공고를 가산점으로 끌어올리지 않는다 |
| 세기 | `Weights.bonus` **기본 0.2**(가산점 10점이면 검색 점수 +20%) |
| 안전장치 | 후보 중 가산점이 있는 공고가 하나도 없으면 다시 정렬하지 않는다 → 가산점 전과 순서가 정확히 같다. 점수가 없는 경로(마감임박순)도 그대로 |
| 측정 | `eval/bonus_rank_eval.py` → `reports/bonus_rank_eval_20261006T015155Z/`. 기준일 9/15 말뭉치 2,084건(가점 행 1,576) · 정상 질의 58 · 가상 신청자 3종 · 세기 0/0.1/0.2/0.3 |

| 가상 신청자 | 상위 10 중 가산점 있는 공고(평균) | 세기 0.3에서 자리 바뀐 수(평균) | 신청 불가@10 · P@3 · nDCG@10 · 쓸모@10 |
|---|---|---|---|
| 여성 · 서울 | 0.02 | 0.00 | 변화 0 |
| 여성기업 · 벤처 · 경기 | 0.21 | 0.31 | 변화 0 |
| 남성 · 장애인기업 · 이노비즈 · 전남광주 | 0.03 | 0.00 | 변화 0 |

- **해석:** 세기 0.3까지 아이템과 맞는 공고가 밀려나는 일은 측정되지 않았다. 다만 상위 10 안에 가산점 공고가 드물어 효과 자체가 작게 잡혔다(9/15 말뭉치 중 지금 닫힌 공고는 가점을 추출하지 않음). 관련도 정답은 가산점을 모르므로 "가산점이 좋은 순위인가"는 재지 못한다. 0.1~0.3이 모두 같아 가운데 0.2를 골랐다.
- **실제 데이터 끝 확인:** 실제 `boot()` 후 가짜 신청 정보(여성기업·벤처·경기 성남시)로 `/api/match` offset 0·10 — 가산점 형식(항목 합 = 합계) 어긋남 0, 속성 없는 신청자는 세기 0과 0.2 순서가 같음. 이 아이템은 상위 20이 대부분 K-Startup 공고라 가산점이 null이었다(첨부 미수집).
