## 1. 무엇을 했나

비유하면, 손님(조율 에이전트)이 실제로 쓰는 **주문 앱을 그대로 가져와** 우리 가게(공고 서버)에 진짜로 주문해 봤습니다. 앞선 시험들은 우리가 손님 흉내를 낸 것이었다면, 이번에는 손님 쪽 코드가 직접 주문하고 받은 음식을 직접 검사했습니다.

조율 쪽 코드 중 다음을 **고치지 않고 그대로** 썼다.

| 조율 쪽 부품 | 하는 일 |
|---|---|
| `match_request` | 웹 입력(시·도 17개 표기 등)을 공고 서버 요청 본문으로 바꿈 |
| `NoticeClient` · `UrllibTransport` | 실제 HTTP 호출(표준 라이브러리, 프록시·다른 주소 따라가기 없음) |
| `make_tc2` · `make_g01` | 실제 Task 함수 — 수집 상태 → 추천 → 카드 / 공고 상세 → 자격 판정 |
| `Tools` | 재시도·호출 기록 도구. 응답이 약속 밖이면 `FormatError` → 재시도 → `ToolCallExhausted` |

신청자 정보는 **가짜**다(조율 쪽 시험 견본 `tests/test_notice_tasks.py`의 `item()`·`company()`와 같은 모양, 이름·사업자번호도 가짜).

## 2. 결과

| 확인 | 결과 |
|---|---|
| T-C2 가짜 신청자 4명 × 첫 조회·추가 조회(8회) | 모두 카드 10건, 수집 상태 `정상`, rank 1~10·11~20, 대체 경로 없음. 첫 호출 2.7초(서버 첫 질의), 이후 약 0.5초 |
| 시·도 바꾸기 | 서울특별시 → `서울`, 광주광역시 → `전남광주`, 경기도 → `경기`, 충청남도 → `충남` — 공고 서버가 받아 형식 오류 없음 |
| G-01 가짜 신청자 4명 × 첫 조회 카드 10건(40회) | 형식 오류 0. 업력: 설립 2025-03-02 → 1.6년, 2019-05-01 → 7.4년, 2012-01-02 → 14.8년(사사오입) |
| 공고 없음 | `ResourceNotFound`(404 + `NOTICE_NOT_FOUND`를 값으로 받음 → 조율 쪽 X-C2-GONE 경로) |
| 경로 없음 404 | 공고 없음과 구분됨 — `ProviderError(404)` |
| 설립일 없는 사업자 | 판정 API를 부르지 않고 `missing_inputs=['foundedAt']`(조율 쪽 규칙) |
| **모든 공고 G-01**(가짜 개인사업자 1명) | **2,765건, 형식 오류·공고 없음 0**, 통과 2,542, 65초(건당 23ms, HTTP 2회) |

참고: 사업자 신청자는 모든 공고에서 "확인 필요"가 있다(02에서 정리 — 개인·법인 자동 판정 안 함). 예비창업자는 상위 10건에서 확인 필요 0건이었다.

가산점은 카드마다 `0` 또는 `null`로 나왔다. 이번 가짜 신청자들이 상위 카드에서 받는 가점이 없었다. 공고 상세의 지원 금액·가점 원문은 있는 공고에서 그대로 전달됐다.

## 3. 다시 돌리는 방법

```powershell
# 조율 브랜치 코드를 작업 폴더 밖 임시 폴더에 푼다(작업 트리를 바꾸지 않는다)
git archive origin/feature/SB-87-init-supervisor-integration agent-orchestration/sbrain | tar -x -C <임시 폴더>
# 8000 서버를 켠 상태에서
.\.venv\Scripts\python.exe -X utf8 -m experiments.notice_api_contract --sbrain <임시 폴더>\agent-orchestration --all
```

- 조율 쪽 코드는 우리 `.venv`로 불러진다(pydantic 2.13.5 같음). 조율 쪽 시험 파일은 pytest가 필요해 쓰지 않고 견본만 옮겼다.
- OpenAI 호출·DB 쓰기 없음(공고 ID 목록만 SELECT).
