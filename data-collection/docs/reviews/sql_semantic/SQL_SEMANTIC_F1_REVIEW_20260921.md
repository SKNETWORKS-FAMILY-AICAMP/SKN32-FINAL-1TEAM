## 판단

최초 F1 반례였던 두 문제는 해결됐다.

- 제목의 `대기업`을 신청 가능한 기업 규모로 읽던 문제
- `제조업은 제외`를 `제조업만 허용`으로 뒤집던 문제

지원대상 칸만 사용하고, 부정·제외·거래 상대 문구를 허용 목록에서 빼며,
`no_limit`을 `unknown`과 구분한 방향도 적절하다. 관련 회귀 테스트와 UI fixture도 통과했다.

하지만 `제한 없음/무관/누구나`를 기업 규모와 업종에 공통 적용해 다른 조건의 제한 없음까지
전파하는 새 오판정이 확인됐다. 이 상태에서는 F1을 완료로 처리할 수 없으며 **부분 해결**이다.

## 수정 필요

### [P1] 한 조건의 “제한 없음”이 기업 규모와 업종을 모두 무제한으로 만듦

- 위치: `experiments/sql_semantic/conditions.py:134`, `:151-152`, `:187`, `:240`.
- `_says_no_limit(text)`는 전체 지원대상 문자열에서 아래 표현 중 하나만 찾는다.
  `제한 없`, `무관`, `관계없이`, `모든 기업`, `누구나` 등이다.
- 같은 함수를 `company_size_condition()`과 `industry_condition()`이 모두 먼저 호출한다.
  어느 필드에 대한 제한 없음인지 확인하지 않으므로 지역·업력·연령·일반 참가자격의 표현도
  기업 규모와 업종의 `no_limit`으로 바뀐다.

최소 재현 1:

```text
지원대상: 업종 제한 없이 중소기업만 신청 가능
```

현재 결과:

```text
company_size = no_limit
industry     = no_limit
대기업 신청자 기업 규모 판정 = 충족
```

기업 규모는 `중소기업`으로 명시돼 있으므로 대기업 신청자는 불충족이어야 한다.

최소 재현 2:

```text
지원대상: 기업 규모 제한 없이 제조업을 영위하는 기업만 신청 가능
```

현재 결과:

```text
company_size = no_limit
industry     = no_limit
서비스업 신청자 업종 판정 = 충족
```

업종은 제조업으로 제한됐으므로 서비스업 신청자는 불충족이어야 한다.

추가 재현:

- `업력 무관, 제조업을 영위하는 중소기업만 신청 가능`도 규모와 업종이 모두 `no_limit`이 된다.
- `기업 규모 제한 없이 모든 기업 신청 가능. 제조업은 제외`도 업종이 `no_limit`이 된다.

이는 표시 문제만이 아니다. `search.judge_list()`는 `no_limit`을 즉시 `OK`로 판정하므로,
명시적으로 불일치하는 신청자가 후보에서 제외되지 않는다.

### 실데이터 영향

로컬 실험 DB의 공고 1,852건을 SELECT로 읽고 현재 추출기를 적용했다.

- `industry=no_limit`: 28건
- 원인이 된 문자열: `누구나` 16건, `제한 없` 6건, `무관` 4건, `관계없이` 2건
- 28건 중 `업종/산업/분야` 언급이 있는 것은 7건뿐이었다.

대표 사례:

- `kstartup:176755`: `창업기업 지역 제한 없음` 때문에 업종이 제한 없음으로 변환됨
- `kstartup:178097`: `지역제한 없음` 때문에 섬유패션 관련 기업이라는 업종성 제한이 사라짐
- `kstartup:179227`, `kstartup:179228`: `지역 관계없이` 때문에 업종이 제한 없음으로 변환됨
- `kstartup:179297`: `연령제한 없음` 때문에 업종이 제한 없음으로 변환됨
- `kstartup:177844`: 특정 업종·기관만 공급한다고 적었지만 다른 위치의 `무관` 때문에 업종이 제한 없음으로 변환됨

따라서 `f1_impact_20260921.json`의 `industry unknown->no_limit 28건`은 F1 개선 효과로 보기 어렵다.
대부분 다른 필드의 제한 없음이 업종으로 새어 들어온 결과다. 기존 저장 조건은 변경되지 않았지만,
현재 추출기로 재적재하면 잘못된 `no_limit`이 저장될 수 있다.

## 수정 기준

1. `no_limit` 판정을 필드별로 분리한다.
   - 기업 규모: `기업 규모 제한 없음`, `기업 형태 무관`, 문맥상 모든 규모 허용 등
   - 업종: `업종 제한 없음`, `업종 무관`, `산업군 무관`, `전 업종` 등
2. `지역 제한 없음`, `업력 무관`, `연령제한 없음`, 일반적인 `누구나`가 규모·업종에 영향을 주지 않게 한다.
3. 같은 문장에 명시적 제한과 다른 필드의 제한 없음이 함께 있으면 명시적 제한을 보존한다.
4. `모든 기업`처럼 의미가 넓은 표현은 어떤 필드의 제한 없음인지 근거가 분명하지 않으면
   해당 필드를 `unknown`으로 두는 보수적 정책을 사용한다.
5. 위 최소 재현 네 건과 실제 사례를 회귀 테스트에 추가한다.
6. 수정 후 1,852건 영향 분석을 다시 생성하고 `industry=no_limit` 사례를 사람이 표본 확인한다.
7. UI의 F1 상태는 이 문제를 해결하고 재검토받기 전까지 `부분 해결`로 표시한다.

## 확인한 정상 동작

- F1 관련 테스트와 UI fixture/route 테스트 31개 통과.
- 전체 테스트 227개 통과, 13개 건너뜀.
- 결정성 테스트의 `timing_ms` 문제와 SQL 단계 제외 표시 문제는 앞선 UI 리뷰 후 수정돼 현재 통과한다.
- 최초 F1 반례 네 건은 UI fixture에서 모두 `기대대로`로 바뀌었다.
- `no_limit`을 검색 판정에서 `OK`로 처리하는 동작 자체는 올바르다. 문제는 추출 단계에서
  다른 필드의 표현을 `no_limit`으로 잘못 분류하는 것이다.

전체 테스트 통과는 현재 회귀 사례가 모두 통과했다는 뜻이며, 위 교차 필드 반례를 검증했다는 뜻은 아니다.

## 검증 범위와 한계

- 실험 DB는 SELECT만 사용했고 조건·벡터·검색 결과를 갱신하지 않았다.
- 실제 검색 비교를 다시 실행하거나 임베딩을 재생성하지 않았다.
- 28건은 현재 추출기 결과를 센 값이다. 사람 자격 판정 정답으로 확정한 수치가 아니다.
- F2·F3, Chroma 내용 정합성, 사람 관련성 판정은 이번 리뷰 범위가 아니다.
- 구현·테스트·STATUS·WORKLOG는 수정하지 않았다. 이 리뷰 문서만 추가했다.
- Git 스테이징·커밋·push는 하지 않았다.

## Claude에게 전달할 후속 작업

1. 필드별 `no_limit` 판정을 구현하고 위 교차 필드 최소 반례를 회귀 테스트로 추가한다.
2. 1,852건 영향 분석을 다시 실행해 잘못된 `industry=no_limit` 28건이 정리되는지 확인한다.
3. 저장된 `lab_conditions`와 `083852Z` 결과는 수정 전 값이므로 자동으로 현재 결과처럼 표시하지 않는다.
4. UI에서 F1을 `부분 해결`로 정정하고, 수정 후 fixture에 교차 필드 사례를 추가한다.
5. 전체 테스트와 실제 데이터 읽기 전용 대조 결과를 기록한 뒤 Codex 재검토로 인계한다.

## 2차 수정 재검토 결과 (2026-09-21)

### 판정: F1 승인

앞선 리뷰에서 지적한 교차 필드 `no_limit` 오판정은 해결됐다. 이번 재검토 범위에서는
새로운 F1 기능 결함을 찾지 못했다.

핵심 변경은 전역 `no_limit` 판정을 기업 규모와 업종의 필드별 문맥 정규식으로 분리한 것이다.
`누구나`, `모든 기업`, 지역·업력·연령의 제한 없음처럼 대상 필드가 불분명한 표현은
규모나 업종의 `no_limit` 근거로 사용하지 않는다. 같은 필드에 제한 없음과 명시적 제한이
동시에 있으면 `unknown`으로 두는 보수적 처리도 확인했다.

### 반례 재검증

앞서 실패했던 네 건은 모두 기대대로 처리된다.

| 지원대상 문구 | 기업 규모 | 업종 |
|---|---|---|
| `업종 제한 없이 중소기업만 신청 가능` | `known: 중소기업` | `no_limit` |
| `기업 규모 제한 없이 제조업을 영위하는 기업만 신청 가능` | `no_limit` | `known: 제조업` |
| `업력 무관, 제조업을 영위하는 중소기업만 신청 가능` | `known: 중소기업` | `known: 제조업` |
| `기업 규모 제한 없이 모든 기업 신청 가능. 제조업은 제외` | `no_limit` | `unknown` |

다음 표현 변형도 직접 확인했다.

- `업종 관계없이`, `산업 분야 상관없이`는 업종에만 적용된다.
- `기업 형태 관계없이`, `기업 규모 무관`은 기업 규모에만 적용된다.
- `지역 제한 없음`, `연령 제한 없음`은 기업 규모·업종으로 전파되지 않는다.

### 실데이터 영향 재검증

로컬 실험 DB 공고 1,852건을 SELECT로 읽어 현재 추출기를 대조한 결과는
`reports/verify_ui/f1_impact_20260921.json`과 일치한다.

- 기존 교차 필드 누수로 생성됐던 `industry=no_limit` 28건은 제거됐다.
- 현재 `industry=no_limit`은 1건이며, 근거 문구는 `산업군 무관`으로 필드 문맥이 명확하다.
- 수정 전 저장 조건 대비 총 54건이 변경 대상으로 집계됐다.
- 허용 목록이 실제로 좁아진 사례는 `kstartup:177864` 한 건으로,
  `대기업,스타트업`에서 `스타트업`으로 정정됐다.

이 수치는 추출기 변경 영향이며 사람 자격 판정 정답 건수로 해석하지 않는다.

### 테스트 결과

- F1 회귀 + UI fixture/route 표적 테스트: 37개 통과
- 전체 테스트: 233개 통과, 13개 건너뜀
- Claude 기록의 전체 테스트 3회 반복 결과와 이번 독립 실행 결과가 일치한다.

### 남은 운영 절차

F1 구현은 승인하지만, 저장된 `lab_conditions`와 기존 `083852Z` 검색 결과는 수정 전 추출값이다.
따라서 실제 검색 결과에 F1 수정이 반영됐다고 주장하려면 조건을 재추출하고 검색 비교를 다시 실행해야 한다.
이는 이번 코드 수정의 결함이 아니라 데이터 갱신 절차다.

F2·F3, Chroma 내용 정합성, 사람 관련성 판정은 이번 승인 범위에 포함하지 않는다.
구현·테스트·STATUS·WORKLOG는 변경하지 않았고 이 리뷰 문서만 갱신했다.
Git 스테이징·커밋·push는 하지 않았다.
