## P1

| # | 지적 | 조치 |
|---|---|---|
| 1 | Linux에서 `ec2/.env`만 두면 `collection_status.check()`가 접속 정보를 못 찾음 | 설명서 1절(빠른 시작)과 5절 예시를 바꿨다. 이제 `app._connect()`로 얻은 연결을 `check(connection=…)`에 넘기고 `finally`에서 닫는다(`collection_status_now()`). 3.2절에 Windows·Linux의 접속 정보 위치 표를 추가했다. **Linux 실제 실행은 여전히 미검증**이라고 적었다 |
| 2 | 합의 ⑩ "`app.eligibility()` 한 줄" 권고가 G-01과 다름(접수 시작 전 공고) | **권고를 철회했다.** 4.5절 제목을 "화면용 자격 확인 (G-01에 그대로 쓰지 않는다)"로 바꾸고 이유 세 가지를 적었다: 시작 전 공고를 X로 판정, 날짜 인자 없음, 404 `JSONResponse`. ⑩은 "공고 ID가 오면 G-01 안에서 `eligibility_of(id)`를 부른다"로 고쳤다. 시작 전 공고는 고를 수 있다는 결정을 2절에 적었다 |
| 3 | 공고 공급은 스텁 시험으로 검증되지 않음. `apply_end=None`만 적용하면 조율 `service.py:259`에서 예외 | 2절 "연결 전에 꼭 합의할 것"을 앞에 새로 두었다. ①은 세 가지를 함께 바꾸도록 제안했다: `date | None`, `apply_period_type` 함께 전달, 259행을 `ann.apply_end and ann.apply_end < 오늘`로. ③에는 "C는 스텁 공고의 양식·평가 항목·금액을 빌렸다 — 실제 공고 공급은 미검증"을 명시했다. 5절 표의 C 설명에도 같은 단서를 달았다 |
| 4 | "모름·입력 누락 = 통과"가 확인 필요 정보를 지움 | 결정은 유지한다(사용자). 2절 ⑦에 대가를 적었다: 아무 안내 없이 작성 단계로 가고, 모집 상태 모름 2,086·마감일 없음 985가 해당할 수 있으며, `E-G1-*` 안내가 사라진다. 제안은 `unknown_conditions` 칸 추가와 **화면 표시까지 함께 합의**하는 것으로 고쳤다. `extra="forbid"` 때문에 합의 전에는 채울 수 없다는 점도 적었다. 이유 문장이 필요하면 `app.eligibility()`의 `checks[].설명`을 참고용으로 쓸 수 있다(4.5) |

## P2

| # | 지적 | 조치 |
|---|---|---|
| 1 | 벡터 장애 시 `summary_embedding`을 못 꺼냄 | 4.4절에 두 경로를 적었다: 벡터 색인, 공용 DB `notices.embedding`(`np.frombuffer(값, '<f4')`, `collect/upload_vectors.py`가 올림). 합의 ⑪을 추가했다 |
| 2 | `industry_code`·`hiring_plan` 미전달, `TC2In.today` 무시 | 4.2 입력 표에 적었다: `main_industry`는 코드를 이해하지 못함, `hiring_plan`은 str↔bool. 주의에 기준일이 오늘 날짜라는 점을 넣었다. 합의 ⑫(변환 책임·규칙)를 추가했다. 예시 코드에는 변환을 넣지 않았다. 규칙이 합의되지 않았기 때문이다 |
| 3 | 직접 호출은 20건 상한을 거치지 않음 | 4.2 표에 `top`은 10 이하, `offset`은 0 또는 10만 쓴다고 적었다. 주의에 "HTTP 상한이 걸리지 않는다"를 넣었다. 예시 `tc2()`에 `top=min(inp.top_k, 10)`을 넣었다 |
| 4 | 재부팅·동시 요청 | 3.3절에 적었다: 실행 중 `boot()` 재호출 금지, 새 프로세스를 띄워 준비가 끝나면 교체, 동시 `match()` 안전성은 미확인이니 잠금이나 순서 호출을 권함 |
| 5 | 알려진 시작 실패(손상 신청자 유형 파일) | 3.3절 5번에 "알려진 문제"로 적었다. 9/28 재검수 P1 링크를 걸고, 배치 PC에만 있는 파일이라는 점도 적었다 |

## 남은 것

- **조율 담당과 합의**: 2절 ①②③⑦(급함), 6절 ④~⑫. 합의 뒤 실제 공고 공급을 넣은 통합 시험을 다시 한다.

- **재검수 요청**: 이 응답의 P1-1·P1-2 설명 수정과 2절 합의 제안이 충분한지 봐 달라.
