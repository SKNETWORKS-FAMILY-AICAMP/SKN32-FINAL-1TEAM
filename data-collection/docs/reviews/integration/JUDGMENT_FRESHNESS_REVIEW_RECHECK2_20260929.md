# 판정표 지문 신선도 2차 재검수 (2026-09-29)

대상: [Claude 2차 응답·재검수 요청](JUDGMENT_FRESHNESS_REVIEW_RECHECK_RESPONSE_20260929.md), [직전 Codex 재검수](JUDGMENT_FRESHNESS_REVIEW_RECHECK_20260929.md). 코드·DB·기존 문서는 수정하지 않았다.

## 결론

**보류 — P1 1건.** 반복 언급·단어 중간 공백의 기존 반례와, 원문 없이 strong 불가를 쓰지 않는 P2는 수정 확인했다. 그러나 첨부 두 개를 붙인 발췌문을 공백 제거하면 **원문 어느 곳에도 없는 `예비창업`이 새로 생긴다.** 그 가짜 1회가 발췌 밖의 실제 1회를 상쇄하여 서비스와 13단계가 옛 `blocked`를 유지하는 합성 입력을 재현했다. 현재 DB에서 같은 오판이 발생했다는 뜻은 아니다.

## 지적 사항

### P1. 첨부 경계에서 생긴 가짜 언급이 읽지 않은 언급을 가린다

[build_document()](../../../collect/extract_conditions.py)는 첨부별 발췌 조각을 `\n\n`으로 합친다(465행). [unread_pre_founder()](../../../search/applicant_types.py)는 발췌 전체의 모든 공백을 없앤 뒤 `예비창업` 횟수를 센다(198~220행). 따라서 첫 첨부의 끝이 `예비`, 다음 첨부의 시작이 `창업`이면 원문 첨부 각각에는 이 말이 없는데 발췌에는 1회 있는 것으로 계산된다. 응답 문서의 “발췌 횟수는 원문보다 많을 수 없다”는 전제가 이 경계에서 성립하지 않는다.

아래 입력은 실제 `prepare()`·`load_auto()`·`type_rows()` 함수로 실행했다. `A` 2,100자는 본문 끝의 새 허용 문장을 2,000자 머리 제한 밖에 두기 위한 자리 채움이다. 길이가 같은 두 첨부는 입력 순서대로 붙는다.

```python
old = prepare({
    'notice_id': 'n1', 'title': 'test', 'target_text': '',
    'body': '예비창업자 신청 불가. ' + 'A' * 2100,
    'attachments': ['예비', '창업'],
})
new = prepare({
    'notice_id': 'n1', 'title': 'test', 'target_text': '',
    'body': old['body'] + ' 예비창업자도 신청 가능.',
    'attachments': ['예비', '창업'],
})
```

| 관찰 | 결과 |
|---|---|
| `old`와 `new`의 `document_sha256` | 같음. 새 허용 문장은 발췌 밖이다. |
| `new` 원문의 언급 | 2회: 읽은 “신청 불가”, 읽지 않은 “신청 가능”. 두 첨부 각각은 0회. |
| 공백을 없앤 `new['document']`의 언급 | 2회: 읽은 “신청 불가”와 첨부 경계의 가짜 `예비\n\n창업`. |
| `unread_pre_founder(new)` | `None` |
| 옛 strong `not_allowed` DB 행 + `load_auto(..., documents={'n1': new})` | `pre_founder('n1') == 'blocked'`, `unread_pre_founder == 0` |
| 같은 옛 결과 JSONL + `type_rows(path, {'n1': new})` | `pre_founder_verdict == 'blocked'` |

이는 **발췌 밖에 실제 허용 문장이 추가되고도 지문은 그대로인** A안 대상 사례다. 새 문장을 못 읽은 옛 강한 차단을 서비스가 계속 적용하고, 13단계도 그 결론을 DB에 올릴 수 있다. 실제 공고의 첨부 경계가 이 패턴인지, 현재 DB의 판정 3건에 영향이 있는지는 확인하지 않았다.

수정 시에는 출처가 다른 발췌 조각 사이에서 단어가 이어지지 않도록 **출처별로 읽은 언급을 세거나** 조각 경계 정보를 보존해야 한다. 위 합성 입력의 서비스·13단계 결론이 둘 다 확인 필요/NULL로 바뀌는 회귀 시험이 필요하다. 발췌문 자체에 비공백 구분자를 넣는 방식은 문서 지문과 재판정 범위에 영향을 주므로 그 영향도 확인해야 한다.
