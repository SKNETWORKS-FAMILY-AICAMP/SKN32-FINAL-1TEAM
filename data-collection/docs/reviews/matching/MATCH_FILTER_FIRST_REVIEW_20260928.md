# 정형 필터 선행 매칭 — Codex 검수 (2026-09-28)

대상: Claude의 [검수 요청](MATCH_FILTER_FIRST_REVIEW_REQUEST_20260928.md)과 현재 작업 트리의 `search/app.py`, `search/gate.py`, `search/hybrid.py`, 평가·테스트·흐름 문서 변경.

## 판정

**필터 통과 공고 안에서만 Chroma와 BM25를 검색하는 핵심 변경은 확인했다.** 지역·업종을 필터에 넣지 않았고, 업력·모집 상태·접수 마감은 확실한 미달일 때만 제외한다. 다만 아래 P2를 수정하고 빈 후보 회귀 테스트를 추가한 뒤 최종 승인하는 것이 좋다. EC2 배포 판단은 별도의 현장 검증이 필요하다.

### [P2] 필터 통과 0건이어도 먼저 임베딩을 생성함

- 위치: `search/app.py`의 `match()` 시작 부분(`qv = _encode(query)`)과 `if passed:` 분기.
- 기능정의서 R-3은 필터 통과 0건이면 빈 결과를 요구한다. 현재는 필터를 돌리기 전에 인코더를 호출한다. 모든 공고가 마감된 가짜 상태에서 `_encode`를 오류로 바꿔 독립 실행하니, 빈 배열 대신 `RuntimeError`가 반환됐다. 인코더가 정상이어도 필요 없는 모델 실행을 한다.
- `passed`를 만든 뒤, 0건이면 빈 결과를 구성해 곧바로 반환하고 그 밖의 경우에만 `_encode`와 검색을 실행해야 한다. 인코더 호출 횟수가 0인 빈 후보 회귀 테스트를 추가한다. `pipeline` 설명도 실제 실행 순서와 맞춘다.

### [P2] Chroma의 모든 질의 오류를 대량 벡터 조회로 전환함

- 위치: `search/app.py`의 `_dense_within()` `except Exception`.
- 현재 `ids` 인자 미지원뿐 아니라 타임아웃·색인 오류·응답 형식 오류도 같은 경로로 들어가, 필터 통과 공고 약 1,500~1,700건의 벡터를 요청마다 다시 읽는다. 실패 원인을 기록하지 않아 운영자가 버전 차이와 색인 장애를 구별하기 어렵다. 대체 조회도 실패하면 매칭 요청이 500이 된다.
- 호환성 예외를 구분하고, 그 밖의 오류는 원인을 로그/응답 상태에 남기며, EC2에서 실제 Chroma 버전·필터 질의·대체 조회의 시간과 결과를 확인해야 한다. 현재 로컬 Chroma 성공 사례만으로 EC2 경로를 검증한 것으로 볼 수 없다.

## 독립 확인과 한계

- 코드를 따라가면 `gate.prefilter()`가 전체 `STATE['rows']`에 먼저 적용되고, 통과 ID가 Chroma `query(ids=...)`와 BM25 `search(allowed=...)`에 전달된다. 결과 후보도 `allowed` 집합으로 한 번 더 제한한다.
- FastAPI가 없는 로컬 Python에서 최소 FastAPI 대역을 주입해 `FilterFirstTests` **11개를 독립 실행했고 모두 통과**했다. 같은 방식으로 `test_match_rules.py` 27개 중 26개가 통과했으며, HTTP `TestClient`가 필요한 1개는 대역이 없어 실행할 수 없었다. Claude의 전체 475개 통과 및 실 Chroma·DB 비교 수치는 이 환경에서 재현하지 못했다. 저장소 `.venv`의 Python 실행 경로도 깨져 있다.
- `gate.prefilter()`의 시작 전 공고 처리는 명시된 R-3 `applyEnd >= today`와 일치한다. 2026-09-28 로컬 정규화 스냅샷 1,734건 중 접수 시작일이 미래인 17건이 있으므로, 이들은 후보에 남되 `/api/eligibility`의 접수기간 판정은 `False`일 수 있다. 후보 화면에서 접수 시작일을 명확히 보여 주고, 시작일까지 필터하려면 기획서의 필터 계약을 먼저 바꿔야 한다.
- 기존 검색 품질 지표는 이전 후보 집합과 순서로 계산됐다. 동일한 평가 질의·판정·기준일을 고정해 변경 후 기준치를 새로 기록해야 한다. 과거 지표와 새 지표를 같은 실행 조건처럼 나란히 비교하지 않는다.

이번 검수는 `data-collection/`의 코드·문서·로컬 스냅샷만 읽었다. LLM·DB를 호출하거나 Git staging·commit·push를 하지 않았다.
