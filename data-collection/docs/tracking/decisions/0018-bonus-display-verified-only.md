# 0018. 가산점 화면 사용 허용 — 원문 대조된 공고만 · Codex 4차 지적 처리

- 날짜: 2026-10-08 · 결정: 사용자 · 상태: 시행 중(시험 서버 반영은 아래 "반영"), Codex 5차는 요청서만(보낼지는 사용자)

## 배경
Codex 4차(`docs/notice_api/CODEX_BONUS_RECHECK4_20261008.md`): P1 0건, 원문 대조 목록 10건·승인 항목 31개 배점 오류 없음, 0.2 운영 결정은 그대로. 남은 지적 P2 3(R4-P2-1 배점 없는 "*" 줄, R4-P2-2 목록 값 오류로 HTTP 500, R4-P2-3 첨부 글 변경 미감지)·P3 1(R4-P3-1 화면 문구). 사용자는 "이상하면 나중에 고치면 된다"며 4건 수정과 함께 가산점을 조율 쪽 화면에 쓰는 것을 이번에 허용했다.

## 결정
- **화면 사용 허용 — 원문 대조된 공고만.** 새 응답 칸 `bonus_verified`(참·거짓, 늘 있음, 추가만): 원문 대조를 마친 공고 목록에 있고, 내용 지문·가점 행 지문·**원문 지문**이 대조 당시와 같고, 지금 결과 항목이 모두 승인 항목 안이고, 가산점 > 0이면 참. 세기·검색 경로와 상관없다. 조율 쪽은 이 칸이 참인 공고만 "확인된 가산점 +N점(일부)" + "전체 가산점은 공고문 확인"으로 보여 주고(`bonus_items` 설명 사용 가능), 거짓이면(0·null 포함) 가산점에 대해 아무것도 보여 주지 않는다(사용자 결정 — "가산점 없음"이 "받을 가점이 없다"로 오해되는 것을 막음).
- 결정 0008·약속 문서의 "Codex 재검수 통과 뒤 화면 사용" 조건을 사용자가 이 조건으로 **대체**했다.
- `bonus_rank_applied`는 이제 `bonus_verified`가 참일 때만 참이 될 수 있다(뜻은 결정 0017 그대로 — 이번 순위 계산에 실제로 쓰였는가).
- 조율 담당 알림은 시험 서버 반영·확인 뒤 사용자가 보낸다(초안 `docs/notice_api/BONUS_NOTICE_DRAFT_20261007.md`).

## Codex 4차 지적 처리
- **R4-P2-2**: `load_reviewed`가 지문 세 개(비어 있지 않은 글자), 승인 항목 이름(비어 있지 않은 글자), 점수(참·거짓이 아닌 유한한 양수)를 검사하고 하나라도 어긋나면 목록 전체를 거부(순위 반영 0건, `boot_errors.bonus_reviewed`). 요청 처리 중 목록 판단 예외는 그 공고를 대조 안 된 것으로 보고 넘어간다(`app.bonus_verified`) — 검색이 500으로 멈추지 않는다.
- **R4-P2-3**: 원문 지문 `evidence_fingerprint` — 계산에 쓰는 원문 조각(본문·지원대상·지금 달린 추출 성공 첨부 글)을 줄바꿈 표기만 통일하고 정렬해 구분 글자로 이어 만든다(첨부 읽는 순서가 달라도 같음, 조각 경계가 달라도 같아지지 않음). found 행에만. 목록에 저장하고 비교한다. 첨부 글을 다시 뽑으면 그 공고는 다시 대조할 때까지 순위·대조됨에서 빠진다("다시 대조 필요"로 보임).
- **R4-P2-1**: 배점 없는 "*" 설명 줄은 앞줄에 자격 이름(`CERT_ALIASES`의 인증 이름·별칭, `KIND_WORDS`의 종류 말)이 없을 때만 붙인다. "벤처기업 가점 10점⏎* 여성기업 우대 안내"의 여성기업 10점은 모름, 127009 "혁신형 중소기업⏎1점⏎* 이노비즈, 메인비즈, 벤처기업"은 그대로.
- **R4-P3-1**: 시험 화면 — 대조된 공고는 "원문 대조됨" + "순위 반영됨 / 세기 0이라 순위 미반영 / 이번 검색에서는 순위 미반영", 대조 안 된 공고는 "원문 대조 전"만.
- 함께: `eval/bonus_conservative_compare.legacy_bonus`가 예전 파일에 `__file__`을 넣어 준다(예전 `bonus.py`가 자기 위치로 목록 경로를 만들어 실행이 멈추던 문제).
