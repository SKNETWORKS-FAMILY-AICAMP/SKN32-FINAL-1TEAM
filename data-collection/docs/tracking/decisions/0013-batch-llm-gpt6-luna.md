# 0013. 배치 AI 3단계(신청자 유형·업종·가점)를 gpt-6-luna로 바꾼다. 자격요건은 gpt-4o-mini 유지

- 날짜: 2026-10-07 · 결정: 사용자

## 배경
매일 배치의 AI 추출 4단계는 자격요건(10단계) gpt-4o-mini, 신청자 유형(11)·업종(12)·가점(14) gpt-5.6-luna(생각 강도 medium)였다. 9/30 팀 Agent용 모델 비교(`model-eval/`)에서 gpt-6-luna가 5.6과 품질은 대체로 같고 단가는 절반 이하(입력 $0.10 · 출력 $0.50 /100만 토큰)라는 결과가 있었지만 배치에는 반영되지 않았다. 사용자가 4단계 모두 6-luna로 바꾸고 싶다고 했고, 먼저 비용·문제점을 확인하기로 했다.

표본 비교(`reports/model_switch_6luna_20261007T073852Z/`, 단계별 40건, 같은 문서만, 모델만 바꿈):
- 가점: 상태·최종 가산점 40/40 같음
- 신청자 유형: 120칸 중 117칸 같음
- 업종: 허용 업종 대분류 39/40 같음
- 자격요건: 업력 40/40, 지원 금액 34/40(5건 있음 → 없음), 사업자 유형·예비창업자 26/40. 새 모델이 칸을 비우거나 근거 검사에서 버려지는 값이 많다. 출력 토큰이 5배라 비용도 거의 같다($1.43 → $1.51 추정)
- 전량 다시 뽑기 추정: 3단계 약 $3.87, 4단계 약 $5.37

## 결정
- 신청자 유형·업종·가점을 **gpt-6-luna, 생각 강도 medium**으로 바꾼다. 프롬프트·검사 규칙은 그대로다.
- **자격요건은 gpt-4o-mini를 유지한다.** 바꿔도 비용이 줄지 않고, 지원 금액(조율 창구 공고 상세에 나가는 값)이 비는 공고가 생긴다.
- 이미 뽑은 결과는 **한 번에 전량** 다시 뽑는다(2026-10-07, 배치 서버, 배치 서버 키). 직전에 공용 DB 백업과 배치 서버 판정 기록 파일 백업을 받는다.
- 업종 순위는 지금 파일(9/28 결과)을 그대로 쓴다. 새 업종 결과는 공용 DB에만 들어간다.
- 신청자 유형·업종 결과는 행마다 엔진을 적고, 엔진이 다르면 공고문이 같아도 다시 뽑는다(옛·새 결과가 섞이지 않게, 앞으로의 모델 변경에도 쓴다).
- 다른 팀원에게 따로 알리지 않는다(가산점은 시험 단계, 실제 연결 전).

## 대안
- **4단계 모두:** 모델 하나로 통일되지만 자격요건 결과가 많이 달라지고 비용 이득이 없다.
- **바꾸지 않음:** 지금 결과는 검수를 거쳤지만, 매일 배치 비용이 3단계에서 약 절반으로 줄어드는 이득을 버린다.
