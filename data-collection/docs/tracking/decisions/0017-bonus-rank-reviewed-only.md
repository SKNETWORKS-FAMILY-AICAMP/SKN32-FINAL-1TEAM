# 0017. 가산점 순위 반영 0.2를 켠다 — 원문 대조를 마친 공고만 · Codex 3차 지적 처리

- 날짜: 2026-10-08 · 결정: 사용자(A 방향) · 상태: 시행 중. Codex 4차 "추가 보완" → 결정 0018로 처리(원문 지문 추가, 목록 값 검사, 화면 사용 허용 — "표시는 시험 단계"는 0018이 대체)

## 배경
Codex 3차 검수(`docs/notice_api/CODEX_BONUS_RECHECK3_20261008.md`)도 "추가 수정 후 재검수 필요, 화면 표시·0.2 활성화 보류"였다(P1 3·P2 1). 모두 구성 입력이고, 지금 가산점이 붙는 10건에서는 Claude 대조와 Codex 7절 대조 모두 배점 오류를 찾지 못했다. 검수마다 입력 모양을 바꾼 새 우회 사례가 나오는 구조라, 사용자는 **확인된 공고만 순위에 쓰는 장치**로 위험을 근본적으로 막고 0.2를 지금 켜기로 했다(멘토 의견 "가산점도 중요").

## 결정
- **`Weights.bonus` 기본 0.2.** 계산식·큰 규칙(다른 시·도 등은 못 넘음)은 결정 0015와 같다.
- **원문 대조를 마친 공고 목록**(`search/bonus_reviewed.json`)에 있는 공고만 순위에 얹는다. 조건: 목록에 있고, 대조 당시와 공고 내용 지문(`content_version`)·가점 행 지문(`row_fingerprint`)이 같고, 지금 결과의 `bonus_items`가 모두 승인 항목(`approved_items`) 안. 아니면 그 공고는 가산점이 없는 것처럼 정렬한다. 목록 파일이 없거나 깨지면 목록 전체를 쓰지 않는다(순위 반영 0건, `boot_errors.bonus_reviewed`).
- **결정 0008·0015 조건의 대체**: "Codex 통과 전에는 쓰지 않는다(0008)", "Codex 검수 뒤 시행(0015)"을 **순위 반영에 한해** 사용자가 이 목록 조건으로 대체했다. 가산점 **표시**는 계속 시험 단계다(조율 쪽 "화면에는 쓰지 말아 달라" 유지).
- **목록 근거 표현**: "Claude 원문 대조(AI 참고)". Codex 3차 7절은 10건의 채택 항목에서 배점 오류를 찾지 못했지만 "승인 목록이 아니다"라고 했다 — "Codex 승인"이라고 쓰지 않는다.
- **목록 추가**: 사용자가 요청할 때만. Claude가 `-m eval.bonus_boostable`로 "새 후보"·"다시 대조 필요(목록 안인데 내용·가점 행이 바뀜 또는 승인 밖 항목 관측)"를 보고, 원문 대조 "맞음"만 `--write-reviewed`로 넣고(지문은 도구가 채움, 손으로 쓰지 않음) 무엇을 넣었는지 알린다. 서버 반영은 사용자가 명령으로. 발표 전 주 1~2회 요청 권장. 배치 서버는 바꾸지 않는다.
- **새 응답 칸** `bonus_rank_applied`(참·거짓, 늘 있음): 이 공고의 가산점이 이번 순위 계산에 실제로 쓰였으면 참. 세기 0·목록 밖·가산점 0·null·score 방식·마감임박순 대체 경로는 거짓. 기존 칸·값은 그대로(추가만). 시험 화면에 "순위 반영됨 / 원문 대조 전이라 순위 미반영".
- **조율 담당 알림**: 반영을 확인한 뒤 사용자가 한 번 보낸다(초안 `docs/notice_api/BONUS_NOTICE_DRAFT_20261007.md`). 목록 추가 때마다 알리지 않는다(처음 알림에 "목록은 수시로 늘어남").
- **Codex 4차 검수에서 지적이 나오면 그때 사용자가 정한다**(미리 자동 조치하지 않음).

## Codex 3차 지적 처리 (`search/bonus.py`, 더 엄격하게만)
- R3-P1-2: 같은 인증 증빙 예외(`same_cert_paper`)가 빼는 대상 말은 인증 코드·별칭·종류 말만(`cert_words`). AI가 지은 항목 이름 낱말은 확인된 자격이 아니다.
- R3-P1-3: 근거에 "및·&·+·그리고"가 있는데 같은 근거의 짝 항목이 **뽑히지 않았으면** 모름(짝이 있고 False면 결정 0016대로 "둘 중 하나").
- R3-P1-1: `load()`가 원문에서 근거 문장이 걸친 줄 경계를 항목에 남기고(`quote_lines`), 점수 주인 검사가 그 줄로도 나눈다. 표의 배점 칸만 있는 줄("1점", "최대 3점")과 "*" 설명 줄은 그 행의 앞줄에 붙인다 — 이것 없이 줄로만 나누면 117928·126830·127009의 맞는 점수까지 빠졌다(첫 시도 결과 8건). 쉼표로만 이어진 문장("여성기업 우대 안내, 벤처기업 가점 10점")은 이번에도 막지 못한다 — 알려진 한계이고 순위는 목록으로 막는다.
- R3-P2-1: `period_lines`가 각주(※·*) 줄을 이어진 줄(최대 2줄)과 합쳐 본다. 한 줄로 되면 그 줄만 낸다.
- `load()`가 found 행에 가점 행 지문(`row_fingerprint`, DB 원래 값 — 원문 확인 칸 덧붙이기 전)을 계산해 둔다.
