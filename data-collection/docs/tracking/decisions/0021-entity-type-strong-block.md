# 0021. 개인사업자·법인도 공고 본문 "불가"(강한 근거)면 뺀다

- 날짜: 2026-10-13 · 결정: 사용자("해 보고 결과 테스트") · 상태: 시행 중 — 시험 서버 반영(10/13 12:20)·조율 `SB-304` 계약 시험 16/16(`reports/notice_api_contract_20261013T032549Z/`), 조율 담당 알림은 사용자

## 배경
2026-09-28 결정(기획서 대조 G)은 공고 본문 신청자 유형 판정을 **예비창업자에게만** 썼다. 개인사업자·법인 판정도 매일 배치 11단계가 공고마다 뽑아 공용 DB `notice_applicant_types`에 있지만, "건수가 적고 적용 범위 주의"로 자격 확인 화면에 근거만 보여 줬다. 그래서 개인사업자에게 "국내 법인사업자" 전용 공고가, 법인에게 "소상공인(법인 제외)" 공고가 추천에 떴다.

1단계 계산(`reports/entity_block_probe_20261013T030233Z/`): 열린 공고 중 강한 불가 개인 11·법인 12건. 평가 정상 질의 58개를 개인사업자·법인으로 돌리면 상위 10에 각 1개 질의, 상위 20에 7·2개 질의(칸 7·3), 상위 3에는 0. 9/28 블라인드(AI 참고) 강한 불가 개인 7/7·법인 8/8 맞음. 효과는 작지만 방향이 맞고 OpenAI 비용이 없어(이미 뽑은 판정만 읽음) 사용자가 진행을 정했다.

## 결정
- 개인사업자·법인 신청자에게 그 유형의 공고 본문 판정이 **`not_allowed` · `strong` · `varies` 아님**이면 정형 필터에서 뺀다. 예비창업자 강한 불가와 같은 기준이다. 빼는 이유 이름은 `개인사업자 불가(공고 본문)`·`법인 불가(공고 본문)`.
- **발췌 밖 확인**도 예비창업자와 같게 한다 — 판정에 쓰지 않은 원문(공백 제거)에 그 유형 말이 발췌보다 많으면 확인 필요로 낮춰 빼지 않는다. 말: 개인 `개인사업`·`개인기업`, 법인 `법인`(넓게 — 낮추는 쪽이 안전). 원문을 확인할 수 없으면(지문 다름·원문 없음) 빼지 않는다.
- `가능`·`weak`·세부사업별(`varies`)은 쓰지 않는다. `가능`도 통과(True)로 올리지 않는다(통과로 두면 그만이고 따로 검증하지 않았다).
- 한 곳(`search/applicant_types.entity`)이 정하고 세 창구가 같이 쓴다: 추천 정형 필터(`app.eligible_with_types` — 신청자 유형 인자 추가), 자격 판정 `지원대상 유형` 줄(`type_check` → `eligibility.conditions`, 화면용·조율용), 공고 상세 `eligibility.applicant_types`(그 유형 줄이 미달이면 뺌).
- 예비창업자 쪽(빼기·되살리기·불가 추정 뒤로 보내기)은 그대로다. 뒤로 보내기는 예비창업자에게만(`use_pre`).
- 평가 도구(`eval/filter_first_eval.py`·`match_variants.py`·`bonus_rank_eval.py`·`vector_db_compare.py`)도 서비스와 같은 조건으로 판정표를 쓴다. `experiments/orchestration_probe.py`(9/29 직접 import 방식 비교)는 고치지 않았다.

## 대안
- 그대로 두기: 신청할 수 없는 공고가 개인·법인에게 계속 뜬다(상위 20 기준 드묾).
- 뒤로만 보내기(순위 신호): 근거가 강하고 블라인드 15/15라 빼는 쪽이 원칙("확실한 미달만 뺀다")과 맞다.
- 발췌 밖 확인을 좁은 말로(법인사업자·법인기업 등): 낮추는 공고가 0이 되지만 "법인인 경우 등기부등본" 같은 신호를 놓친다.

## 남는 한계
- 판정은 AI 참고(블라인드 표본 15건). 발췌 밖 확인의 '법인'은 서식 칸·기관 이름에도 걸려 빼야 할 공고 일부(지금 3건)를 확인 필요로 남긴다.
