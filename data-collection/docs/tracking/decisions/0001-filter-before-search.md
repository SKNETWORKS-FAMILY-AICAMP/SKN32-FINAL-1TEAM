# 0001. 정형 필터를 검색보다 먼저 건다

- 날짜: 2026-09-28 · 결정: 사용자(기획서 5-3·기능정의서 R-3 기준)

## 배경
예전 `/api/match`는 의미 검색 상위 후보를 먼저 자르고 마감만 거른 뒤, 모자라면 더 깊이 찾았다. 그 결과 상위 10건에 신청 불가 공고가 섞인 질의가 정상 질의 58개 중 21개(hybrid)였다. 기능정의서는 이 순서를 결함으로 본다.

## 결정
모든 공고에 정형 필터(모집 상태·접수 마감·업력/신청자 유형, 예비창업자면 공고 본문 판정)를 먼저 걸고, 통과한 공고 안에서만 Chroma(`ids=`)·BM25(`allowed=`)를 돌린다.

## 대안
- 검색 뒤 거르기(예전 방식): 신청 가능한 공고가 상위에서 사라지거나 하나도 안 남을 수 있다.
- SQL WHERE로 미리 거른 별도 DB에서 검색(실험 경로): 지역·업종까지 필터에 들어가 "지역·업종은 순위만" 원칙과 어긋났고, 서비스 코드와 따로 놀았다.

## 결과
- 신청 불가@10 4.8% → 0.0%. P@3(2) 하한 62.6% → 60.3%(차이 구간이 0 포함) — "내용은 맞지만 신청할 수 없는 공고"가 빠진 몫이다.
- 매 요청이 메모리의 모든 공고를 한 번 훑는다. 공고 수가 크게 늘면 이 비용이 커진다.
- 정형 필터에 넣는 조건은 "확실한 미달만"이어야 한다. 모르는 값으로 빼는 조건을 넣으면 검색 대상 자체가 사라진다.
