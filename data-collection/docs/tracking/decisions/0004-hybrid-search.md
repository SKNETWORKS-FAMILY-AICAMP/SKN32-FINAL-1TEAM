# 0004. 의미 검색과 단어 검색(BM25)을 RRF로 합치고, 리랭커는 서비스에 붙이지 않는다

- 날짜: 2026-09-17(하이브리드 적용) · 결정: 사용자

## 배경
의미 검색만으로는 공고 고유 단어(사업명·업종명)가 들어간 질의에서 엉뚱한 공고가 올라왔다. 리랭커(크로스인코더, LoRA 학습)는 정확도를 더 올릴 수 있지만 팀 EC2 4GB에 BGE-M3(피크 약 2.7GB)와 함께 올리기 어렵고 GPU가 없으면 느리다.

## 결정
기본 검색은 BGE-M3 의미 검색 + BM25를 RRF(k=60, 1:1)로 합친다. 학습한 리랭커는 ML 제출물과 시연 화면(`/demo`)에만 두고 서비스 경로에 넣지 않는다.

## 대안
- 의미 검색 단독(`search='dense'`): 비교용으로 남겼다.
- 리랭커 서비스 연결: 메모리·지연 문제. 양자화·별도 서버·후보 축소가 선택지이며 GPU가 생기면 다시 본다.

## 결과
- 서버를 켤 때 BM25 색인을 메모리에 만든다(배치 뒤 재시작이 필요한 이유 중 하나).
- 두 검색 중 하나가 죽어도 다른 하나로 답할 수 있다(대체 경로의 바탕).
- 표시 점수(`score`)는 코사인, 순위는 RRF라 둘의 순서가 다를 수 있다.
