## 남은 일 (순서대로)

1. 실제 연결 전 시험 서버(팀 EC2 `http://43.201.90.238:8000`, 10/6부터 상시 실행·매일 09:20 재시작, 답변서로 주소 전달 10/7)의 8000 포트를 부르는 곳 IP로만 제한한다 — 지금은 시험 기간이라 전체 공개.
2. 가산점: 조율 담당에게 뜻 변경(확인된 부분합) 알림 → Codex 재재검수 → 통과하면 "화면에 써도 됨" 알림. 점수가 나오는 공고가 적다(10/8 신청자마다 8곳) — 늘리는 방법 가운데 "뜻을 바꾸지 않는 추가 조건 허용"은 10/8 반영(결정 0014). 업종·수출 항목 채점, 떨어진 표 칸 배점 인정, 가점 재추출은 하지 않음(근거 안의 표 "배점" 칸 숫자는 10/8 결정 0019로 인정 — 목록 21건). 순위 반영은 Codex 검수 통과 뒤 세기 0.2로 올리기로 함(결정 0015, 대기 — 켜는 절차는 결정 문서에). 10/8 재재검수는 "보류"(P1 5·P2 2) → 결정 0016으로 처리(가산점 관측 공고 11 → 10건) → 3차도 "보류" → **결정 0017로 0.2 시행 — 원문 대조를 마친 공고 목록에 있는 공고만**(새 칸 `bonus_rank_applied`, 목록 추가는 요청 시). 4차 요청서 `docs/notice_api/CODEX_BONUS_RECHECK4_REQUEST_20261008.md` → 4차 "추가 보완"(P1 0) → **결정 0018: 원문 대조된 공고(`bonus_verified`)만 화면 사용 허용**, 5차 요청서 `docs/notice_api/CODEX_BONUS_RECHECK5_REQUEST_20261008.md`(보낼지는 사용자) → **결정 0019: 표 "배점" 칸 숫자 인정, 원문 대조 목록 21건**, 6차 요청서 `docs/notice_api/CODEX_BONUS_RECHECK6_REQUEST_20261008.md` → 6차 "목록 통과, 일반 계산 P2 2" → **결정 0020: 계산 완화(R1~R5)·6차 P2 조이기, 목록 27건**, 7차 요청서 `docs/notice_api/CODEX_BONUS_RECHECK7_REQUEST_20261008.md`(보낼지는 사용자).
3. 공고 서버 배포 위치 결정(요청서: AWS 내부망) → 배포 → 인증·요청 기록 정책 결정 → 서버 메모리 확인(약 2GB, 4GB 서버면 증설 필요). 함께 정할 것: 매일 배치 뒤 서버 다시 켜기(안 켜면 하루 뒤 수집 상태 "지연" → 조율 쪽 추천 멈춤)와 동시 호출 안전성 확인. (시험 서버는 팀 EC2에서 매일 09:10 색인 갱신·09:20 재시작으로 돌고, 재시작 중 약 10초 응답 불가.)
