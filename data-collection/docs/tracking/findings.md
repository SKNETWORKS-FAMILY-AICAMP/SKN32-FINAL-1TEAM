# 아직 못 푼 문제

## 실행 안내 문서의 DB 초기화 명령이 실제 옵션과 다르다

- 증상: `README.md` "시작하기"는 `python -m shared.store_mysql --init-schema`라고 하지만, 실제 명령은 정규화 파일 경로를 받는 `python -m shared.store_mysql <파일> --init-db`다. 그대로 따라 하면 인자 오류로 끝난다.
- 영향: 새 환경에서 DB를 처음 만들 때 막힌다(팀 공용 DB에는 영향 없음).
- 지금 못 푸는 이유: 이번 정리는 새 문서 작성 범위였고 `README.md` 본문은 고치지 않았다.
- 가능한 방법: `README.md`의 해당 줄을 실제 명령으로 고친다.

## `.env.example`에 `OPENAI_API_KEY`가 없다

- 증상: 배치 10~14단계가 `OPENAI_API_KEY`를 읽는데 예시 파일에 이름이 없다. 키가 없으면 LLM 단계는 조용히 건너뛰고 종료 코드 4만 남는다.
- 영향: 새 환경(학원 계정 서버 등)에 옮길 때 판정표·가점이 갱신되지 않는 것을 늦게 알아챈다.
- 지금 못 푸는 이유: 코드·설정 파일 수정은 이번 범위 밖이었다.
- 가능한 방법: `.env.example`에 `OPENAI_API_KEY=`와 "개인 결제 계정, 배치 LLM 단계용" 설명을 더한다.

## `shared/config.py` 머리말의 `.env` 위치 설명이 코드와 다르다

- 증상: 머리말은 `poc/.env`·`finak_mok/.env`를 찾는다고 하지만, 코드는 `shared/.env` → `data-collection/.env` 순서로 찾는다.
- 영향: `.env`를 엉뚱한 곳에 두고 "환경변수가 없습니다"를 만난다.
- 지금 못 푸는 이유: 이번 범위는 문서였다.
- 가능한 방법: 머리말을 실제 두 경로로 고친다.

## data-collection 시험이 CI에서 돌지 않는다

- 증상: 저장소 CI(`.github/workflows/ci.yml`)는 PR 제목과 `web/backend`만 검사한다. data-collection의 시험(10/7 기준 884개)은 로컬에서만 돈다.
- 영향: 시험이 깨진 코드가 PR로 들어가도 막히지 않는다. 조율 쪽은 우리 브랜치를 머지해 쓴다.
- 지금 못 푸는 이유: CI 파일은 저장소 공용이라 팀 합의가 필요하다. 시험 일부는 `.venv`의 무거운 패키지(chromadb·sentence-transformers)를 필요로 할 수 있어 CI 시간·용량을 따져 봐야 한다.
- 가능한 방법: data-collection 시험만 도는 작업을 추가하되, 무거운 패키지가 필요한 시험은 건너뛰게 한다.

## 가산점 남은 양수의 정확도를 사람이 확인하지 않았다

- 증상: 10/7 오후 규칙(애매하면 모두 null)에서도 열린 공고 4곳(117928·120481·122147·126642)은 가산점이 나온다. 규칙이 막지 못하는 경로가 남아 있을 수 있다. 예를 들어 근거가 원문에 그대로 있고 "N점"도 하나뿐인데 다른 항목의 배점이거나, 묶음이 다르고 근거도 다른데 실제로는 택1인 경우다.
- 영향: 조율 쪽이 화면에 쓰면 틀린 점수가 보일 수 있다. 지금은 "화면에 쓰지 말라"고 해 두었다.
- 지금 못 푸는 이유: Codex 재재검수(`docs/notice_api/CODEX_BONUS_RECHECK2_REQUEST_20261007.md`)가 아직 나오지 않았다. 사람 정답(원문 대조)도 없다.
- 가능한 방법: 재검수 결과를 받는다. 남은 양수 공고 4곳은 원문과 직접 대조한다. 그래도 남는 경로가 있으면 `bonus_score`를 모두 null로 내는 방안(결정 0012의 대안)을 다시 검토한다.
