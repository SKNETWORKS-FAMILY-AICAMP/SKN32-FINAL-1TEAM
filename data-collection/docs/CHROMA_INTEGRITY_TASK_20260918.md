## 목적과 현재 상태

임베딩 단독·하이브리드 비교에서 남은 **실제 Chroma 벡터의 내용 정합성**을 확인한다.
DB 공고 → NPZ의 입력 해시 → Chroma의 실제 벡터가 연결되는지 읽기 전용으로 검증하고,
불일치하거나 검증하지 못하면 향후 비교 실행이 정상 진행되지 않도록 보완한다.

- [검색 비교 리뷰](SEARCH_COMPARISON_REVIEW_20260918.md)의 **후속 확인 2**까지 읽는다.
  날짜 혼합 결과 정상 발행 문제는 해결됐고, 신규 테스트 7개·추가 경계 조건 4개가 통과했다.
- 현재 `eval/search_comparison.py::data_check()`는 DB와 NPZ 입력 해시, BM25 토큰 집계를 대조하지만
  Chroma는 ID만 조회하고 `chroma_content_verified: false`로 기록한다.
- 최신 사례 비교는 `reports/search_comparison_20260918T054314Z/`다.
  이 실행 당시의 Chroma 내용은 미검증이며, 이번 검사로 과거의 검증 상태를 소급 변경하지 않는다.

## 이번에 할 일과 범위

1. 실제 Chroma↔NPZ 검사 함수를 구현하고 기존 정합성 검사·실패 처리와 연결한다.
2. 검색 없이 검사만 수행하는 진입점을 제공한다. 예: `eval/search_comparison.py --check-only`.
   이름은 구현에 맞게 정하되 실행 명령을 문서에 남긴다.
3. 관련 테스트를 실행하고, 현재 로컬 데이터로 읽기 전용 검사만 실제 수행한다.
4. 검사 결과를 새 파일에 저장하고 STATUS·WORKLOG로 인계한다.

**실제 데이터는 읽기만 한다.** 코드·테스트·새 검사 보고서는 수정·작성할 수 있다.
DB 갱신, Chroma add/upsert/delete/컬렉션 생성·재생성, NPZ 덮어쓰기, 임베딩 생성,
수집 배치, 모델 다운로드·추론, 유료 LLM 호출은 하지 않는다.
BM25를 검증용 메모리에 구성하는 것은 가능하다.
검색 40건 재실행, 가중치·서비스 랭킹 변경, qrels·사람 판정 수정도 이번 범위에 포함하지 않는다.
기존 결과 폴더는 보존한다. **Git 스테이징·커밋·push는 사용자가 직접 한다.**

현재 `app.boot()`는 워밍업 경로가 있으므로 검사 전용 실행에서 무심코 호출하지 않는다.
필요한 컬렉션·공고·BM25만 준비하도록 검사 경로를 분리하거나 기존 읽기 함수를 재사용한다.
큰 서비스 구조 변경으로 확대하지 않는다. 색인이 없으면 새로 만들지 말고 확인 실패로 보고한다.

## 검사 요구사항

### 1. 실제 벡터와 공고 ID 대조

- 서비스가 사용하는 로컬 컬렉션을 열고 `get(include=['embeddings'])`로 실제 벡터를 읽는다.
  필요하면 배치로 나눠 읽되 **공고 전체**를 검사한다. 공고 ID로 대응시키고 반환 순서에 의존하지 않는다.
- 관리용 `__watermark__`는 명시적으로 제외한다. 나머지는 DB·NPZ·Chroma의 ID 집합을 비교한다.
  추가·누락 ID, 중복 ID, ID와 벡터 배열 길이 불일치를 조용히 버리거나 덮어쓰지 않는다.
- 벡터 누락, 차원 불일치, NaN/Inf 등 비정상 값은 정상 일치로 처리하지 않는다.
- NPZ 입력 해시와 현재 DB 입력의 일치를 기존 검사로 확인한 뒤,
  같은 ID의 NPZ 벡터와 Chroma 벡터를 원소 단위로 대조한다.
  서로 다른 벡터가 통과할 수 있으므로 코사인 유사도 하나만으로 일치 판정하지 않는다.
- 수치 비교의 dtype, 절대/상대 허용 오차와 이유를 명시한다.
  허용 오차는 판정 전에 정하고, 실제 실패를 통과시키려고 넓히지 않는다.
  불일치 공고 수·대표 ID·최대 절대 차이를 기록한다.

### 2. 모델·입력 계약 및 검사 시점

- Chroma 컬렉션 자체의 `metadata['embed_meta']`, NPZ의 `meta`, 현재 로컬 임베딩 설정을 대조한다.
  모델명·리비전·입력 버전·토큰 상한·차원·정규화 설정 등 의미에 영향을 주는 필드를 확인한다.
- 메타데이터가 없거나 해석할 수 없으면 확인 실패로 구분한다.
  `vecstore.stat()`은 Chroma 메타데이터가 없을 때 NPZ 값으로 대체할 수 있으므로,
  이 대체 값을 실제 Chroma 메타데이터라고 보고하지 않는다.
- 검증 중 원본·NPZ·색인이 바뀐 정황이 있으면 한 시점의 일치로 결론 내리지 않는다.
  검사 시작/종료 시각과 재현 가능한 데이터 식별 정보를 남기고, 변경 감지 방식·한계도 기록한다.
  검사를 위해 운영 서버를 종료하거나 배치를 임의로 변경하지 않는다.

### 3. 결과 판정과 비교 실행 연결

- 상태를 `통과 / 불일치 / 확인 실패`로 구분한다. 빈 결과나 예외를 통과로 바꾸지 않는다.
- `chroma_content_verified`는 모든 공고 벡터의 필요한 검사가 끝난 경우에만 true로 기록한다.
  메타데이터 검증 결과도 별도로 기록하고, 전체 정합성 통과에 필요한 조건으로 포함한다.
- 불일치·확인 실패 시 `integrity_failures()`에 사유를 연결한다.
  기존 비교 경로는 검색·워밍업 전에 중단하고, 정상 비교표·사람 판정 양식을 만들지 않아야 한다.
  날짜 변경 시 종료코드 3인 기존 동작도 유지한다.
- 검사 전용 모드는 검색 없이 종료한다. 성공은 0, 정합성 불일치·확인 실패는 비정상 코드로 반환한다.
  실제 검사 실패도 원인·대표 ID·검증 범위를 새 보고서에 남긴다. 자동 복구나 색인 재생성은 하지 않는다.

## 필요한 테스트

외부 DB·모델을 호출하지 않는 가상 데이터로 다음을 확인한다.

- ID 반환 순서가 달라도 동일한 벡터면 통과.
- ID는 같지만 Chroma 벡터만 바뀌면 실패. 허용 오차 이내/초과도 구분.
- 공고 추가·누락·중복, 벡터 없음·차원 오류·NaN/Inf, 배열 길이 불일치 검출.
- 컬렉션 메타데이터 불일치·누락·파싱 실패, Chroma 조회 실패를 확인 실패 또는 불일치로 처리.
- 검사 전용 모드에서 모델 인코딩·검색·DB 및 색인 변경 함수를 호출하지 않음.
- 검증 실패 시 비교 실행이 검색 전에 중단됨. 기존 날짜 무효 처리·정상 저장 회귀 테스트 유지.

실제로 확인 가능한 환경이면 현재 로컬 DB·NPZ·Chroma의 검사 전용 모드를 실행한다.
접근 문제나 데이터 부족으로 불가능하면 장애와 미검증 범위를 기록한다. 테스트 통과를 실제 데이터 일치로 대신하지 않는다.

## 결과물과 완료 기준

검사 실행마다 새 `reports/chroma_integrity_<실행시각>/`에 아래 결과를 남긴다.

- `integrity.json`: 상태, 시작/종료 시각, Git 리비전·관련 로컬 코드 해시,
  컬렉션 식별 정보, 공고 수, ID·내용 검사 결과, 수치 오차 기준과 측정값,
  메타데이터 원본/대조 결과, DB 입력 집합·NPZ·조회 벡터 집합의 식별 해시.
  벡터 집합 해시는 ID 정렬·dtype·바이트 순서 등 계산 방법도 기록한다.
  해시의 바이트 일치와 허용 오차 기반 벡터 일치는 구분한다. 비밀정보는 기록하지 않는다.
- `summary.md`: 무엇을 검증했는지, 통과·불일치·확인 실패 여부, 불일치 대표 사례,
  실행 명령·테스트 결과·남은 한계를 사람이 읽을 수 있게 요약한다.
- STATUS·WORKLOG: 변경 파일·검증 근거·결과 폴더를 연결하고 Codex 재검토 대상으로 남긴다.
  실행 방법이 추가되면 해당 평가 안내도 최소한으로 갱신한다.

검사 도구·중단 동작·관련 테스트가 준비되고, 실제 실행의 성공 여부와 근거가 보고되면 인계한다.
실데이터가 어긋나면 원인을 보고하는 것이 이번 작업의 결과다. 통과시키기 위한 데이터 수정은 하지 않는다.
현재 검사 통과는 과거 `054314Z` 실행 당시의 정합성 증명이 아니며, 검색 품질 향상의 증명도 아니다.
