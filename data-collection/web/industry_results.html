업종 추출 결과

LLM 이 공고마다 "어떤 업종만 신청할 수 있나"를 읽은 결과입니다. 결과 파일만 읽고 아무것도 저장하지 않습니다. 검증 화면 · 방식 비교 · 업종 강조 실험

  • 참고용입니다. 이 값은 DB 에 넣지 않았고 공고 탈락 필터로 쓰지 않습니다.
  • 품질은 30건 표본을 Codex 가 판정한 것과 비교해 짐작한 수준입니다(사람 정답 아님). luna(medium)는 표본 30건 중 24건이 Codex 와 같았고, 없는 업종을 지어낸 것은 0건이었습니다.
  • 검사가 내림은 LLM 은 업종이 있다고 했지만 근거 검사에서 확인 불가로 바꾼 공고입니다. 이 중 일부는 LLM 이 맞았습니다 — 눈으로 확인해 볼 만한 곳입니다.
  • 매칭용 판정: 업종 제한 있음 · 제한 없음(언급 없음·추정) — 신청 자격 문장은 찾았는데 업종 얘기가 없는 공고(대부분의 지원사업) · 제외 업종만 — 그 업종만 빼면 누구나 · 제한 없음(명시) · 조건부·세부사업별 — 통합공고나 "중점기업이면 전 업종" 같은 분기가 섞인 공고 · 확인 필요 — 검사가 내렸거나, 자격 문장을 못 찾았거나, 업종 후보가 있었지만 검사를 통과하지 못한 공고. "언급 없음"은 추정이라 명시된 제한 없음과 따로 둡니다. 발췌가 6,000자에서 잘렸던 97건은 18,000자로 다시 읽었습니다.
  • 검사 강도: 엄격은 근거 문장이 원문과 글자 그대로 같고 자격 머리말 아래 있어야 합니다. 러프는 공백·글머리표 차이를 무시하고, 지원 내용·제외 목록으로 확실한 것만 떨어뜨립니다. 두 결과 모두 같은 LLM 답을 다시 검사한 것입니다(추가 비용 없음). 결과 폴더에서 골라 보세요.
  • 업종 이름은 공고 원문 표현 그대로입니다. 초록 표시는 원문이 12개 표준 이름(제조업·건설업 …)과 같은 경우입니다.
  • 큰 묶음은 원문 표현을 한국표준산업분류(KSIC) 대분류로 규칙에 따라 묶은 것입니다(industry_groups.py). 이름이 헷갈리는 것 — 정보통신공사업·전기공사업은 건설업(F), 의료기기는 제조(C), 여행사는 사업지원(N) — 은 공식 분류를 따랐습니다. 바이오·AI·주력산업처럼 표준 업종이 아닌 표현은 "분야·정책 범주"로 따로 둡니다. 규칙 정확도는 재지 않았습니다.
