# data-collection 공통 작업 규칙

이 문서는 이 폴더를 작업하는 Claude, Codex 및 다른 AI가 함께 따르는 기준이다.
목표는 사용자가 코드의 흐름, 변경 이유, 검증 여부를 이해하고 다음 작업자가 이어받을 수 있게 하는 것이다.
현재 사용자의 명시적 지시를 우선하며, 규칙을 바꿀 때는 그 이유를 작업 기록에 남긴다.

## 담당 범위와 Git

- 기본 작업 범위는 `data-collection/`이다. 다른 영역은 사용자 요청에 필요한 경우에만 다룬다.
- **Git 커밋과 push는 반드시 사용자가 직접 한다. AI는 실행하지 않는다.**
- 사용자가 별도로 요청하지 않으면 스테이징(`git add`)도 하지 않는다. 상태·차이·이력 조회는 가능하다.
- 기존 수정, 스테이징, 미추적 파일을 자신의 작업으로 간주하지 않는다. 임의로 되돌리거나 삭제하거나 덮어쓰지 않는다.

## 작업 시작

1. [현재 상태](docs/STATUS.md)와 [작업 이력](docs/WORKLOG.md)의 최근 항목을 읽는다.
2. [구조 안내](README.md), [기능 흐름](docs/FLOW.md) 중 작업과 관련된 부분과 실제 코드를 확인한다.
3. `git status --short -- data-collection` 등 읽기 전용 명령으로 기존 변경을 확인한다.
4. 사용자에게 이번 목적과 변경 범위를 짧게 설명한다.
5. 파일 수정·실험 등 실작업을 시작하면 `STATUS.md`의 진행 중 작업에 담당 AI, 목적, 수정 예정 파일, 다음 단계를 적는다.

문서의 과거 수치나 이전 AI의 보고를 이번 실행 결과처럼 쓰지 않는다.
문서와 코드가 다르면 현재 코드에서 확인한 사실과 미검증 사항을 구분해 기록한다.

## 작업 중

- 기능 단위로 작게 변경하고, 구조 정리와 기능 변경은 가능한 한 구분한다.
- 사용자가 요청하지 않은 과거 작업의 재실행·완료 처리를 하지 않는다. 예정 작업은 실행 허가가 아니다.
- 긴 작업은 의미 있는 단계가 끝날 때 `STATUS.md`를 갱신한다. 중단되면 실행 중인 명령·프로세스, 완료 범위, 남은 일, 재개 방법을 남긴다.
- 여러 AI가 동시에 일하면 진행 중 작업을 각각 별도 항목으로 기록한다. 다른 AI의 항목을 지우거나 완료로 바꾸지 않는다.
- 같은 코드나 문서를 수정해야 하면 쓰기 직전에 다시 읽고 자신의 변경만 반영한다. 충돌하는 작업은 먼저 조율한다.
- API 키, 비밀번호, 접속 문자열, 실제 신청자의 개인정보는 공용 문서에 적지 않는다.

## 작업 종료

1. 변경 범위에 맞게 검증한다. 실행한 명령·조건·결과를 기록하고, 실행하지 않은 것은 이유와 함께 명시한다.
2. `WORKLOG.md`의 기록 구역 맨 위에 작업 한 건을 추가한다. 과거 기록은 보존하고, 정정은 새 항목에서 이전 항목을 참조한다.
3. `STATUS.md`에서 자신의 작업 상태를 정리한다. 완료한 기록은 이력으로 연결하고, 미해결 문제와 다음 단계는 남긴다.
4. 기능 흐름이 바뀌면 `FLOW.md`, 실행 방법·구조가 바뀌면 `README.md` 등 해당 문서를 함께 수정한다.
5. 사용자에게 변경 내용, 검증 결과, 남은 문제와 이해해야 할 핵심을 짧게 전달한다. 커밋·push는 사용자에게 맡긴다.

단순 질문 응답은 매번 기록하지 않아도 된다. 코드·설정·문서 변경, 실험 결과, 중요한 결정과 인계 사항은 기록한다.
작업 이력에 대화 전문이나 전체 diff를 복사하지 말고, 이유와 확인 근거를 남긴다.

## 문서별 역할

| 문서 | 역할 | 갱신 방식 |
|---|---|---|
| [FLOW.md](docs/FLOW.md) | 현재 입력 → 처리 → 저장·출력의 연결 | 관련 기능이 바뀌면 수정 |
| [STATUS.md](docs/STATUS.md) | 현재 진행 상황·문제·다음 단계 | 최신 상태로 유지, 다른 AI의 진행 항목 보존 |
| [WORKLOG.md](docs/WORKLOG.md) | 변경 이유·전후 차이·검증 근거 | 작업마다 추가 |
| [HANDOFF.md](docs/HANDOFF.md) | 기존 인계 시점의 배경과 기록 | 과거 자료로 참고, 현재 상태로 단정하지 않음 |

## 검색 비교 작업 시 남길 조건

검색 비교를 요청받으면 질의·공고 데이터 기준, 모델·색인 상태, 기준 날짜, 후보 수와 Top-K,
검색 방식(`dense`/`hybrid`), RRF 가중치, 마감·지역·지원대상 처리 및 리랭커 사용 여부를 기록한다.
평가 정답의 버전과 사람/LLM 판정 여부, 미판정 비율도 구분한다.
검색 자체의 결과와 후처리 후 최종 노출 결과를 구분하고, 코사인 유사도를 정확도나 확률로 표현하지 않는다.

## 새 대화에서 읽기 시작하는 방법

도구마다 지침 파일을 읽는 범위가 다를 수 있다. 저장소 루트에서 시작하거나 자동으로 읽었는지 불확실하면 다음 지시로 시작한다.

> data-collection/AGENTS.md를 읽고, docs/STATUS.md와 최근 WORKLOG.md를 확인한 뒤 작업해줘. 커밋과 push는 내가 직접 한다.
