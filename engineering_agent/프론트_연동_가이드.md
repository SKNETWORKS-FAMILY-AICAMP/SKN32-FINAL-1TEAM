## 1. 실패 처리 — 웹의 "완전 실패" 화면과 연결됨

상세는 같은 폴더의 **`완전실패_예외처리.md`**에 있다. 웹 쪽 반영 상태는 이렇다.

| 웹 동작 | 조건 | 상태 |
|---|---|---|
| 진행 화면이 "프로토타입을 만들지 못했어요" 카드로 바뀜, [처음부터 다시 생성하기] | 생성 중 **예외 발생** → 서버 `status='failed'` | 완료 (SB-59 `GenerationFailed`) |
| 일시 오류면 자동 재개(최대 5회), 입력·운영 오류면 바로 실패 | 예외의 `error_kind` 속성 → 없으면 메시지 키워드 | 완료 (백엔드가 `error_kind` 우선 판정) |
| 다시 생성은 재작성 횟수에서 차감 안 함, 연속 2회 실패하면 버튼 대신 안내 | `rerun_type='regenerate'`, `regenerate_fail_streak/cap` | 완료 (SB-183) |
| 관리자 벨 알림 + [확인] | `generation_failure_alerts` | 완료 |

**agent가 할 일은 한 가지다.** 결과물을 못 만들었으면 **예외를 올린다.**
`ToolCallExhausted`(tools.llm이 재시도를 다 쓴 뒤 올림)는 `error_kind`를 이미 들고 있어서, 그대로 올리면 서버가 알맞게 분류한다.

- 품질 문제(게이트 위반, 점수 미달)는 예외가 **아니다.** `CheckResult(passed=False)`로 정상 반환한다. 이건 검증-2 → 사용자 재작성 흐름으로 간다.
- `failure_reason`에 앞 2000자가 저장되고 **관리자 화면에 그대로 뜬다.** 키, 프롬프트 원문, 사용자 입력 원문을 넣지 않는다.

**~~남은 작업 (R2)~~ → 2026-09-29 적용 완료.** `build_prototype_html`이
`tools.llm(..., parse=_parse_llm_files)`를 쓴다. 빈 응답·코드블록 0개면 `FormatError`를
올려 tools가 재시도하고, 소진되면 `ToolCallExhausted`로 완전 실패가 된다.
게이트 위반(E-B1-ENTRY/DEP/SANDBOX)은 그대로 `CheckResult(passed=False)` 정상 반환이다.
테스트: `tests/test_artifact_agents.py`, `tests/test_contract_tasks.py`.

## 2. 프로토타입(T-B1) — 웹이 화면에 띄우는 방식

프론트 코드: `front/src/features/workflow/ArtifactResult.jsx` (`useArtifactFile`, `SiteMock`), `FinalVerdict.jsx`

```
artifacts.executable_path (예: /uploads/<uuid>.html)
  → fetch로 Blob 받기 → URL.createObjectURL(blob)
  → <iframe src=blob:... sandbox="allow-scripts" style="width:1440px; height:3770px; transform:scale(...)">
```

그래서 결과 HTML은 아래 조건을 지켜야 화면에 제대로 뜬다.

| 조건 | 이유 |
|---|---|
| **파일 1개(`index.html`)에 CSS·JS를 전부 인라인** | blob URL이라 `./style.css`, `./app.js`, `./img/a.png` 같은 **상대경로가 전부 깨진다.** `asset_paths`는 비워 둔다 |
| **외부 CDN·폰트·이미지 URL 0개** | E-B1-DEP 게이트와 같은 규칙. 이미지는 인라인 SVG, CSS 도형, data URI로 |
| **`localStorage`/`sessionStorage`/`document.cookie` 쓰지 않기** | `allow-same-origin`이 없어서 origin이 opaque다. 접근하면 **예외가 나서 스크립트가 통째로 멈춘다.** 상태는 JS 변수(메모리)로 |
| **`alert`/`confirm`/`prompt` 쓰지 않기** | `allow-modals`가 없어서 무시된다. 화면 안 토스트나 모달로 대체 |
| **`<form>` 전송이나 페이지 이동으로 동작하지 않기** | `allow-forms`가 없어서 submit이 막힌다. 버튼 `onclick`과 `preventDefault`로 처리 |
| **데스크톱 폭 1440px 기준 레이아웃** | 프론트가 1440×3770 캔버스를 축소해서 보여준다. 세로가 이보다 길면 아래가 잘릴 수 있다 |
| `<html lang="ko">`, 명도 대비 4.5:1 | 검증-2 자동 검사 항목이다(목업 기준 `lang` 누락, 대비 미달이 감점 사례) |

`<!-- IMPLEMENTED_FEATURES: ... -->` 자기신고 마커는 웹 화면에 표시되지 않는다. 검증 쪽에서만 쓰니 형식은 자유다.

## 3. 인포그래픽(T-B2) — 반드시 이미지 파일

```
artifacts.infographic_path → Blob → blob.type이 image/* 가 아니면 "이미지가 아닌 파일" 에러, 미리보기 실패
```
(`useArtifactFile(path, { expect: 'image' })`)

- 저장 확장자를 **`.svg`**로 둔다. 서버 `/uploads`는 `FileResponse`라 확장자로 Content-Type을 정하고, `.svg`는 `image/svg+xml`이 된다.
- **알려진 버그:** 백엔드 더미 `run_implement_agent_retry`는 인포그래픽도 `.html`로 만든다(`artifact_kind` 무시). 이건 원래 구현 agent 담당이 고치기로 한 건이다(2차 요청서 참고). 실제 함수로 바꿀 때 `file_ext='.svg'`로 돌려주면 해결된다.
- SVG 안의 텍스트는 이미 `_esc`로 이스케이프하고 있다. **유지**한다. `<img>`로 띄우는 게 아니라 blob이라 스크립트는 안 돌지만, 깨진 마크업은 이미지 자체가 안 뜬다.
- 폰트는 SVG 안에서 외부 로드가 안 된다. 시스템 폰트 스택만 쓴다.

| agent (`sbrain.contracts`) | DB `artifacts.category` | 웹 재작성 항목 라벨 | retry `task_key` |

## 5. 백엔드 연결 지점 — 아직 더미

지금 웹 백엔드는 구현 agent를 **호출하지 않는다.**

| 흐름 | 위치 | 지금 | 붙일 것 |
|---|---|---|---|
| **첫 생성** (`POST /projects/{id}/prototype/start` → stage `prototype_building`) | `back/app/routers/projects.py` `_simulate_generation` | `sleep`하면서 진행률만 올림. 산출물은 시드로 채워짐 | 여기서 T-B1/T-B2 호출 → 파일 저장 → `Artifact` 행 생성 |
| **재작성** (`POST /projects/{id}/retry-task`, `implement_*`) | `back/app/agents.py` `run_implement_agent_retry(*, artifact_kind, project_description)` | 더미 HTML 바이트 반환 | 실제 T-B1/T-B2 호출 → `ImplementArtifactResult(file_bytes, file_ext)` |

**계약 (이미 정해짐):** `ImplementArtifactResult(file_bytes: bytes, file_ext: str)`

- 저장 위치(`UPLOAD_DIR`), 파일명(uuid), 버전 행 복제(`_clone_artifact_as_new_version`)는 **백엔드 책임**이다.
- agent의 `file_writer.save_files`로 저장한 경로를 넘기는 게 아니라 **바이트를 넘긴다.**
- 저장 뒤 실패하면 백엔드가 파일을 지우고, 재작성 횟수를 돌려준다(실패 환불).

**입력이 부족하다.** 백엔드에 요청해야 한다.
`run_implement_agent_retry`는 지금 `project_description`(아이템 설명 한 줄)만 받는다. 그런데 T-B1/T-B2는 이것들이 필요하다.

| agent 입력 | 웹에서 나오는 곳 |
|---|---|
| `category` | `artifacts.category` (매핑 필요) |
| `feature_list` | 계획서 기능 목록 (`business_plans` / `plan_canonical_data`) |
| `item_spec` (아이템명, 목표 고객 등) | 프로젝트 입력(`ProjectCreateRequest` → projects/companies) |
| `plan_doc` (섹션, 표) — T-B2 | `plan_sections`, 계획서 표 데이터 |
| `rework_input.issues` | 검증-2 미달 사유 `artifact_score_reasons.reason_text` (사용자가 고른 항목) |

→ 백엔드에 `run_implement_agent_retry`와 첫 생성 호출부가 위 값을 넘기도록 **시그니처 확장을 요청**해야 한다.
`TB1In`/`TB2In`을 그대로 만들어 넘기는 방식이 가장 깔끔하다. Orchestration(SB-86) 쪽에서 그 모델을 조립하는 함수가 있으면 그걸 쓴다.

## 6. 알고 있으면 좋은 것

- **다운로드 파일명:** 결과 화면에 `executable_path`, `infographic_path`의 마지막 조각(uuid 파일명)이 그대로 보인다. 사람이 읽을 이름이 필요하면 백엔드와 별도로 정해야 한다.
- **README:** 구현 agent가 만들지 않는다(G-04 몫, `CLAUDE.md` 컨벤션). `readme_path=None` 유지.
- **점수:** 구현 agent는 채점하지 않는다. `artifact_score`, `artifact_score_reasons`는 검증-2가 쓴다.
- **격리:** `verification_agent` import 금지 규칙은 웹 연동 후에도 그대로다. 백엔드가 두 agent를 각각 부른다.
- **시연 목업:** 실제 파일이 없으면 프론트는 `front/public/prototype-preview.html`(짐세일즈 AI 예시)을 띄운다. 연결 후에도 이 화면이 보이면 `executable_path`가 비었거나, 파일을 못 받은 것이다.
