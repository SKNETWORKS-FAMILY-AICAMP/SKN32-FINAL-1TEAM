# 정보 보존 검증기 v3 개선 결과와 다음 단계

작성일: 2026-09-22. 사용자 요청: “검증기 확실하게 개선 하자.” 한도 중단 후 코드·평가·무결성 검사를 재확인하여 마무리했다.

현재 데이터·분할·후속 작업 기준은 [최신 인수인계](다음세션_인수인계_수작업검증_재검토와_실험설계_20260922.md)와 [135쌍 실험 계획](원천풀_마무리와_135쌍_실험계획_20260922.md)에 맞췄다. 채택 135쌍의 검수 완료와 학습용 분할·내보내기 완료를 구분한다.

## 1. 완료한 작업

기존 오류 분석에서 확인한 관계 변경 미탐과 정상 윤문의 과잉 경고를 줄이는 별도 v3를 구현했다. **이번에 정한 한 차례 개선은 완료했으며, 자동 의미 판정기의 완성을 뜻하지 않는다.** v2 코드, 원천 정답, 생성 원본, 사람 판정, 채택 135쌍은 보존했다. 기존 검수 앱·최종 반영 파이프라인의 v2를 소급 교체하지 않았다.

| 파일 | 역할 |
| --- | --- |
| `scripts/information_validator_v3.py` | v2 핵심 검사를 계승하면서 주체·목적·내용어 및 작은 의미 차이 검사를 보완 |
| `scripts/validator_v3_relations.py` | 과제–상태, 대상–수량, 행위–시간·조건·부정, 행위 참여자·수단의 연결 검사 |
| `scripts/information_validator.py`, `scripts/semantic_layers.py` | v3 실행에 필요한 고정 v2 검사·형태소 분석 의존 코드 |
| `scripts/evaluate_information_validator_v3.py` | 동일 개발 자료와 채택 정상 자료에서 v2/v3 비교, 수정 전후 진단, 출처 해시 검사 |
| `scripts/test_information_validator_v3.py` | 의미 변화와 허용 표현 변화의 동작 점검 |
| `scripts/test_validator_v3_relations.py` | 관계 변경 및 정상 관계 표현의 회귀 점검 |
| `scripts/test_evaluate_information_validator_v3.py` | 평가 집계·자료 보호 검사 |
| `data/validator_v3/` | 행별 결과, 수정 진단, 집계 보고서, 재현용 manifest |

조사·서술어와 문장 내부 연결을 이용해 주체/대상 및 목적/수단을 비교한다. 복합어·제한된 동의 표현을 정규화하여 단순 어순 변경이나 풀어쓰기를 내용 추가로 취급하는 경고를 줄였다. 강도(`해소↔줄이기`), 행위 범위(`운영↔운행`, `방영↔편성`), 기능·기준 변화와 불능/단순 부정의 차이도 검사한다. 사례 ID로 정답을 지정하는 방식은 사용하지 않았다.

v2의 광범위한 `new_content`, `new_purpose`, `subject_relation`, `quantity_binding`은 새 검사로 재평가한다. 해당 과거 근거는 `observations`에 남기며, v3의 주요 경고는 `signals`로 구분한다. 경고 감소에는 이 재분류의 효과가 포함된다. **과거 근거를 모두 의미적으로 해소했다는 뜻은 아니다.**

## 2. 같은 자료에서 확인한 변화

| 비교 항목 | v2 | v3 |
| --- | ---: | ---: |
| 개발 오류 61건 중 탐지 | 51 | 61 |
| 개발 오류 미탐 | 10 | 0 |
| 개발 정상 23건 중 경고 | 1 | 0 |
| 사람 채택 정상 135쌍 중 경고 | 32 (23.7%) | 6 (4.4%) |
| 사람 의미 차이 메모 2건의 수정 전 경고 | 0 | 2 |
| 위 2건의 수정 후 경고 | 0 | 0 |

개발 84건은 조사 목록 98건에서 기존과 동일하게 문맥 의존 2건·라벨 매핑 대기 12건을 제외한 결과다. 라벨이나 제외 범위를 바꾸지 않았다. 기존 v2가 탐지한 오류 51건은 모두 계속 탐지하며, 관계·인과·조건의 기존 미탐 10건을 추가 탐지한다.

**개발에 사용한 자료를 다시 평가한 결과이므로 일반 성능 100% 또는 독립 시험 통과로 해석하지 않는다.** 135쌍은 정답 49문장의 반복 변형이고 개발 자료와 일부 중복된다. 두 평가를 합산하지 않으며, 정상 135쌍으로 오류 재현율을 계산하지 않는다. 별도의 미사용 문서·실제 서비스 오류 성능은 아직 측정하지 않았다.

정상 경고의 전이는 기존 32쌍 중 28쌍 해소·4쌍 유지, 새 경고 2쌍이다. 기존 경고 32쌍의 근거는 모두 `observations`로 보존되며 그중 28쌍은 주요 경고 없이 관측 기록만 남는다. 프롬프트별 경고는 P1 3→1/37, P2 17→3/37, P3 11→2/37, 최초 묶음 1→0/24다. 생성·자기검토가 독립적이지 않으므로 프롬프트 우열을 확정하지 않는다.

수정 이력 14건은 사람 의미 차이 메모 2건, 사람 표현 수정 2건, assistant 수정 제안 10건으로 구분한다. 수정 전 경고는 3→5건, 수정 후 경고는 3→2건이지만, **14건을 확정 의미 오류 14건으로 계산하지 않는다.** 사람 메모의 `해소→줄이기`, `운영→운행`은 수정 전 경고·수정 후 무경고로 구분된다. 의무 적용 범위, 추진/상태 추가, 운영 범위 제한 등 일부 assistant 수정은 여전히 전후를 구분하지 못한다. 표현 명확화도 포함되어 있어 이를 모두 미탐으로 확정할 수는 없다.

## 3. 남은 정상 경고와 사용 한계

| 최종 채택 사례 ID | v3 경고 | 남은 문제 |
| --- | --- | --- |
| `SENT-EV2025-08-01::P1_narrative` | purpose_binding | 대응 관계를 명시적 목적으로 풀어쓴 표현 정렬 |
| `SENT-EDU-01-01::P3_expanded` | argument_binding | 의견 수렴을 과정으로 풀어 쓸 때 목적어·행위 정렬 |
| `SENT-EV2025-03-01::P2_reorder` | purpose_binding | 이동한 버스 관련 구문이 목적 범위 추출에 섞임 |
| `SENT-KTV-01-01::P2_reorder` | purpose_binding | 어순 변경된 목적어가 목적 범위 추출에 섞임 |
| `SENT-KTV-06-02::P2_reorder` | purpose_binding | 병렬 절 사이 목적 적용 범위 정렬 |
| `SENT-KTV-09-01::P3_expanded` | purpose_binding | 소구력·수단 표현의 풀어쓰기 정렬 |

위 설명은 검사 근거를 살펴본 개발상 진단이다. 이 중 EV2025-03-01 P2와 KTV-09-01 P3는 v2 대비 새 경고다. 수정 전후 비교에서 새로 경고가 생긴 사례와 버전 간 새 경고 사례는 서로 다른 비교이므로 혼동하지 않는다. 사람 최종 채택은 유지하며 이 여섯 건 때문에 다시 전수 검수를 요청하지 않는다.

v3는 형태소·구문·어휘 규칙에 따른 보조 도구다. 임계치와 제한적 동의어 대응에는 새 의미 변화를 놓칠 가능성이 있다. 복잡한 병렬/중첩 절, 동일 행위가 반복되는 사건, 의무·계획·완료의 적용 범위, 문서 문맥이 필요한 시제는 충분히 해결되지 않았다. 개발 사례 외의 오류 재현율은 알 수 없다.

`flagged=true`는 근거 확인이 필요하다는 뜻이며 자동 탈락이 아니다. `flagged=false`도 의미 보존 확정이 아니다. 출력은 항상 `semantic_verdict="uncertain"`, `semantic_acceptance_enabled=false`다. 경고가 없을 때도 `routing="semantic_review_still_required"`로 표시한다. 기존 사람이 채택한 자료에 기계 경고를 소급 적용해 채택을 취소하지 않는다.

## 4. 재현과 검증

프로젝트 루트의 기존 가상환경에서 실행한다. 비교 평가를 재실행하면 `data/validator_v3/`의 평가 산출물을 갱신하며 고정 원본은 건드리지 않는다.

검증기 런타임에는 `kiwipiepy`가 필요하다. 비교 평가 스크립트는 고정 개발 자료뿐 아니라 이전 분석 manifest가 참조하는 출처 파일까지 확인한다. 이 재현 명령은 해당 출처를 갖춘 현재 작업 폴더를 기준으로 한다.

```powershell
.venv/Scripts/python.exe -X utf8 -m unittest discover -s scripts -p '*v3*.py'
.venv/Scripts/python.exe -X utf8 -m unittest discover -s scripts -p 'test_information_validator.py'
.venv/Scripts/python.exe -X utf8 scripts/evaluate_information_validator_v3.py
```

마무리 확인: **v3 관련 59개 + 기존 v2 17개 테스트 통과**. 평가 manifest의 원천·코드·출력 해시 41개가 현재 파일과 일치했다. 테스트는 동작·회귀 검사이며 독립 성능 평가가 아니다.

CLI 동작 확인에서도 수량 변경의 경고, 자동 의미 채택 비활성, 입력 보존과 동일 입출력 경로 거부를 확인했다. 이번 문서 정합화에서 테스트를 새로 수행한 것으로 합산하지 않는다.

새 쌍에 대한 배치 사용은 각 줄에 `reference_text`, `candidate_text` 문자열을 담은 JSONL을 준비한 뒤 실행한다.

```powershell
.venv/Scripts/python.exe -X utf8 scripts/information_validator_v3.py input.jsonl output.jsonl
```

출력은 원래 행에 `validation_v3`를 추가한다. 입력과 출력 경로는 달라야 한다. 출력 경로로 기존 원천·검수·채택 파일을 지정하지 않는다. 채택 135쌍은 기존 스키마이므로 위 CLI에 바로 넣지 않고 전용 비교 평가 스크립트를 사용한다.

상세 수치: [개발 비교 보고서](data/validator_v3/검증기_v3_개발비교.md), [기계 판독 보고서](data/validator_v3/report.json), [재현 manifest](data/validator_v3/manifest.json).

## 5. 다음 단계

이번 범위의 완료 기준인 전후 비교, 기존 핵심 오류 탐지 회귀 확인, 잔여 한계 기록, 원본·라벨 보존을 충족했다. 정상 여섯 쌍에 맞춰 규칙을 계속 추가하기보다 이 버전을 기록하고 **135쌍의 SFT 준비로 이동**한다.

1. 정답·문서·유사 문장 그룹을 점검한다. 동일 정답의 모든 프롬프트 변형과 연도 간 유사 문장을 같은 분할에 둔다.
2. 기존 기본안인 EDU+KTV 학습 90쌍 / EV2024+EV2025 내부 개발평가 45쌍을 중복 점검 후 별도 파일로 내보낸다. 135쌍 원본은 보존하고 분할 근거·출처·해시를 기록한다. 제목은 보존하되 첫 실험 입력은 본문 한 문장으로 준비한다.
3. 기반 모델·GPU·학습 설정을 확인하고, 입력 그대로 / 기준 모델 / 동일 기반 모델의 QLoRA SFT를 같은 조건으로 비교한다. 현재 모델 다운로드와 학습은 실행하지 않았다.
4. 모델 출력의 정보 보존·문체·가독성·불필요한 변경을 평가한다. v3는 근거를 제시하는 보조 지표로 사용하고 사람 판단이나 독립 오류 라벨을 대체하지 않는다. 새 수작업은 같은 채택 데이터 전수 재검수가 아니라 실제 비교 출력의 경고·버전 불일치·무경고 표본에 목적을 두고 설계한다.
5. 일반화 성능을 주장할 단계에서 새 문서/서비스 유사 입력을 별도 확보한다. 현재 개발 자료를 독립 골든셋이라고 부르거나 그 완성을 SFT 파일럿의 선행 조건으로 만들지 않는다.

현재 채택 데이터는 **135쌍 모두 `training_ready=false`, `split=unassigned`**다. 분할·내보내기·SFT는 다음 실행 단계이며 이 작업에서 완료한 것으로 보고하지 않는다.
