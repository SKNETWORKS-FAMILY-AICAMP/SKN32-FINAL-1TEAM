기존 72쌍에 마지막 63쌍의 사람 판정을 반영했다. 검수에서는 정보 유지와 문체 수정을 구분했고, 채택은 검수 당시 후보에 대한 판정이다. 수정 전 원시 생성의 오류까지 확정한 것은 아니다. 완료된 135쌍의 전수 재검수는 요청하지 않는다.

자기검토에서 6쌍을 수정했다: 운영 확대의 범위 한정, 교육 대상 수식 명확화, 이용 지원 행위 추가, 목적 적용 범위, 스토리텔링 강화의 강도, 방영을 편성으로 바꾸는 행위 변경. 이 중에는 표현 명확화도 있으므로 의미 오류 6건으로 확정하지 않는다.

v2 신호는 최초/자기검토 후 모두 13쌍(P1 0·P2 11·P3 2)이다. 오류율이나 프롬프트 순위가 아니다. 무신호 후보도 사람 검수에 포함했다. EV2024-01/05/07/08-01 및 EV2025-03-01의 P1 5쌍은 성과·달성 원인 문맥의 현재형 표현을 확인하도록 표시했다. 이 다섯 쌍도 최종 채택·정보 유지로 반영했으며 재검수하지 않는다.

사람 판정 저장 후 source hash·정답·최초 생성·판정 일치를 확인하고 같은 v2로 재검사하여 반영을 완료했다. 아래는 당시 사용한 반영 명령의 기록이며 다음 작업으로 재실행할 필요가 없다.


확정 출력: `data/sentence_pilot/accepted_pairs_20260922_pool.jsonl`, 실제 채택 135쌍. 이전 48쌍·72쌍 파일은 고정 출처이므로 보존한다.

[135쌍 오류 분석](135쌍_오류분석_20260922.md)과 `data/error_analysis/pool_20260922/`에 다음 네 분류를 정리했다.

1. 사람이 의미 차이를 명시한 수정·제외.
2. 의미 변경으로 확정하지 않은 문체·표현 수정.
3. assistant가 미리 수정한 후보와 그 근거(사람 오류 라벨 아님).
4. 사람이 채택했으나 v2 신호가 있는 정상 표현 및 문맥 의존 사례.

분류표에는 사례 ID, 원문/후보/수정본, 출처, 판정 주체, 유형, 근거, 문맥 필요 여부, 향후 활용을 기록했다. 과거 라벨을 조용히 바꾸거나 수정됐다는 이유만으로 changed 라벨을 만들지 않는다.

## 4. 검증기 v3 개선 완료

검수·반영에 사용한 **v2를 고정**하고 별도 v3에서 다음 문제를 보완했다. 복잡한 문맥·적용 범위 문제는 잔여 한계로 기록했다.

- 실제 추가·누락·강도·행위·조건·관계 변경을 놓치는 경우.
- 정상 어순 변경·조사 보충·목적 관계 풀어쓰기에 경고하는 경우.
- 본문만으로 판정하기 어려운 시제는 무리하게 정상/오류로 확정하지 않고 문맥 확인으로 분리하는 경우.

같은 개발 84건에서 오류 탐지는 51/61→61/61, 정상 경고는 1/23→0/23이었다. 최종 채택 정상 135쌍의 경고는 32→6쌍으로 줄었다. 기존 오류 탐지 51건의 손실은 없다. v3 관련 59개와 기존 v2 17개 테스트가 통과했다. 개선에 사용한 자료의 개발 결과이며 독립 성능이 아니다. 정상 135쌍으로 오류 재현율을 계산하지 않는다. 남은 정상 경고와 의무·상태 적용 범위 등의 한계는 [v3 결과 문서](검증기_v3_개선완료_20260922.md)를 따른다.

**완료 기준 충족:** 개선 대상·변경 근거·전후 오탐/미탐·남은 한계를 보고했고, 채택 데이터와 사람 라벨을 보존했으며, 기존 핵심 오류 탐지의 회귀를 확인했다. 검증기는 자동 합격·탈락 판정이 아닌 보조 검사로 사용한다. 잔여 한계 때문에 개선을 무기한 반복하지 않는다. 기존 재분류 제안 12건이나 독립 골든셋 완성을 SFT 진입의 필수 조건으로 추가하지 않는다.

## 5. 확정 135쌍의 SFT 역할·분할안

아래는 확정 135쌍의 **첫 파일럿 실행 기본안**이다. 실제 내보내기 전에 유사 문장 그룹을 점검하고 누수 가능성이 있으면 분할안을 조정한다. 현재 분할 파일을 생성하거나 학습을 시작한 것은 아니다.

| 역할 | 문서 그룹 | 쌍 | 고유 정답 |
| --- | --- | ---: | ---: |
| 학습 | EDU + KTV | 33 + 57 = 90 | 12 + 20 = 32 |
| 내부 개발 평가 | EV2024 + EV2025 | 27 + 18 = 45 | 10 + 7 = 17 |
| 독립 최종 시험 | 새 문서·실제 서비스 입력 | 미확보 | 미확보 |

EV2024와 EV2025를 서로 다른 분할에 두지 않는다. 미디어교육 접근성 개선 문장은 문자 유사도 약 0.962, 나눔버스 운영 확대 문장은 약 0.855로 연도 간 유사 문장이 확인됐다. 이는 SequenceMatcher의 단순 문자 유사도이며 의미 유사도 성능지표가 아니다. 다른 유형의 중복도 추가 확인한다.

같은 정답의 프롬프트 변형·수정 전후는 전부 같은 분할에 둔다. 개발 평가의 두 문서도 서로 유사하므로 독립 45표본으로 해석하지 않는다. 개별 쌍 결과뿐 아니라 고유 정답·문서군·프롬프트별 결과를 함께 낸다.

이 분할은 교육/정책 계획에서 성과 보고 문장으로 적용해 보는 제한적인 내부 비교다. 장르·문체 차이와 KTV 비중이 크다는 한계를 기록한다. 개발 평가를 보고 모델/프롬프트를 조정했다면 최종 시험이라고 부르지 않는다. 현재 135쌍 전체를 학습에 넣고 동일 135쌍으로 성능을 평가하지 않는다.

## 6. 학습·비교 실험의 기본안

연구 질문: **원천 기반 합성 데이터의 SFT가 기준 모델보다 목표 문체를 개선하면서 정보를 유지하는가?**

- 모델 방향: 기존 합의인 5~9B QLoRA SFT. 실제 모델·GPU·라이선스·학습 설정은 실행 준비 때 확인한다. 지금 모델 다운로드·비용 지출·학습을 실행하지 않는다.
- 첫 실험 입력: 본문 한 문장만 사용하는 안을 기본으로 한다. 제목은 분석·문맥 필요 여부 기록에 보존한다. 문맥 포함 비교는 첫 결과에서 필요성이 드러나면 별도 실험으로 추가한다.
- 비교 대상: 입력을 그대로 둔 결과(변경 없음 기준), 기준 모델의 동일 지시 출력, 같은 기반 모델을 SFT한 출력.
- 통제 조건: 출력 한 문장, 정보 추가·누락 금지, 같은 프롬프트·디코딩 설정. 모델·데이터 해시·학습 설정·실행 이력을 기록한다.
- 평가 축: 정보 보존(유지/변경/판단 보류), 목표 문체 적합성, 가독성, 불필요한 변경, 원문 유지 적절성. source target과 글자가 다르다는 이유만으로 실패 처리하지 않는다.
- 개발 평가 45개 입력 전체에 자동 비교·검증 신호를 기록한다. 검증기를 유일한 정답 판정기로 쓰지 않는다.
- 사람 비교는 첫 회 **25개 입력 × 기준/SFT 출력 2개 = 50개 출력**을 제안한다. 고유 정답 17개에서 각 1개 변형을 먼저 고르고, 나머지 8개는 수치·조건·긴 문장·문맥·검증 불일치 사례로 선정한다. 모델명을 가리고 같은 문맥 조건으로 비교하며, 대표 표본과 위험 표본의 결과를 구분한다.

25개 비교는 초기 실패 진단과 개선 여부 확인을 위한 제안이지 최종 품질 보장이 아니다. 현재 합성 데이터에는 '그대로 두는 것이 최선인 입력'을 별도로 설계한 평가군이 없으므로, 이 점의 성능은 추가 서비스 유사 평가 자료가 필요하다. 평가를 위해 사람 정답을 새로 만드는 것과 현재 학습 후보 전수 검수를 반복하는 것은 다른 작업이다.
