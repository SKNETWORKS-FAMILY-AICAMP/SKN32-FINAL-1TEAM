# 검증 1 결과 작성 스타일 가이드

- 검증 결과는 한국어로 간결하게 작성한다.
- `issues`는 재작성이나 계약 수정이 필요한 구체적 오류만 기록한다.
- `warnings`는 근거 보완, 제안값, 시험조건 미확정, 사용자 확인 필요 사항을 기록한다.
- 같은 원인과 경로의 메시지는 한 번만 기록한다.
- 확정 사실과 사업계획 제안을 문장 안에서 구분한다.
- 판단 근거가 없는 경우 임의로 확정하지 않고 확인 필요로 표시한다.
- 메시지에는 가능하면 사업계획서 항목 위치, 판정 원인, 필요한 조치를 함께 작성한다.
- `pass`, `warning`, `fail` 상태를 혼동하지 않는다. warning을 필수 오류처럼 표현하지 않는다.
- `fail`은 재작성 또는 조립 보류가 필요한 경우에만 사용하고, 표현 차이·제안값·시험조건 미확정은 warning으로 작성한다.
- 표·이미지·일정·예산 구조가 실제 결과에서 충족되면 상반된 의미 진단만으로 fail을 작성하지 않는다.
- `sourceRefs`, `evidence`, `originalFacts`가 없을 때는 사실을 보충해 만들지 말고 근거 확인 필요로 작성한다.
- 결과 JSON의 키 이름과 상태값은 계약을 유지하고, 사용자에게 표시되는 설명만 자연스러운 한국어로 작성한다.
- 같은 원인으로 여러 항목이 영향을 받으면 대표 원인과 영향 범위를 구분해 중복 메시지를 줄인다.
