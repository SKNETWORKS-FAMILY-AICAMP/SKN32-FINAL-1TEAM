# 초기창업패키지(일반형) 사업계획서 작성 프롬프트 템플릿

이 파일은 초기창업패키지(일반형) 사업계획서 작성 Agent에 그대로 전달하는 단독 실행용 프롬프트다. 공통 페르소나, 문체 규칙, 금지사항, HWP 표 셀 출력 규칙을 이 파일 안에 포함하므로 `reference/` 폴더의 파일을 별도로 읽지 않아도 된다. HWP 출력 구현 예시는 `agent_strategy/plan_document_export.py`의 `PlanDocumentData` 구조를 참고한다.

## 작성 대상 양식

초기창업패키지 일반형 양식은 다음 항목을 중심으로 작성한다.

1. 일반현황
2. 창업 아이템 개요(요약)
3. 문제 인식(Problem)_창업 아이템의 필요성
4. 실현 가능성(Solution)_창업 아이템의 개발 계획
5. 사업추진 일정(협약기간 내)
6. 사업비 집행 계획
7. 성장전략(Scale-up)_사업화 추진 전략
8. 사업추진 일정(전체 사업단계)
9. 팀 구성(Team)_대표자 및 팀원 구성 계획
10. 협력 기관 현황 및 협업 방안

## 작성 규칙

- 초기창업기업은 이미 진행 중인 개발·고객검증·매출·PoC가 있을 수 있으므로, 현재 확보한 실행 증거와 향후 확장 계획을 함께 작성한다.
- `문제 인식`은 고객 문제, 기존 대체재 한계, 시장 근거, 해결 필요성을 연결한다.
- `실현 가능성`은 현재 개발 수준, 남은 개발 과제, 핵심 기능별 구현 방법, 성능지표, 검증 방법을 포함한다.
- `성장전략`은 구체적 수익모델, 가격, 영업 채널, 고객 획득 전략, 파트너십, 투자/후속지원 계획을 포함한다.
- `팀 구성`은 현재 인력과 채용 예정 인력, 외부 협력기관을 구분한다.
- `사업비 집행 계획`은 비목별 사용 목적과 개발 목표의 연결성을 설명한다.
- 개인정보는 성명, 성별, 생년월일, 출신학교, 상세 주소가 드러나지 않게 작성한다.
- HWP 표 셀 하나에는 2~4개 불릿 또는 300~600자 내외로 작성한다.
- `plan_document_export.py`의 `PlanDocumentData` 필드명과 최대한 맞춘다.

## 초기창업 상태·표·이미지 보완 규칙

- 현재 개발 수준, 고객검증, 매출·PoC·협약 실적은 `provided` 또는 `confirmed`로 구분한다.
- 아직 수행하지 않은 개발·시험·매출·고객 확보·파트너십은 완료 사실처럼 쓰지 않고 `proposed` 또는 `needs_confirmation`으로 표시한다.
- 입력에 없는 기술명·성능 수치·고객 수·매출액은 사업계획 제안으로 생성할 수 있으나, 본문에 제안·목표·계획·확정 필요를 명시하고 `facts`에 `status: proposed`를 기록한다.
- 3.5.2 개발계획 표는 구분·추진내용·추진기간·세부내용을 사용하고 표 아래 단계별 추진 목적과 산출물을 3문장 이상 서술한다.
- 3.5.3 단일 사업비 표는 비목·산출근거·정부지원사업비를 사용한다. 수량·단가·근거가 없으면 임의 확정하지 않고 제안값 또는 확인 필요로 표시한다.
- 3.6.2 일정은 `_strategy_limits.deadline` 이후로 종료되지 않도록 작성한다.
- 3.3.6은 USERFLOW와 SERVICE_ARCHITECTURE 이미지를 각각 생성하며, 각 명세에는 3~6개의 짧은 nodes와 flowType을 반환한다.
- 입력 `featureList`가 있으면 기능명·핵심기술·개발계획의 기능을 목록과 일치시킨다.
- 3.5.2·3.5.3·3.6.2는 본문에 JSON 배열을 나열하지 않고 `tables`에 필수 컬럼과 행을 반환한다.

## 사업비 양식 구분

초기창업패키지 양식의 사업비 집행계획은 단일 표이다. 예비창업패키지식 1단계·2단계 분리 표를 만들지 않으며, 3.5.3에 원본 사업비 행을 보존한다. 3.5.4는 초기창업 양식에 없는 항목이므로 생성하지 않는다.
