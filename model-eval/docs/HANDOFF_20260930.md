- 목적: S-Brain Agent 7개에 어떤 모델을 쓸지 **한 Agent씩** 실측한다. 결국 하나씩 시험해 보는 수밖에 없다는 판단이다.
- 사용자 결정(9/30):
  - 기존 파일을 고치지 않고 **새 파일로** 한다(`model-eval/`).
  - GPT에 한정하지 않는다. **로컬 모델도** 후보다(집 PC RTX 3060, 이 PC는 GPU 없음·RAM 15.7GB).
  - Agent 순서는 Claude 추천을 따른다: 검증-1 → 조율(T-C1·C3) → 전략 → 작성 → 구현 → 검수.
  - **팀이 정한 것이 아니다.** 사용자가 자체적으로 시험하는 것이다.
  - **정정(9/30 저녁):** 처음 이 문서에 "기획서 v1.10의 Agent별 모델 배치(5-2절)가 저장소에 없다"고 적었으나 **틀렸다.** `data-collection/docs/specs/`에 기획서 v1.10(PDF)과 기능정의서 v1.9(xlsx)가 있다. 5-2절 배치 방침은 아래 표다.

| Agent | 요구 성능 | 팀 배치 방침(기획서 5-2) |
|---|---|---|
| 조율 | 의도 해석·작업 분해 정확도 | 추론 성능 우선 모델 |

- 수치유도("구체 수치를 강조해 달라")에서는 luna도 12건 중 4건에서 입력에 없는 수치를 만들었다(예: 500개·2년·34,500,000원, 3,600곳). gpt-4.1-mini는 12건 전부 지어냈다(호출당 1~9개).
- 지어낸 경력은 경력 정보가 없을 때도 luna 0건, mini 1건이었다.

**채점 기준을 결과를 본 뒤 고쳤다(모두 오탐 제거, 리포트에도 적음).** 전략: 낡은 자료 한계 문구에서 '참고'라는 단어만으로는 인정하지 않도록 좁힘(오히려 엄격해짐), 무관자료 한계 문구·근거 문장에 연도가 든 경우 인정. 작성: 요청받은 금액을 언급하며 반영하지 않겠다고 쓴 줄(요청·초과·반영하지·제외·넘는·불가·아닌·대신·자부담·별도·잔여)은 지원금 계획에서 제외, 문장에서 지원 몫(지원금·상한·이내)을 따로 밝힌 "총사업비 ○○원"은 제외, "지원금 ○원"·"자체 자금 ○원"처럼 조달원을 밝힌 금액은 항목 합에 더하지 않음(지원금 자체가 상한을 넘으면 초과), 관대 기준 추가, "가정·예시·추정"이라고 밝힌 수치와 월 단가 × 12개월은 지어낸 수치에서 제외, 값이 1 이하인 수치는 검사하지 않음(v4 표는 재채점해도 변화 없음). 고친 기준을 반영한 새 표가 위 숫자다. 검사 함수는 `tests/test_v6_hard.py`에서 오탐 사례를 재현한다. 알려진 잔여 결함: 월 단가가 우연히 항목 금액과 같으면(몰드아이 단가 2,500만 원 = mini의 개발비 2,500만 원) 그 항목이 합에서 빠져 초과액 표기가 틀리고(통과·실패 판정은 같음), "1천 5백만 원" 같은 띄어 쓴 한글 숫자는 1천 + 5백만으로 잘못 읽는다.

**한계.** 보통·나쁨 단계는 규칙으로 만든 것이라 사람이 느끼는 품질 차이와 다를 수 있다 — 사람 채점 도구(`human/rating_tool.html`, 12편, 이름 가린 채 별점)를 만들어 뒀다. 저장한 `ratings.json`을 `human/`에 넣고 `python -m v6_hard.human_tool score human/ratings.json reports/v6_gradient_20260930T171201`로 사람 점수와 모델 점수의 순위 상관·순서 일치를 낸다. **사용자는 도메인 지식이 얕아 직접 채점하지 않기로 했고(9/30), Codex에게 맡기기로 했다.** 지시서는 `docs/CODEX_RATING_TASK_20260930.md`, 꾸러미는 `human/codex_pack/`(12편 본문과 평가 기준만, 정답 없음). Codex가 `human/codex_pack/ratings.json`을 쓰고 `python -m v6_hard.human_tool check …`로 형식을 검사한 뒤, 같은 `score` 명령으로 비교한다(`score`는 Codex가 아니라 사용자나 Claude가 돌린다). 결과는 사람 정답이 아니라 **AI 참고 점수**이고, Codex도 OpenAI 계열이라 후보 모델과 성향이 닮았을 수 있다. 반복 3회·계획서 4편이라 작은 차이는 오차 범위. 전략·작성 사례는 한 사람이 쓴 함정 16개씩이다. 아이템·회사·수치는 모두 가상.

## 4. 알게 된 것 (측정 조건: 가상 계획서 4편·반복 3·기준 eval-2)

1. 순서 맞힘·원인 짚기는 네 후보가 같아서, **"얼마나 깊게 깎았는가"**가 실제 차이를 가른다.
2. **gpt-4.1-mini는 없는 섹션에도 점수를 준다**(시장성을 지워도 5~10점만 내림). 분량 절반은 4~7점만 내려 거의 못 알아챘고, 원본에 68.8/70점으로 후하다. 흔들림이 가장 작은 것은 온도 0 때문이며, 일관되게 후한 채점이라 장점으로 보기 어렵다.
3. luna는 섹션 삭제에 1~3점, 분량 절반에 20점 안팎을 준다. 반복 흔들림은 약 1점(만점 70의 1.4%)이다.
4. luna low는 분량 절반 판정이 계획서마다 11~25점으로 크게 달랐다. medium·high는 정확도가 같고(85%), high는 추론 토큰이 약 3배·시간이 30% 더 든다. **현재로서는 luna-medium이 가성비 후보**이나 오차 범위일 수 있다.
5. 추론 모델(luna)은 이 작업에서 거의 생각하지 않는다(평균 추론 토큰 low 47 · medium 97 · high 266). 그래서 luna 비용이 예상보다 훨씬 낮다. **작성·구현처럼 긴 작업에는 이 수치를 쓰면 안 된다.**

## 5. 한계 (결론을 과장하지 않기 위해)

- 계획서 4편이 모두 **가상 샘플(AI 초안)**이다. AI가 쓴 글을 AI가 채점하는 편향이 남는다. 인용된 기관·통계 수치도 가상이다.
- **사람 점수와의 일치도는 측정하지 않았다.** 미묘한 품질 차이를 맞게 매기는지는 모른다. 지금 말할 수 있는 것은 "gpt-4.1-mini는 검증-1에 부적합, luna는 가능성 있음" 정도다.
- 채점 기준(`rubric.json`)은 팀의 기능정의서 rubric이 아니라 이 실험용 자체 기준이다(문서층 70점 구조만 맞춤).
- 후보는 OpenAI 모델뿐이다. 로컬 모델·Claude 등은 아직 시험하지 않았다.
- 단가는 2026-09-22 OpenAI 요금 페이지 기준(저장소 기록)이며 실행 시점에 새로 확인하지 못했다. 비용은 API가 돌려준 실제 토큰 수로 계산했다.
