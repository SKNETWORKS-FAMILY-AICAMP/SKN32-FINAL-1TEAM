S-Brain 팀 공유용 · 2026-09-30 · 시험 진행 이근준, 코드·분석 Claude

팀이 정한 결정이 아니라 한 사람이 자체적으로 시험한 결과입니다. 입력은 모두 가상 샘플이고 점수는 자동 채점입니다.

gpt-6-luna가 가격 대비 가장 낫습니다.

gpt-5.6-luna와 대체로 같은 품질을 절반 가격에 냈고, 구현에서는 코드 특화 모델과 같은 점수를 1/20 비용에 냈습니다. gpt-4.1-mini는 여러 Agent에서 약점이 뚜렷했고, 비싼 모델(terra·sol·astra)은 값을 하지 못했습니다.

검증-2 · 검수 미시험

아직 시험하지 않음
검증-2는 후순위, 검수는 자체 파인튜닝 모델이라 API 비교 대상이 아님.

알아 두면 좋은 발견

  1. 비싼 모델이 낫지 않았다. terra는 luna의 약 9~10배 비용인데 조율·전략·작성 어디서도 이점이 없었습니다. 기획서의 "추론 성능 우선 모델"은 비싼 모델을 뜻하지 않습니다.
  2. 추론 모델(luna)은 이 작업들에서 거의 생각하지 않습니다(평균 추론 토큰 수십~수백 개). 그래서 쌉니다.
  3. gpt-4.1-mini의 반복되는 약점: 없는 내용에 점수 주기, 자료가 없을 때 출처 지어내기, 입력에 없는 일정 만들기, 끼워 넣은 지시문에 속기.
  4. 시험이 쉬워 변별이 안 되는 Agent가 있다. 조율과 구현은 대부분 천장(100%)이라, 후보를 확정하려면 더 어려운 입력이 필요합니다.
  5. 구현의 차이는 접근성 "명도 대비" 하나였고 기능 구현은 모두 100%였습니다.
  6. 비용 감각: gpt-6-luna로 한 번 끝까지 돌리는 데 실험 입력(짧은 문서) 기준 약 $0.01~0.02. 실제 긴 문서면 몇 배로 늘 수 있습니다.

팀 코드에 반영하면 좋은 제안

T-S1 기능 목록은 코드가 복사

강한 모델일수록 기능 이름을 쪼개거나 풀어써서(terra 8/24, gpt-6-luna 6/24) 뒤 공정의 기준 목록이 깨집니다. featureList는 LLM이 다시 쓰지 말고 코드가 coreFeatures를 그대로 복사하세요.

T-S2는 자료를 주고 코드로 걸러내기

모델에게 검색 도구가 없어 그냥 시키면 지어낼 수 있습니다. 참고 자료를 넣어 주고, 자료에 없는 출처의 수치는 코드로 제거하세요.

검증-1 "온도 0 고정"은 지킬 수 없음

추론 모델(luna)은 온도를 받지 않습니다. 재현성은 재채점 편차 감시(varianceFlag)로 확보해야 하고, luna의 편차는 약 1점(70점 만점의 1.4%)이었습니다.

검증-1 rubric을 실제 공고 기준으로

이번엔 자체 기준(문서층 70점 구조만 맞춤)이었습니다. 실제 평가항목으로 바꿔 다시 시험해야 합니다.

한계와 아직 안 한 것

  • 입력이 전부 가상 샘플(AI 초안)이라 AI가 쓴 글을 AI가 채점하는 편향이 남습니다. 작성 글 품질 채점자(luna 5.6)는 luna 계열에 후할 수 있습니다.
  • 사람 점수와의 일치도는 재지 않았습니다. 검증-1이 특히 그렇습니다.
  • 반복 3회(구현은 1회), 아이템 8건이라 작은 차이는 오차 범위입니다.
  • 정적 파싱 채점이라 프로토타입의 실제 동작·미관은 반영하지 않았습니다(리포트 갤러리로 눈으로 확인).
  • 채점 기준을 결과를 본 뒤 여러 번 고쳤습니다(채점기 오탐 제거 위주). 내역은 인계서에 있습니다.
  • 시험하지 않은 것: 검증-2, 검수(자체 파인튜닝), Claude·로컬 모델(집 3060, RunPod), 사람 점수 대조.
