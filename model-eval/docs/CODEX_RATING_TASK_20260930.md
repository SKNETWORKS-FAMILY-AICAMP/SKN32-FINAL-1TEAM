# Codex 채점 지시서 — 사업계획서 12편 (2026-09-30)

작성: Claude · 결정: 사용자(이근준) · 채점: Codex · 결과는 **AI 참고 점수**다(사람 정답이 아니다).

## 왜 하는가

- `model-eval/`에서 검증-1(계획서 채점) 후보 모델을 시험했다. 같은 계획서를 좋음 / 보통 / 나쁨 3단계로 만들어 모델이 그 순서대로 점수를 매기는지 재었다(결과: `docs/HANDOFF_20260930.md` 3-7절).
- 그런데 "보통"과 "나쁨"은 우리가 규칙으로 만든 단계라, 독립적인 채점자가 봐도 같은 순서인지는 모른다. 사용자는 도메인 지식이 얕아 직접 채점하기 어렵다고 해서 Codex에게 부탁한다.
- Codex의 점수와 모델 점수의 순위 상관·순서 일치를 낸다. 일치하면 시험 설계가 믿을 만하다는 근거가 되고, 어긋나면 그 단계 구분을 다시 봐야 한다.

## 꾸러미

폴더: `model-eval/human/codex_pack/`

| 파일 | 내용 |
|---|---|
| `docs.jsonl` | 채점할 계획서 **12편**. 한 줄에 `id`(D01~D12)와 `text`(섹션 4~5개짜리 본문) |
| `rubric.json` | 가상 공고, 평가항목 5개(코드 E1~E5·이름·만점·설명), 총 70점 |
| `meta.json` | 편 수, 항목 코드, 출력 경로, 점수 단위(0.5) |

- 12편은 계획서 4편을 3단계로 만든 것이 섞여 있다. **어느 편이 어느 단계인지는 알려 주지 않는다.** 알려고도 하지 않는다.
- 사람 채점 도구(`human/rating_tool.html`)와 같은 내용·같은 항목이다. 사람이 채점했다면 받았을 정보와 같은 정보만 쓴다.

## 채점 방법

1. `rubric.json`의 공고와 평가항목 설명을 읽고, 이 공고의 심사위원이라고 생각하고 채점한다.
2. 계획서 **한 편씩 D01 → D12 순서로** 5개 항목의 점수를 매긴다. 각 항목은 0 ~ 만점, **0.5점 단위**다.
3. **평가항목 설명만 기준으로 삼는다.** 어떤 편이 어떻게 만들어졌는지 추측하지 않는다. 비슷한 편이 여러 개 있어도 서로 비교해 점수를 맞추지 말고, 한 편을 그 자체로 항목 기준에 대어 채점한다(모델도 한 편씩 채점했다).
4. 채점을 끝낸 편의 점수를 다음 편을 본 뒤에 고치지 않는다.
5. 도구나 코드로 편끼리 글을 대조(diff·유사도 등)하지 않는다.

## 출력

`model-eval/human/codex_pack/ratings.json` 하나를 만든다. 사람 채점 도구가 내려받는 파일과 같은 모양이다.

```json
{
  "rater": "codex",
  "rated_at": "2026-09-30T00:00:00Z",
  "items": ["E1", "E2", "E3", "E4", "E5"],
  "ratings": {
    "D01": {"E1": 11.5, "E2": 12, "E3": 9, "E4": 10.5, "E5": 8},
    "D02": {"E1": 10, "E2": 12.5, "E3": 6, "E4": 11, "E5": 3}
  },
  "comments": {
    "D01": "이 편을 이렇게 채점한 이유 한두 문장",
    "D02": "..."
  },
  "notes": "판단이 어려웠던 점(선택)"
}
```

- `ratings`는 D01~D12 12편 × E1~E5 5항목이 모두 있어야 한다. `comments`는 편마다 한두 문장으로 쓴다(점수의 근거를 나중에 볼 수 있게).
- 다 쓴 뒤 형식 검사를 돌린다. 통과해야 끝난다. 이 명령은 정답 열쇠를 읽지 않는다.

```powershell
cd model-eval
..\data-collection\.venv\Scripts\python.exe -X utf8 -m v6_hard.human_tool check human\codex_pack\ratings.json
```

- **검사를 통과한 뒤에도 점수를 고치지 않는다.** 마음이 바뀐 편이 있으면 `notes`에 적기만 한다.
- 모델 점수와의 비교(`score`)는 Codex가 하지 않는다. 사용자나 Claude가 채점 파일을 받은 뒤에 한다.
