# S-Brain 랜딩페이지 목업

정부지원사업 매칭·사업계획서·프로토타입 자동 생성 서비스 "S-Brain"의 중간발표(2026-09-15)용 정적 목업입니다. 서버·DB·LLM 호출이 전혀 없는 **완전 프런트엔드 전용 목업**이며, 화면에 보이는 점수·공고·프로젝트는 전부 더미 데이터입니다.

## 실행 방법

빌드 도구가 필요 없는 단일 HTML 파일입니다. 아래 두 방법 중 하나로 열면 됩니다.

- **바로 열기**: `index.html`을 브라우저로 더블클릭 (일부 브라우저는 `file://`에서 CDN 스크립트를 막을 수 있어, 안 뜨면 아래 방법을 쓰세요)
- **로컬 서버로 열기** (권장):
  ```bash
  python -m http.server 8791
  # 이후 http://localhost:8791/index.html 접속
  ```

인터넷 연결이 필요합니다 — React·Babel·Tailwind·GSAP·폰트를 전부 CDN에서 불러옵니다(아래 참고).

## 무엇으로 만들었나

- **React 18 (UMD) + Babel Standalone** — 브라우저에서 JSX를 그 자리에서 변환합니다. `npm install`도, 번들러도 없습니다. 페이지 소스의 `<script type="text/babel-jsx" id="app-source">` 안에 전체 컴포넌트 코드가 들어 있습니다.
- **Tailwind CDN** — 유틸리티 클래스. 커스텀 CSS 변수(색상 등)는 `<head>`의 `<style>` 블록에 정의돼 있습니다.
- **GSAP + ScrollTrigger** — 랜딩(마케팅) 섹션의 스크롤 애니메이션에만 사용합니다.
- 전부 CDN 참조라 `node_modules`가 없고, 이 파일 하나만 있으면 동작합니다.
- 후기 섹션 사진 3장은 별도 이미지 파일 없이 base64로 `index.html` 안에 직접 인코딩돼 있습니다(약 500KB) — 팀원이 별도로 이미지 파일을 받을 필요 없이 이 파일 하나만 pull하면 됩니다.

## 화면 구성 (파이프라인 순서)

로그인(구글 목업) → 내 프로젝트 대시보드 → 사전 정보 입력(아이디어·신청자 유형·팀·단가, 첨부 선택) → 공고 매칭 → 자격요건 게이트 → 사업계획서 작성(문서 평가) → 프로토타입 제작(산출물 점검) → 종합 평가 → 표현 검수 + 결과물 다운로드

각 화면은 `index.html` 안에서 하나의 React 컴포넌트(`IntakeForm`, `MatchResults`, `EligibilityGate`, `PlanForm`, `ArtifactResult`, `FinalVerdict`, `ReviewScreen` 등)이고, 최상위 `App` 컴포넌트가 `view` 상태값으로 화면을 전환합니다(별도 라우터 없음).

"사업계획서 작성 중"·"프로토타입 제작 중" 진행 상황은 별도 화면으로 전환되지 않습니다 — 생성 버튼을 누른 화면(`EligibilityGate`/`PlanForm`)을 블러 처리한 채로 두고 그 위에 `GeneratingOverlay` 모달(`PipelineProgress`/`ArtifactProgress`)을 띄워서 보여주고, 완료되면 다음 화면으로 넘어갑니다.

같은 저장소의 `admin-dashboard.html`은 관리자용 화면 목업으로, 이 파일과는 별개입니다.

## 더미 데이터와 시연 시나리오

- `MY_PROJECTS` — 대시보드에 뜨는 더미 프로젝트 2건(진행중 "동네 헬스장 예약 서비스", 완료 "중고거래 안전결제 플랫폼"). 각 항목의 `view` 필드가 "이 프로젝트를 열면 어느 화면으로 바로 들어갈지"를 정합니다(이어하기 시뮬레이션).
- `ANNOUNCEMENTS` — 공고 매칭 결과로 나오는 6건의 더미 공고.
- `DOC_SCORE_BY_OUTCOME` / `ARTIFACT_SCORE_BY_OUTCOME` — 문서층·산출물층 점수. `docOutcome`/`artifactOutcome`이 각각 `'fail'`(기본값)이면 미달 예시, `'pass'`면 통과 예시를 보여줍니다(두 층을 독립적으로 추적하므로 한 층만 재작성해도 됩니다).
- 시연 발표용 더미 숫자와 사업계획서 본문 내용은 `sbrain_demo_run.json`(14단계 시연 로그)의 실제 아이템 — **"동네 헬스장 회원관리·예약 서비스"(대표 김서준, 법인)** — 에 맞춰뒀습니다. "미달" 예시의 문서층 52/70·산출물층 19/30 같은 숫자, 계획서 4개 섹션(문제인식/실현가능성/성장전략/팀구성) 본문, 수익모델 단가표(월회원권 35,000원)까지 전부 그 로그에서 가져온 값입니다.
- **종합 평가에서 Task를 체크하고 재작성하면** 그 로그가 보여준 점수 진행(71 → 79 → 86)을 그대로 재현하고, 재작성 직후 자동으로 뜨는 모달에서 계획서·프로토타입 각각의 재작성 전/후 내용을 나란히 비교해서 보여줍니다(두 층을 함께 재작성하면 모달 하나에 둘 다 이어서 나옵니다).
- 대시보드 우측 상단의 **"기존 유저 / 신규 유저" 토글**은 실제 회원가입 없이 완전 신규 유저(프로젝트 0건)의 빈 화면을 시연 중에 바로 보여주기 위한 발표자용 컨트롤입니다.

## 참고 문서

이 목업이 따르는 기획 문서들입니다 (저장소 루트):

- `프로젝트_기획서_v1.3.docx` — 최초 기획서
- `목업_수정_요청서_v3.md` — 가장 최근 수정 요청서. P0(발표 전 필수)/P1(문서 정합)/P2(여유되면) 순으로 우선순위가 매겨져 있고, 각 항목이 `sbrain_demo_run.json`의 어느 위치와 대응하는지 표로 정리돼 있습니다.
- `sbrain_demo_run.json` — 발표 시연에 쓸 14단계 더미 실행 로그. 목업 상수(점수, 공고, 문단 등)의 값 출처입니다.
- `S-Brain_Agent_기능정의서_v1.5.xlsx` — Agent별 기능 정의.
- `verification_agent/` — 산출물 자동 검증(코드 검증 8항목) 로직의 실제 파이썬 구현. `ArtifactResult`의 검증 항목 이름·배점은 여기서 가져왔습니다.

## 알려진 한계 (목업이라서)

- 실제 로그인/OAuth, 파일 업로드, LLM 호출, DB 저장이 전혀 없습니다 — 전부 화면상의 시뮬레이션입니다.
- "재작성" 버튼을 누르면 점수는 실제로 갱신되지만(더미 프리셋 값으로 전환), 다른 항목의 실제 재생성은 일어나지 않습니다.
- 새로고침하면 모든 상태(로그인, 진행 중이던 화면 등)가 초기화됩니다.
- 상단 네비게이션의 **FAQ 링크는 아직 자리만 잡아둔 placeholder**입니다 — 눌러도 아무 반응이 없습니다.
