# S-Brain

정부지원사업 사업계획서 · 프로토타입 동시 생성 AI 서비스

> SK 네트웍스 Family AI 32기 1팀 · [SKNETWORKS-FAMILY-AICAMP/SKN32-FINAL-1TEAM](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN32-FINAL-1TEAM)
> 중간발표 2026-09-15 · 최종발표 2026-10-26

## 한 줄 정의

창업 아이템을 입력하면 지금 열려 있는 정부지원사업 공고 중 맞는 것을 찾아, 그 공고 기준으로 사업계획서를 쓰고, 심사에서 가장 약한 칸인 "준비 정도"를 실제 프로토타입으로 채워준다.

사용자가 상대하는 것은 조율 Agent 하나뿐이지만, 뒤에서는 역할이 분리된 실행 Agent 6개가 순차적으로 협업한다(조율 포함 총 7개). 파이프라인은 끝까지 자동으로 돌지 않는다 — 계획서를 만든 뒤와 프로토타입을 만든 뒤 두 지점에서 멈추고 사용자의 판단을 받는다. 최종 산출물은 문서 한 벌이 아니라 **사업계획서 + 프로토타입 + 두 산출물을 대조한 검증 결과**, 세 겹의 묶음이다.

## 왜 만드는가

창업지원사업·R&D 신청 과정에서 신청자가 반복적으로 막히는 지점 네 가지에서 출발했다.

| 문제 | 현재 상황 | S-Brain의 대응 |
|---|---|---|
| 공고 탐색 비용 | 수만 건 중 유효 공고 선별에 장시간 소요 | 정형 필터 + 임베딩 유사도로 후보 3건 제시 |
| 자격 판정 부재 | 작성 후에야 신청 불가를 인지 | 실행 전 자격요건 게이트로 통과·불통과 판정 |
| 준비 정도 공란 | "개발 예정" 서술로 실현가능성 점수 손실 | 동작하는 프로토타입을 증빙으로 생성 |
| 자기 검증 불가 | 작성자가 자기 문서의 약점을 못 봄 | 계획서와 프로토타입을 각각 채점하고 대조해 미달 지적 |
| AI 문체 부적합 | 번역투·상투어가 제출 문서 문체와 어긋남 | 한국어 파인튜닝 검수 모델이 표현만 교정 |

가장 유사한 경쟁 서비스는 [플랜스코어](https://www.planscore.kr/)다. 공고 매칭과 계획서 평가는 이미 상품화되어 있으므로 그 두 가지로는 경쟁하지 않는다. S-Brain만 제공하는 것은 네 가지다.

- 계획서의 "준비 정도"를 실제 동작하는 프로토타입으로 채운다 — 다른 서비스는 "프로토타입을 개발할 계획"이라는 문장까지만 만든다.
- 계획서에 쓴 기능이 프로토타입에 실제로 있는지 대조해 지적한다 (`기능 정의서의 '결제' 기능이 프로토타입에 존재하지 않습니다` 같은 지적은 계획서 한 벌만으로는 나올 수 없는 판정이다).
- 작성에 들어가기 전에 자격요건을 게이트로 걸러, 계획서를 다 쓴 뒤 신청 불가를 확인하는 낭비를 막는다.
- 제출 문서 문체에 맞춘 한국어 표현 검수를 자체 파인튜닝 모델로 수행한다.

## 산출물

| 구분 | 내용 |
|---|---|
| 사업계획서 | 표준 양식 기준 본문 + 삽입 표와 그래프 |
| 프로토타입 | 카테고리별로 HTML 실행 파일 또는 SVG 원페이지, 그리고 인포그래픽 |
| 검증 결과 | 2층 체크리스트 기반 항목별 점검 결과와 점수 |

공고 매칭은 산출물이 아니라 이 과정에서 함께 제공되는 결과다. 세 산출물 모두 AI 생성 고지가 붙는다 — 검증 점수도 서비스 내부 기준값일 뿐 실제 심사 점수가 아님을 명시한다.

## 서비스 흐름

```
로그인 → 사전 정보 입력(+첨부 문서, 선택) → 공고 후보 3건 중 선택 → 자격요건 게이트
   → 사업계획서 작성 → 문서 평가(100점 환산) ─┬─ 미달 시 재작성
   → 프로토타입 제작 → 산출물 확인(합격선 비표기) ┘
   → 종합 평가(문서층+산출물층, 100점) ─ 미달 시 계획서/프로토타입 중 다시 만들 항목 선택
   → 표현 검수(점수 불변) → 결과물 내려받기
```

설계 원칙은 진입 순서다: **아이템을 말한다 → 맞는 공고를 찾아준다 → 그 공고 기준으로 만든다.** 반대 순서(공고를 먼저 고르고 아이템을 맞추는 것)는 금지한다. 입력은 대화형이 아니라 폼으로 한 번에 받아, 실행 중 되묻기가 없도록 한다. 동시 실행은 계정당 1건으로 제한하며, 진행 중인 작업은 중단 지점부터 이어할 수 있다.

## 시스템 구성

### Agent 7개 · Task 14개

| Agent | 담당 업무 | Task 수 |
|---|---|---|
| 조율 (Supervisor) | 요구사항 해석, 공고 매칭, 자격 확인, 실행 Agent 선정·작업 분해, 결과 통합 | 3 |
| 전략 | 요구사항 분석, 목표시장 분석 | 2 |
| 작성 | 사업계획서 본문·표·그래프 작성 | 3 |
| 구현 | 프로토타입 제작 — HTML 실행 파일, 인포그래픽 | 2 |
| 검증-1 (문서) | 문서층 검증 — 공개된 평가항목 기준 LLM 판정 | 1 |
| 검증-2 (산출물) | 산출물층 검증 — 코드 기준 자동 검증 + 계획서 대조 | 1 |
| 검수 (표현) | 문장 형식 적합성 검수, 한국어 윤문 (자체 파인튜닝 모델) | 2 |

실행 순서는 `조율 → 전략 → 작성 → 검증-1 → (사용자 판단) → 구현 → 안내 문서 생성 → 검증-2 → (사용자 판단) → 검수 → 조율`로 고정된다. 검증을 두 Agent로 나눈 이유는 판정 방식이 다르기 때문이다 — 검증-1은 LLM 판단, 검증-2는 규칙 기반 계산. 검수를 별도 Agent로 둔 이유는 내용 생성과 표현 교정을 분리해야 변경분에 보호 토큰 검사를 적용할 수 있기 때문이다.

아이템 카테고리(원페이지 / 웹개발 / AI API)에 따라 구현 Agent의 산출 형태와 실행 Task 수가 달라진다. 카테고리는 내부 판정값이며 사용자에게 선택 UI로 노출하지 않는다.

### 2층 검증 구조

| 층 | 검증 대상 | 방식 | 배점 |
|---|---|---|---|
| 문서층 | 사업계획서가 평가항목을 충족하는가 | LLM 판정 (검증-1) | 70 |
| 산출물층 | 프로토타입이 기준을 지키고, 계획서에 쓴 것이 실제로 있는가 | 규칙 기반 계산 + 대조 (검증-2) | 30 |

문서 평가 시점(산출물층이 아직 없을 때)은 70점을 100점으로 환산해 표시하고, 종합 평가 시점은 100점 그대로 표시한다. 두 시점 모두 Threshold는 80점(관리자 설정값)이다. 산출물층 30점은 "코드 기준 자동 검증 15점 + 계획서 대조 15점"으로 나뉘며, 코드 기준 자동 검증은 카테고리별로 8항목 체크리스트가 다르다(HTML 실행 파일 기준은 KWCAG 2.2 접근성 근거, SVG 원페이지 기준은 지면 정보 파싱 근거). 판정(합격선을 넘었는가)과 점검(무엇이 부족한가)은 화면에서 분리해서 보여준다.

재수행은 자동이 아니라 사용자가 요청할 때만 실행하며, 미달이 발생한 Task만 선별 재수행한다(전체 파이프라인을 다시 돌리지 않는다). 이전 결과는 삭제하지 않고 보존해 점수 변화 이력을 남긴다.

### LLM 호출 vs 직접 구현

배점의 70%가 LLM 판정이므로, "무엇을 직접 만들었는가"는 배점이 아니라 파이프라인에서 답한다. 다음은 LLM 호출이 아니라 직접 구현한 로직이다.

- 공고 데이터 수집 배치와 지원대상 정형화 파싱
- 자격요건 게이트 — 구조화 필드 비교로 통과·불통과 판정
- 정형 필터 우선 적용 후 임베딩 유사도로 순위를 매기는 매칭
- 산출물층 코드 기준 자동 검증 8항목
- Task 고정 목록과 실행 시점 지시 생성으로 구성된 작업 분해
- 검수 산출물의 보호 토큰 불변식 검사와 문단 단위 재시도 제어

검수 Agent가 쓰는 모델은 외부 API가 아니라 한국어 공개 사전학습 모델을 베이스로 한 경량 파인튜닝(LoRA 계열) 모델이다 — 이 프로젝트에서 모델 자체를 만드는 유일한 지점이다. 학습 데이터는 원문·교정문 쌍으로 구성하고, 실제 제출된 사업계획서는 개인정보·재현 위험 때문에 학습 데이터로 쓰지 않는다.

## 데이터·산출물 정책

- 첨부 문서 원본은 텍스트 추출 직후 파기한다. 서비스가 필요로 하는 것은 본문 텍스트뿐이다.
- 실행 로그는 12개월 보관 후 계정 식별자를 분리해 통계로만 남긴다(품질 기준 조정 근거 확보 목적).
- 학습 데이터 편입 동의와 알림 수신 동의는 선택 동의로 분리하며, 언제든 철회할 수 있다.
- 관리자 열람은 메타데이터로 한정한다. 계획서 본문·아이템 내용은 사용자 동의를 받은 건에 한해서만 열람하고 접근 이력을 남긴다.
- 산출물마다 AI 초안 생성 사실과 검토 필요를 표기하고, 검증 점수가 서비스 내부 기준값이며 실제 심사 결과가 아님을 명시한다.

- 고객사 관리자와 조직 분리 (데이터 모델 전면 수정 필요)
- 대형 국가 R&D(IRIS·NTIS) 연동 (데이터 확보 불가)
- 멀티모달, 채팅 기반 정보 입력/실행 중 되묻기 (입력 폼 방식으로 대체)
- 한 계정의 여러 공고 동시 실행 (이어하기 대상이 모호해짐)
