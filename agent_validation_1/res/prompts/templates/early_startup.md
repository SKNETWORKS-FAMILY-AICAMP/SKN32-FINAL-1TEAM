# 초기창업패키지 검증 기준

## 검증 범위
- 현재 개발 수준·고객 검증·매출·PoC와 향후 개발·사업화 계획을 구분한다.
- 수행 사실은 근거와 상태를 보존하고 목표·예정·추정은 proposed로 표시한다.
- 관리기준의 사업비·협약기간·성과 조건과 단계별 표의 합계를 확인한다.
- 개발·양산·마케팅 일정은 _strategy_limits.deadline 이전에 종료되어야 한다.

## 판정
확정 사실의 원본 불일치·필수 표/이미지 계약 위반·지원금 상한 초과는 fail이다. 제안 KPI·시험 조건·고객 정보 부족은 warning과 확인 필요 사항으로 남긴다.

## 추가 검증 기준

- 3.5.2 개발계획 표의 필수 컬럼과 표 아래 서술문을 함께 확인한다.
- 3.5.3·3.5.4 단계별 사업비가 원본 행과 연결되고 정부지원사업비 합계가 상한을 넘지 않는지 확인한다. 단계 미지정 원본을 양쪽 단계에 중복 배분하면 안 된다.
- 3.6.2 추진기간은 월 단위로 정규화해 `_strategy_limits.deadline` 초과 여부를 확인한다.
- 3.3.6은 USERFLOW·SERVICE_ARCHITECTURE 두 이미지 명세와 각 nodes(3~6개)를 확인한다.
- `featureList`는 기능·핵심기술·개발계획에서 비교하고, 서비스 개요와 성능지표만으로 기능 누락을 판정하지 않는다.
- 확정 사실 불일치·필수 표/이미지 계약 위반·지원금 상한 초과·마감일 초과는 fail이다. 제안 KPI·시험 조건·고객 정보 부족·수량/단가 미확정은 warning과 확인 필요로 남긴다.
- 매핑의 `writeTarget: table`인 3.5.2·3.5.3·3.5.4·3.6.2는 JSON 배열만 출력된 경우가 아니라 실제 `tables`의 columns/rows 구조를 충족하는지 확인한다.
